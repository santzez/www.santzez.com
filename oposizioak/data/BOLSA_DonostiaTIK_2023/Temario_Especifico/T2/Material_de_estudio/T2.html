Mapa del tema

T2 explica cómo viajan los datos por encima de Ethernet: la pila TCP/IP (IP, ICMP, ARP, TCP, UDP), el direccionamiento IPv4 (máscaras, subredes, privadas, asignación) y el direccionamiento IPv6. Es el tema más «de cálculo» del bloque 1 y el que más preguntas de test aporta: subnetting y diagnóstico son lo que más rinde para test, preguntas cortas y caso práctico.

Cada apartado sigue tres niveles: concepto, explicación y aplicación práctica.

1. El modelo TCP/IP y la encapsulación

Concepto. TCP/IP es la familia de protocolos de Internet, normalizada por el IETF en documentos RFC. El modelo de referencia tiene cuatro capas: aplicación, transporte, internet y acceso a la red.

Explicación.

Capa TCP/IP Protocolos Unidad de datos Dirección que usa
Aplicación HTTP/S, DNS, DHCP, SMTP, IMAP, SSH, SNMP, SIP Datos / mensaje —
Transporte TCP, UDP Segmento (TCP) / datagrama (UDP) Puerto (16 bits)
Internet IP (v4, v6), ICMP Paquete IP (32 / 128 bits)
Acceso a la red Ethernet, wifi (T1, T5) Trama MAC (48 bits)

Algunos autores usan cinco capas (separan física y enlace). La correspondencia con OSI es aproximada: aplicación ≈ 5-7, transporte = 4, internet = 3, acceso a la red ≈ 1-2. ARP queda en la frontera entre internet y acceso a la red: no merece la pena discutir su capa; lo importante es qué hace (apartado 4).

Encapsulación: cada capa añade su cabecera a lo que le entrega la superior. Un correo viaja como datos SMTP dentro de un segmento TCP, dentro de un paquete IP, dentro de una trama Ethernet. El destino desencapsula en orden inverso.

Aplicación práctica. Para que un paquete llegue hacen falta tres direcciones: la MAC del salto local, la IP del destino final y el puerto del programa. Si una falla, falla la comunicación, y cada una se diagnostica de forma distinta.

🧠 Para memorizar
Puerto → aplicación · IP → equipo de destino · MAC → interfaz en el salto local.
Bits: MAC 48 · IPv4 32 · IPv6 128 · puerto 16 («cuatro-ocho, tres-dos, uno-dos-ocho, uno-seis»).
Trama ⊃ paquete ⊃ segmento ⊃ datos.
⚠️ No confundir — MAC vs IP vs puerto
La MAC cambia en cada salto (es la del siguiente equipo de la red local); la IP de destino se mantiene de extremo a extremo; el puerto elige el programa dentro del equipo.

2. El protocolo IP

Concepto. IP (Internet Protocol) lleva cada paquete de una red a otra (encaminamiento) usando direcciones lógicas jerárquicas (red + host).

Explicación.

  • Sin conexión: cada paquete viaja de forma independiente.
  • Best effort (no fiable): IP no garantiza entrega, orden ni ausencia de duplicados. Si la aplicación usa TCP, este aporta esa fiabilidad; pero no todo el tráfico IP va sobre TCP (UDP, ICMP…).
  • Fragmentación (IPv4): si un paquete no cabe en la MTU de un enlace, se trocea, salvo que lleve el bit DF (Don't Fragment): entonces se descarta y se avisa con ICMP.

Campos de la cabecera IPv4 que hay que conocer (20 bytes sin opciones):

Campo Para qué sirve
TTL (Time To Live) Contador que cada router resta en 1 al encaminar; al llegar a 0 descarta el paquete y avisa con ICMP. Evita bucles infinitos (en IPv6 se llama Hop Limit)
Protocolo Qué lleva dentro: 1 = ICMP, 6 = TCP, 17 = UDP
DSCP Marca de prioridad (QoS); la voz se marca para tener preferencia (T9)
IP origen / IP destino 32 bits cada una
Suma de comprobación Solo de la cabecera

Aplicación práctica. El traceroute funciona gracias al TTL (apartado 3), y la marca DSCP es lo que permite que la telefonía IP tenga prioridad en la red municipal.

3. ICMP

Concepto. ICMP (Internet Control Message Protocol) transporta mensajes de control y de error de IP. Va directamente sobre IP (protocolo 1) y no usa puertos.

Explicación.

Uso Mensajes ICMP
ping Echo Request (tipo 8) y Echo Reply (tipo 0): ¿responde el destino? y RTT (ida y vuelta)
Traceroute Ver el principio más abajo; los routers responden Time Exceeded (tipo 11)
Errores Destination Unreachable (tipo 3: red, host o puerto inalcanzable), Redirect, «hace falta fragmentar»

Principio del traceroute: se envían paquetes con TTL (o Hop Limit) creciente → cada router lo decrementa → donde llega a cero, el router responde ICMP Time Exceeded → así se descubre el camino salto a salto. El tipo de paquete de sonda depende de la implementación (tracert de Windows usa Echo Request ICMP; traceroute de Linux, datagramas UDP por defecto), pero el principio es siempre el mismo.

Aplicación práctica. Que un ping no responda no demuestra que el equipo esté apagado: muchos cortafuegos (incluido el de Windows) bloquean ICMP. Los asteriscos en un traceroute son saltos que no responden, no necesariamente una avería.

⚠️ TRAMPA DE EXAMEN
ICMP no usa puertos (ni TCP ni UDP). «Ping usa el puerto 7» es falso.

4. ARP

Concepto. ARP (Address Resolution Protocol) obtiene la dirección MAC que corresponde a una IPv4 dentro del enlace local. Funcionalmente está en la frontera entre la capa de red y la de enlace.

Explicación.

  1. El equipo A quiere enviar a 192.168.1.20 (está en su subred) y no conoce su MAC.
  2. Envía un ARP Request en broadcast (FF:FF:FF:FF:FF:FF): «¿quién tiene 192.168.1.20?». Lo reciben todos los equipos de la VLAN.
  3. Solo el dueño de esa IP responde con un ARP Reply, normalmente en unicast.
  4. A guarda la correspondencia en su caché ARP durante un tiempo (arp -a en Windows, ip neigh en Linux).

Si el destino está fuera de la subred, el equipo no pregunta por la MAC del destino remoto: resuelve la del siguiente salto, normalmente su puerta de enlace. La trama va al router y el paquete IP sigue hacia el destino.

📌 Imprescindible — ARP con destino remoto
Destino en mi subred → ARP por la MAC del destino. Destino fuera → ARP por la MAC de la puerta de enlace. Nunca se hace ARP por una IP de otra red.
⚠️ TRAMPA DE EXAMEN
«Para enviar a 8.8.8.8, el PC obtiene por ARP la MAC de 8.8.8.8» es falso: obtiene la de su puerta de enlace.

Variantes y riesgos (contexto):

  • ARP gratuito: un equipo anuncia su propia IP; sirve para detectar IP duplicadas y actualizar cachés tras un cambio.
  • ARP spoofing: un atacante responde con su MAC para interceptar tráfico. Su protección en el switch (Dynamic ARP Inspection) se ve en T4 y T17.
📌 Imprescindible — examen 2023, pregunta 7
El protocolo que obtiene la MAC a partir de la IP es ARP. En IPv6 no hay ARP: lo hace NDP (Neighbor Discovery Protocol, sobre ICMPv6).
⚠️ No confundir — ARP vs DNS vs DHCP
ARP: IPv4 → MAC, en el enlace local. DNS: nombre → IP (T10). DHCP: entrega la configuración IP al equipo (apartado 8).

5. TCP, UDP y puertos

Concepto. La capa de transporte entrega los datos a la aplicación correcta (por puerto). TCP añade conexión y garantías; UDP ofrece un servicio mínimo, sin conexión ni garantías. Se elige según lo que necesite la aplicación.

Explicación.

Característica TCP UDP
Conexión Orientado a conexión (three-way handshake) Sin conexión
Garantías Confirmaciones (ACK), retransmisión, orden, control de flujo y de congestión Ninguna por sí mismo: si se pierde, se pierde (la aplicación decide)
Cabecera 20 bytes mínimo 8 bytes
Cuándo conviene Cuando importa que llegue todo y en orden Cuando importa la inmediatez o el intercambio es muy simple

Conexión TCP: SYN → SYN-ACK → ACK. El cierre ordenado usa FIN y ACK en cada sentido; un RST corta de golpe (por ejemplo, si el puerto está cerrado).

⚠️ No confundir — «TCP lento, UDP rápido»
Es una simplificación. TCP añade mecanismos (conexión, confirmación, retransmisión) que tienen un coste; UDP no los tiene. Por eso la voz va sobre UDP: un paquete retransmitido llegaría tarde y no serviría.

Puertos. Un puerto (16 bits, de 0 a 65.535) identifica la aplicación.

Rango Nombre
0 – 1023 Bien conocidos (well-known), asignados por la IANA
1024 – 49151 Registrados
49152 – 65535 Dinámicos o efímeros: los usa el cliente como origen
Puerto · transporte habitual Servicio Puerto · transporte habitual Servicio
20/21 TCP FTP (datos/control) 110 TCP POP3
22 TCP SSH, SFTP, SCP 123 UDP NTP
23 TCP Telnet (inseguro) 143 TCP IMAP
25 TCP SMTP 161/162 UDP SNMP / traps
53 UDP y TCP DNS 443 TCP HTTPS (HTTP/3: UDP)
67/68 UDP DHCP (servidor/cliente) 445 TCP SMB (compartición Windows)
69 UDP TFTP 514 UDP Syslog
80 TCP HTTP 3389 TCP RDP
5060 / 5061 SIP / SIP sobre TLS 993 / 995 IMAPS / POP3S

La columna indica el transporte habitual, no una regla absoluta: algunos protocolos admiten ambos (DNS usa UDP en las consultas normales y TCP en respuestas grandes y transferencias de zona; syslog puede ir por TCP o TLS).

Endpoint y conexión. Un extremo de comunicación (lo que en programación se llama socket) se identifica por dirección IP + puerto + protocolo. Una conexión TCP concreta se distingue por la combinación IP origen, puerto origen, IP destino, puerto destino y protocolo: así un servidor web atiende a miles de clientes en el mismo puerto 443.

Aplicación práctica. Abrir o cerrar un servicio en el cortafuegos es abrir o cerrar un puerto y un protocolo (T14).

📌 Imprescindible — examen 2023, pregunta 8
Para configurar un switch de forma remota con SSH se usa el puerto 22.
🧠 Para memorizar los puertos que de verdad importan
22 SSH · 25 SMTP · 53 DNS · 67/68 DHCP · 80 HTTP · 123 NTP · 161/162 SNMP · 443 HTTPS · 514 syslog · 3389 RDP. «Dos-dos para Seguro (SSH); cuatro-cuatro-tres para la web Segura».

6. Direccionamiento IPv4

Concepto. Una dirección IPv4 tiene 32 bits, escritos como cuatro números de 0 a 255 (192.168.193.25). El prefijo o máscara indica qué bits son de red y cuáles de host.

Explicación.

  • Dirección de red: todos los bits de host a 0. Identifica la subred; no se asigna a equipos.
  • Dirección de broadcast: todos los bits de host a 1. Llega a todos los equipos de la subred.
  • Hosts útiles = 2ⁿ − 2 (n = bits de host) en las subredes convencionales, que son las de los ejercicios. Existen excepciones técnicas: un /31 se usa en enlaces punto a punto con sus 2 direcciones útiles, y un /32 identifica un único equipo.

CIDR y clases. Hoy se usa CIDR (Classless Inter-Domain Routing): el prefijo puede tener cualquier longitud (/20, /26…) y siempre se indica. Antes de CIDR, la máscara venía dada por el primer octeto (clases, histórico):

Clase Bits iniciales Primer octeto Máscara por defecto
A 0 0 – 127 (útiles 1 – 126) /8
B 10 128 – 191 /16
C 110 192 – 223 /24
D 1110 224 – 239 Multicast
E 1111 240 – 255 Reservada
⚠️ No confundir — clase histórica vs prefijo CIDR real
Las clases pueden preguntarse en el test, pero no sirven para calcular redes actuales. 10.42.96.0 «sería de clase A», y sin embargo en el caso de 2023 su prefijo real es /20. Calcula siempre con la máscara que te dan, nunca con la que «tocaría» por clase.

Direcciones privadas y especiales:

Rango Uso
10.0.0.0/8 Privada (RFC 1918)
172.16.0.0/12 (172.16.0.0 – 172.31.255.255) Privada (RFC 1918)
192.168.0.0/16 Privada (RFC 1918)
127.0.0.0/8 Loopback (127.0.0.1 = el propio equipo)
169.254.0.0/16 Link-local (en Windows, APIPA): la toma un equipo que esperaba DHCP y no obtuvo configuración
100.64.0.0/10 CGNAT de operadores (RFC 6598)
224.0.0.0/4 Multicast
192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24 Reservadas para documentación y ejemplos
0.0.0.0 Dirección no especificada (p. ej., origen de un equipo que aún no tiene IP; un servicio que escucha «en todas las interfaces»)
0.0.0.0/0 Prefijo que abarca todas las redes: la ruta por defecto
255.255.255.255 Broadcast limitado (solo la red local)

Aplicación práctica. Las privadas no se enrutan en Internet; en el modelo IPv4 habitual, salen a Internet mediante NAT/PAT con una dirección pública (apartado 9). Todas las redes del caso de 2023 eran privadas.

🧠 Para memorizar las privadas
«Diez, ciento setenta y dos dieciséis a treinta y uno, ciento noventa y dos ciento sesenta y ocho»: 10/8 · 172.16/12 · 192.168/16. De mayor a menor tamaño.
⚠️ TRAMPA DE EXAMEN
172.16.0.0/12 llega hasta 172.31.255.255: 172.20.x.x es privada; 172.32.x.x, no.

7. Cálculo de subredes paso a paso

Concepto. Calcular una subred es encontrar su dirección de red, su broadcast, su rango de hosts y su número de hosts a partir de una IP y una máscara.

Explicación — método del salto:

  1. Localiza el octeto interesante: el primero de la máscara que no es 255.
  2. Salto = 256 − valor de la máscara en ese octeto.
  3. Las subredes empiezan en múltiplos del salto (0, 64, 128, 192…).
  4. Red = el múltiplo igual o inferior al valor de la IP en ese octeto.
  5. Broadcast = siguiente red − 1. Hosts = lo que queda entre ambas.
Prefijo Máscara Bits de host Hosts útiles Salto
/30 255.255.255.252 2 2 4
/29 255.255.255.248 3 6 8
/28 255.255.255.240 4 14 16
/27 255.255.255.224 5 30 32
/26 255.255.255.192 6 62 64
/25 255.255.255.128 7 126 128
/24 255.255.255.0 8 254 1 en el 3.er octeto
/23 255.255.254.0 9 510 2 en el 3.er octeto
/22 255.255.252.0 10 1.022 4 en el 3.er octeto
/20 255.255.240.0 12 4.094 16 en el 3.er octeto
/16 255.255.0.0 16 65.534 —
🧠 Para memorizar los valores de máscara
128 · 192 · 224 · 240 · 248 · 252 · 254 · 255 (1, 2, 3… bits a 1 en el octeto): cada uno suma la mitad del anterior salto (128 + 64 = 192; + 32 = 224; + 16 = 240…).
📌 Imprescindible — examen 2023, pregunta 5
Red 213.114.93.0 con máscara 255.255.255.192 (/26): salto 64, la primera subred va de .0 a .63 → broadcast 213.114.93.63. Las otras opciones eran trampas: .127 (broadcast de la segunda /26), .31 (de una /27) y .255 (de una /24).

Las subredes del caso de 2023:

Subred del enunciado Máscara Rango de hosts Broadcast Hosts
Usuarios 192.168.193.0 /24 .1 – .254 192.168.193.255 254
Telefonía 10.42.96.0 255.255.240.0 (/20) 10.42.96.1 – 10.42.111.254 10.42.111.255 4.094
Registro 192.168.16.16 255.255.255.240 (/28) .17 – .30 192.168.16.31 14
Internet libre 192.168.122.0 /23 192.168.122.1 – 192.168.123.254 192.168.123.255 510
Cámaras 172.16.47.0 /24 .1 – .254 172.16.47.255 254

Telefonía: máscara 255.255.240.0 → octeto interesante el tercero, salto 16; 96 es múltiplo de 16 y la siguiente red empieza en 112, así que el broadcast es 10.42.111.255.

Misma subred o no. Dos equipos están en la misma subred si, aplicando la máscara, les sale la misma dirección de red. 192.168.16.20/28 (red .16) y 192.168.16.33/28 (red .32) no lo están, aunque «parezcan de la misma red».

VLSM y sumarización (nivel de este tema; la configuración de rutas está en T4):

  • VLSM (Variable Length Subnet Mask): máscaras distintas según el tamaño de cada subred (/30 o /31 para enlaces entre routers, /24 para usuarios, /28 para un grupo pequeño). Se asignan primero las subredes más grandes para que los bloques queden alineados.
  • Sumarización (superred): agrupar redes contiguas en una sola ruta: 192.168.0.0/24 + 192.168.1.0/24 = 192.168.0.0/23.

Aplicación práctica. Comprueba siempre el tamaño: la subred de registro (/28) solo admite 14 equipos, contando la puerta de enlace. Si te piden añadir dispositivos, mira primero si caben. Los ejercicios del apartado 19 entrenan todo esto por niveles.

💡 Para el caso práctico
Ante una tabla de subredes, calcula para cada una rango, broadcast y número de hosts, y di cómo se asignan: DHCP para puestos, wifi, invitados y telefonía; dirección estable (manual o reserva DHCP) para servidores, impresoras, cámaras y electrónica de red.

8. Asignación de direcciones: manual, reserva y DHCP

Concepto. Un equipo obtiene su configuración IP (dirección, máscara, puerta de enlace y DNS) a mano o automáticamente por DHCP. Si necesita una dirección estable, puede lograrse de las dos formas.

Explicación.

  • Configuración manual (estática): se escribe en el propio equipo. Típica de servidores, electrónica de red y equipos que deben funcionar aunque el DHCP falle.
  • DHCP (Dynamic Host Configuration Protocol, UDP 67 servidor / 68 cliente): un servidor presta la configuración durante un tiempo (concesión o lease). Proceso DORA: Discover → Offer → Request → Ack.
  • Reserva DHCP: el servidor entrega siempre la misma IP a una MAC concreta. Da una dirección estable con gestión centralizada. Cuidado con las MAC aleatorias (T1).
  • DHCP relay (ip helper-address): el Discover es un broadcast y no atraviesa routers; el switch de capa 3 o el cortafuegos de cada VLAN lo reenvía al servidor central.
  • Opciones DHCP: puerta de enlace (opción 3), DNS (opción 6) y, para teléfonos IP, el servidor de configuración (opción 66; la 150 es propia de Cisco).
⚠️ No confundir — IP estática vs reserva DHCP
Las dos dan una dirección estable. La estática se configura en el equipo; la reserva, en el servidor DHCP. Una impresora o una cámara pueden usar cualquiera de las dos según el diseño de la organización: no hay una regla única.

Aplicación práctica. Sin puerta de enlace, un equipo solo habla con su propia subred. Sin DNS, se comunica por IP pero no resuelve nombres: ping 8.8.8.8 funciona y ping www.donostia.eus no. La administración del servidor DHCP se estudia en T10.

⚠️ No confundir — red, broadcast, host y puerta de enlace
Dirección de red: bits de host a 0, no es de nadie. Broadcast: bits de host a 1, es de todos. Host: cualquier dirección intermedia asignable. Puerta de enlace: un host más de la subred (a menudo la .1 o la .254), el router. Y máscara ≠ puerta de enlace: la máscara delimita la red; la puerta de enlace es la salida.

9. NAT (concepto)

Concepto. NAT (Network Address Translation) traduce direcciones IP al atravesar un router o cortafuegos. Se extendió para paliar el agotamiento de IPv4: muchas privadas comparten pocas públicas.

Explicación.

Tipo Qué hace Uso típico
NAT estático (1:1) Una privada ↔︎ una pública fija Publicar un servidor interno
NAT dinámico Privadas ↔︎ un conjunto de públicas Poco usado hoy
PAT / NAT overload Muchas privadas → una pública, distinguidas por puerto Salida a Internet de una LAN
Redirección de puertos (DNAT, port forwarding) Un puerto de la IP pública → IP y puerto internos Dar acceso desde fuera a un servicio concreto

Aplicación práctica. En el caso de 2023, el acceso remoto del mantenedor del PLC podía resolverse con VPN (lo recomendable, T15) o con una redirección de puerto en el cortafuegos, coordinada con Sistemas. La configuración de NAT en el cortafuegos se estudia en T14.

⚠️ No confundir — NAT vs PAT vs cortafuegos vs NAC
NAT traduce direcciones; PAT es el NAT que distingue por puerto (muchas a una). Ninguno filtra: eso lo hace el cortafuegos con reglas (T14). NAC controla qué equipos pueden entrar en la red (T17).

10. IPv6

Concepto. IPv6 usa direcciones de 128 bits para resolver el agotamiento de IPv4 (la IANA repartió los últimos bloques IPv4 en 2011).

Explicación — notación. Ocho grupos de cuatro dígitos hexadecimales separados por dos puntos. Para abreviar:

  1. Se quitan los ceros a la izquierda de cada grupo.
  2. Una sola vez por dirección, una secuencia de grupos a cero se sustituye por ::.

Una red de usuarios es normalmente un /64: 64 bits de prefijo y 64 de identificador de interfaz.

Tipos de direcciones:

Tipo Prefijo Analogía aproximada en IPv4
Unicast global (GUA) 2000::/3 (empiezan por 2 o 3) Pública
Link-local FE80::/10 169.254.x.x, pero en IPv6 es normal: toda interfaz con IPv6 activo tiene una (lo exige el estándar) y la usa NDP
Unique local (ULA) FC00::/7; la mitad definida para uso local es FD00::/8 Privadas RFC 1918 (solo como analogía: no son iguales)
Multicast FF00::/8 224.0.0.0/4
Loopback ::1 127.0.0.1
No especificada :: 0.0.0.0

Sin broadcast y sin ARP. IPv6 usa multicast (FF02::1 = todos los nodos del enlace) y NDP (Neighbor Discovery, sobre ICMPv6) para descubrir vecinos y routers.

Autoconfiguración:

  • Router Advertisement (RA): el router anuncia el prefijo y sus banderas indican cómo configurarse.
  • SLAAC: el equipo forma su dirección con el prefijo del RA y un identificador de interfaz. Hoy suele ser estable (sin revelar la MAC) o temporal (por privacidad); el derivado de la MAC (EUI-64) es el método histórico.
  • DHCPv6 sin estado: SLAAC para la dirección + DHCPv6 para datos como el DNS. DHCPv6 con estado: el servidor asigna la dirección.
  • Puerta de enlace: se aprende por el RA (NDP), no por DHCPv6.
⚠️ TRAMPA DE EXAMEN
En IPv6 la puerta de enlace no la da DHCPv6: la anuncia el router en el RA. No traslades el modelo DHCPv4 (opción 3) a IPv6.
IPv4 IPv6
Longitud 32 bits 128 bits
Notación Decimal con puntos Hexadecimal con dos puntos
Cabecera Variable (20–60 B), con suma de comprobación Fija de 40 B, sin suma de comprobación
Difusión Broadcast Sin broadcast (multicast)
Resolución de MAC ARP NDP
Autoconfiguración DHCP SLAAC y/o DHCPv6
Fragmentación Origen y routers Solo el origen
NAT Muy habitual con las privadas No es el modelo básico: hay direcciones globales de sobra (existen traducciones como NAT64 en escenarios concretos)

Transición: doble pila (el equipo usa IPv4 e IPv6 a la vez; es lo preferido), túneles (IPv6 dentro de IPv4) y traducción NAT64 + DNS64 (equipos solo IPv6 que acceden a servicios solo IPv4).

⚠️ TRAMPA DE EXAMEN
«IPv6 no tiene NAT» y «en IPv6 IPsec es obligatorio» son simplificaciones falsas. IPv6 normalmente no necesita NAT, pero existen mecanismos de traducción; y IPv6 contempla IPsec, sin que su uso sea obligatorio para todo el tráfico (T15).

Aplicación práctica. Aunque la red municipal sea IPv4, los equipos actuales tienen IPv6 activado y muestran una dirección FE80:: en ipconfig: es normal y no indica avería.

⚠️ No confundir — 169.254/16 en IPv4 vs FE80::/10 en IPv6
169.254.x.x en un equipo que esperaba DHCP es síntoma: no obtuvo configuración. FE80:: en IPv6 es normal: la tiene toda interfaz con IPv6.
⚠️ TRAMPA DE EXAMEN
El :: solo puede usarse una vez en una dirección; si se usara dos veces no se sabría cuántos ceros hay en cada hueco.

11. Diagnóstico básico de conectividad IP

Concepto. La mayoría de los avisos «no tengo red» se ordenan comprobando la conectividad de abajo arriba: se busca el primer paso que falla. Aquí interesa el razonamiento IP; la metodología completa de averías y su escalado está en T19.

Explicación — metodología:

  1. Enlace: luces de la tarjeta y del puerto, cable.
  2. Configuración IP: ipconfig /all. ¿Tiene la IP esperada o 169.254.x.x?
  3. Máscara y puerta de enlace: ¿coherentes con la subred?
  4. Red local: ping a la puerta de enlace.
  5. Fuera: ping a una IP externa; tracert si falla.
  6. Nombres: nslookup; si la IP funciona y el nombre no, es DNS.
  7. Servicio: ¿responde el puerto concreto? (Test-NetConnection servidor -Port 443, nc -zv).

13. Anclas de memoria

18. Posibles preguntas cortas (con esquema de respuesta)

1. Diferencias entre TCP y UDP, con ejemplos.
Conexión (sí/no) · garantías (ACK, retransmisión, orden, control de flujo y congestión / ninguna) · cabecera 20 frente a 8 B · criterio: fiabilidad frente a inmediatez, según la aplicación · ejemplos TCP: HTTPS, SMTP, SSH; UDP: DHCP, voz, SNMP · DNS usa ambos.

2. Explica cómo funciona ARP.
IPv4 → MAC en el enlace local · request en broadcast, reply normalmente unicast · caché ARP · destino remoto → MAC de la puerta de enlace · ARP gratuito e IP duplicada · ARP spoofing (T17) · en IPv6, NDP.

3. Explica el método del salto con un ejemplo de /20.
Octeto interesante (el tercero, 240) · salto 16 · múltiplos 0, 16… 96, 112 · 10.42.100.7/20 → red 10.42.96.0 · broadcast 10.42.111.255 · hosts 10.42.96.1–10.42.111.254 (4.094).

4. Asignación manual, reserva DHCP y DHCP dinámico.
Cuándo se necesita una dirección estable · estática en el equipo frente a reserva en el servidor · DORA, concesión, UDP 67/68 · relay entre VLAN · opciones (puerta de enlace, DNS, opción 66).

5. Principales diferencias entre IPv4 e IPv6.
32 frente a 128 bits y notación · sin broadcast (multicast) · NDP en lugar de ARP · SLAAC y DHCPv6 · cabecera fija de 40 B · fragmentación solo en origen · NAT no es el modelo básico · transición: doble pila, túneles, NAT64.

6. Qué es NAT, tipos y por qué no es seguridad.
Traducción de direcciones por el agotamiento de IPv4 · estático, dinámico, PAT, redirección de puertos · PAT distingue por puerto · NAT no filtra: eso lo hacen las reglas del cortafuegos (T14).

7. Autoconfiguración en IPv6.
Router Advertisement y sus banderas · SLAAC (identificador estable o temporal; EUI-64 histórico) · DHCPv6 sin estado y con estado · la puerta de enlace se aprende por el RA, no por DHCPv6.

20. Casos prácticos

Mini caso A — PC con 169.254. Un PC recién instalado tiene 169.254.33.10 y no navega; los demás de la planta funcionan.
Esquema: esperaba DHCP y no obtuvo configuración · enlace y latiguillo · en el switch, puerto activo y en la VLAN correcta · relay de esa VLAN, servidor y direcciones libres en el ámbito · ipconfig /release y /renew · escalado a comunicaciones si hay que tocar el switch.

Mini caso B — Llega a la puerta de enlace, pero no a Internet. Un PC tiene IP correcta, responde ping a su puerta de enlace, pero no llega a ninguna IP externa.
Esquema: la red local funciona · el problema está más allá de la puerta de enlace · tracert 8.8.8.8 para ver dónde se corta · ¿afecta a todos? → salida, cortafuegos u operador · ¿solo a él? → reglas del cortafuegos para su IP o VLAN · escalar con el dato del salto que falla.

Mini caso C — Sale por IP, pero no por nombre. ping 8.8.8.8 responde, pero no abre ninguna web por nombre.
Esquema: la red y la salida funcionan · fallo de DNS · ipconfig /all para ver los servidores DNS · nslookup contra el DNS corporativo · si el DNS del equipo es correcto, revisar el servidor (T10).

Mini caso D — Máscaras distintas. PC1 tiene 192.168.1.10/24 y PC2 192.168.1.130/25, con la misma puerta de enlace; a veces no se comunican.
Esquema: PC1 cree que PC2 está en su red (/24) y le envía directamente · PC2 calcula su red como 192.168.1.128/25: cree que PC1 está fuera y le contesta a través de la puerta de enlace · el tráfico es incoherente o se pierde · corregir la máscara de PC2 a /24 (o la de quien esté mal según el plan de direccionamiento).

Mini caso E — ¿Por qué ARP pide la MAC del router? Un compañero ve con Wireshark que su PC (192.168.193.25/24) envía un ARP preguntando por 192.168.193.1 cuando abre una web externa, y cree que es un error.
Esquema: el destino está fuera de 192.168.193.0/24 · según la tabla de rutas se usa la ruta por defecto (0.0.0.0/0 → 192.168.193.1) · se necesita la MAC del siguiente salto, la puerta de enlace · la trama lleva la MAC del router y el paquete, la IP del destino · es el comportamiento correcto.

Mini caso F — No caben más equipos. Hay que añadir 6 tabletas a la subred de registro 192.168.16.16/28, que ya tiene 2 AP, 8 tabletas y la puerta de enlace.
Esquema: /28 = 14 hosts útiles · ocupados 11 · libres 3 → no caben 6 · ampliar a /27 (30 hosts) si el plan lo permite (192.168.16.0/27, revisando que no pise otras redes) o crear otra subred · cambio coordinado con comunicaciones (T20).

Supuesto desarrollado — Plan de direcciones de un edificio municipal (supuesto). Un edificio va a tener cuatro VLAN: usuarios (90 puestos), telefonía (90 teléfonos), cámaras (12) y gestión de la electrónica de red (8 equipos). Se dispone del bloque privado 10.20.0.0/16 y la salida a Internet es por el cortafuegos municipal.

a) Diseño de subredes.
Usuarios y telefonía: 91 equipos con la puerta de enlace → /25 (126) bastaría; se elige /24 (254) para crecer · cámaras: 13 → /28 justo; mejor /27 (30) · gestión: 9 → /28 (14) · ejemplo: usuarios 10.20.1.0/24, telefonía 10.20.2.0/24, cámaras 10.20.3.0/27, gestión 10.20.3.32/28 · los bloques no se solapan porque cada uno empieza en un múltiplo de su salto.

b) Asignación.
Usuarios y telefonía por DHCP con relay en cada VLAN; la de telefonía, con la opción 66 para aprovisionar los teléfonos · cámaras y gestión con dirección estable (manual o reserva, según el criterio de la organización) y documentada · la puerta de enlace de cada VLAN, en el switch de capa 3 o en el cortafuegos (T4).

c) Salida a Internet.
Direcciones privadas: salida con PAT en el cortafuegos · ningún equipo interno publicado salvo necesidad justificada (redirección de puerto o, mejor, VPN, T15) · reglas del cortafuegos por VLAN (T14).

d) Incidencia.
Tras la puesta en marcha, varios teléfonos muestran 169.254.x.x. Por la escalera: tienen enlace, pero no obtienen configuración DHCP → revisar que su puerto está en la VLAN de voz, que el relay de esa VLAN apunta al servidor y que el ámbito tiene direcciones libres. Se corrige, se verifica con un equipo de prueba y se registra la incidencia (T20).

22. Resumen final: si mañana fuera el examen

TCP/IP tiene cuatro capas y cada una encapsula a la superior: el puerto identifica la aplicación, la IP el equipo y la MAC la interfaz del salto local. IP es sin conexión y best effort; el TTL evita bucles y hace posible el traceroute. ICMP (ping, traceroute) no usa puertos. ARP traduce IPv4 a MAC con un request en broadcast; si el destino está fuera, pregunta por la puerta de enlace. TCP aporta conexión y garantías (SYN, SYN-ACK, ACK); UDP es mínimo (DHCP, voz; DNS usa ambos). Una IPv4 tiene 32 bits: con el prefijo (nunca con la clase) se calculan red, broadcast y hosts (2ⁿ − 2) usando el salto = 256 − máscara. Las privadas (10/8, 172.16/12, 192.168/16) salen habitualmente con PAT; NAT no es seguridad. DHCP sigue DORA, necesita relay entre VLAN, y 169.254 indica que no se obtuvo configuración. IPv6 tiene 128 bits, se abrevia con :: una vez, no tiene broadcast ni ARP (NDP), se autoconfigura con SLAAC o DHCPv6 y aprende la puerta de enlace por el RA. Para diagnosticar: enlace → IP válida → puerta de enlace → IP externa → nombre → servicio.

23. Actualidad — datos fechados

📌 Información sujeta a cambio · Apuntes actualizados en octubre de 2026
Lo estable para el examen es lo explicado arriba; estos datos cambian y no hay que memorizarlos.
  • Adopción de IPv6. La estadística pública de Google mide el porcentaje de usuarios que acceden a los servicios de Google por IPv6, no «el tráfico de Internet»: ronda la mitad a escala mundial, con mucha variación por país y operador.
  • En las redes corporativas internas sigue siendo habitual IPv4 privado con NAT; la doble pila se despliega de forma progresiva.
  • HTTP/3 (sobre QUIC, en UDP 443) ya lo usan muchos navegadores y servicios, aunque HTTPS clásico sobre TCP 443 sigue siendo la referencia.
  • DNS cifrado (DoH, DoT) se extiende en navegadores y sistemas; su efecto sobre el filtrado se trata en T14 y T17.
  • Los sistemas operativos usan por defecto identificadores IPv6 temporales o estables y MAC aleatorias en wifi (T1), lo que complica identificar equipos solo por dirección.
