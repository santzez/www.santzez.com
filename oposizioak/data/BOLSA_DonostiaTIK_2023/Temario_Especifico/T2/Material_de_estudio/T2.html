⚠️ No confundir — fronteras del tema
Este tema trata la pila TCP/IP (IP, ICMP, ARP, TCP, UDP), el direccionamiento IPv4 (clases, privadas, máscaras, subredes, NAT) y el direccionamiento IPv6.
T1 → Ethernet y direcciones MAC. T4 → routing y configuración de interfaces en routers y switches. T10 → servicios de aplicación (DNS, DHCP en detalle, correo, web). T14 → NAT desde el punto de vista del cortafuegos.

1. El modelo TCP/IP

TCP/IP es la familia de protocolos de Internet, desarrollada para ARPANET en los años 70 y normalizada por el IETF mediante documentos RFC. Se organiza en 4 capas (algunos autores separan la física y hablan de 5):

Capa TCP/IP Equivale en OSI Protocolos Unidad de datos Dirección
Aplicación 5, 6 y 7 HTTP/S, DNS, DHCP, SMTP, IMAP, SSH, FTP, SNMP, SIP Datos / mensaje —
Transporte 4 TCP, UDP Segmento / datagrama Puerto (16 bits)
Internet (red) 3 IP (v4, v6), ICMP, IGMP Paquete IP (32 / 128 bits)
Acceso a la red (enlace) 1 y 2 Ethernet, wifi, PPP; ARP en la frontera Trama MAC (48 bits)

Encapsulación: cada capa añade su cabecera a los datos de la capa superior. Un correo viaja como datos SMTP → dentro de un segmento TCP → dentro de un paquete IP → dentro de una trama Ethernet. En el destino se desencapsula en orden inverso.

🧠 Para memorizar
Puerto → aplicación · IP → equipo en Internet · MAC → interfaz en la red local.
Para que un paquete llegue hacen falta las tres: la MAC para el salto local, la IP para el destino final y el puerto para el programa concreto.

2. El protocolo IP

IP (Internet Protocol) encamina paquetes entre redes. Sus características:

  • Sin conexión: cada paquete viaja de forma independiente.
  • No fiable (best effort): no garantiza la entrega, el orden ni la ausencia de duplicados; de eso se encarga TCP.
  • Direccionamiento lógico jerárquico (red + host) que permite el enrutamiento.
  • Fragmentación (IPv4) cuando el paquete supera la MTU de un enlace.

Campos importantes de la cabecera IPv4 (20 bytes mínimo): versión, longitud, TTL (Time To Live: cada router lo decrementa en 1; al llegar a 0 descarta el paquete y avisa con ICMP, lo que evita bucles infinitos), protocolo (6 = TCP, 17 = UDP, 1 = ICMP), IP origen e IP destino, y una suma de comprobación de la cabecera.

3. ICMP y ARP

ICMP

ICMP (Internet Control Message Protocol) transporta mensajes de control y error de IP. Lo usan:

  • ping: envía Echo Request (tipo 8) y espera Echo Reply (tipo 0). Comprueba alcanzabilidad y mide el RTT.
  • tracert / traceroute: envía paquetes con TTL creciente (1, 2, 3…); cada router que lo descarta responde con Time Exceeded (tipo 11), y así se descubre la ruta.
  • Mensajes de error: Destination Unreachable (tipo 3: red, host o puerto inalcanzable), Redirect, etc.
⚠️ TRAMPA DE EXAMEN
ICMP no usa puertos (no es TCP ni UDP; va directamente sobre IP, protocolo 1). Que un ping no responda no prueba que el equipo esté apagado: muchos cortafuegos bloquean ICMP.

ARP

ARP (Address Resolution Protocol) obtiene la dirección MAC (capa 2) a partir de la dirección IP (capa 3) en la red local:

  1. El equipo A quiere enviar a 192.168.1.20 y no conoce su MAC.
  2. Envía un ARP Request en broadcast (FF:FF:FF:FF:FF:FF): «¿quién tiene 192.168.1.20?».
  3. El dueño de esa IP responde con un ARP Reply en unicast con su MAC.
  4. A guarda la correspondencia en su caché ARP (arp -a en Windows) durante un tiempo.

Si el destino está en otra red, el equipo resuelve con ARP la MAC de su puerta de enlace, no la del destino final.

📌 Imprescindible — examen 2023, pregunta 7
El protocolo que obtiene la MAC a partir de la IP es ARP. NTP sincroniza la hora, ICMP transporta mensajes de control y DHCP asigna la configuración IP.
En IPv6 no hay ARP: lo sustituye NDP (Neighbor Discovery Protocol, sobre ICMPv6).

Variantes y riesgos: el ARP gratuito (un equipo anuncia su propia IP, útil para detectar IP duplicadas) y el ARP spoofing / poisoning (un atacante responde con su MAC para interceptar tráfico). Este último se mitiga en el switch con Dynamic ARP Inspection (T4, T17).

4. TCP y UDP

Característica TCP UDP
Conexión Orientado a conexión (three-way handshake) Sin conexión
Fiabilidad Confirmaciones (ACK), retransmisión, orden, control de flujo y de congestión Ninguna: si se pierde, se pierde
Cabecera 20 bytes mínimo 8 bytes
Velocidad / latencia Mayor sobrecarga Mínima sobrecarga y latencia
Usos Web (HTTP/S), correo (SMTP, IMAP), SSH, FTP, transferencia de ficheros DNS (consultas), DHCP, VoIP (RTP), vídeo en directo, SNMP, NTP, syslog, TFTP

Establecimiento de una conexión TCP (three-way handshake): SYN → SYN-ACK → ACK. El cierre se hace con FIN/ACK en ambos sentidos. Un RST corta la conexión de golpe (p. ej., puerto cerrado).

🧠 Para memorizar
TCP = correo certificado (con acuse de recibo y reenvío). UDP = buzoneo (rápido, sin garantías).
La voz va por UDP: un paquete retransmitido llegaría tarde y no sirve.

Puertos

5. Direccionamiento IPv4

Una dirección IPv4 tiene 32 bits, escritos en notación decimal con puntos: cuatro octetos de 0 a 255 (192.168.193.25). Se divide en parte de red y parte de host, y la frontera la marca la máscara.

Clases (direccionamiento classful, histórico)

Clase Primer octeto Bits iniciales Máscara por defecto Uso
A 1 – 126 0 /8 (255.0.0.0) Redes muy grandes
B 128 – 191 10 /16 (255.255.0.0) Redes medianas
C 192 – 223 110 /24 (255.255.255.0) Redes pequeñas
D 224 – 239 1110 — Multicast
E 240 – 255 1111 — Experimental

El 127 está reservado para loopback (127.0.0.1 = el propio equipo). Hoy se usa CIDR (Classless Inter-Domain Routing): la máscara puede ser cualquiera (/26, /20…), y las clases solo sirven como referencia.

Direcciones privadas y especiales

Rango Uso
10.0.0.0/8 Privada (RFC 1918)
172.16.0.0/12 (172.16.0.0 – 172.31.255.255) Privada (RFC 1918)
192.168.0.0/16 Privada (RFC 1918)
127.0.0.0/8 Loopback
169.254.0.0/16 APIPA / link-local: la toma el equipo cuando no recibe respuesta del DHCP
100.64.0.0/10 CGNAT de operadores (RFC 6598)
0.0.0.0 «Esta red» / ruta por defecto (0.0.0.0/0)
255.255.255.255 Broadcast limitado
📌 Imprescindible
Las direcciones privadas no se enrutan en Internet: para salir hace falta NAT (apartado 8). Las redes del caso de 2023 (192.168.193.0, 10.42.96.0, 172.16.47.0) son todas privadas.
Un PC con 169.254.x.x indica fallo de DHCP (cable, VLAN mal configurada en el puerto o servidor caído): es una pista clásica de avería.

Máscara, red, broadcast y hosts

  • Dirección de red: todos los bits de host a 0 (identifica la subred; no se asigna a equipos).
  • Dirección de broadcast: todos los bits de host a 1 (llega a todos los equipos de la subred).
  • Hosts útiles = 2ⁿ − 2, siendo n el número de bits de host.

🧠 Para memorizar los valores de máscara
128 · 192 · 224 · 240 · 248 · 252 · 254 · 255 (1, 2, 3… bits a 1 en el octeto).
Salto = 256 − valor de la máscara en el octeto «interesante». Con 255.255.255.192 el salto es 256 − 192 = 64.

6. Cálculo de subredes paso a paso

Método del salto (bloque):

  1. Localiza el octeto interesante (el primero de la máscara que no es 255).
  2. Salto = 256 − valor de la máscara en ese octeto.
  3. Las subredes empiezan en múltiplos del salto (0, 64, 128, 192…).
  4. Red = el múltiplo del salto igual o inferior a la IP. Broadcast = siguiente red − 1. Hosts = lo que hay entre ambas.
📌 Examen 2023, pregunta 5
Red 213.114.93.0 con máscara 255.255.255.192 (/26): salto = 256 − 192 = 64. La primera subred va de .0 a .63, así que el broadcast es 213.114.93.63. Hosts útiles: .1 a .62 (62 hosts).
Trampas de las otras opciones: .127 sería el broadcast de la segunda subred /26 (o de una /25); .31 el de una /27; .255 el de una /24.

Ejemplos con las subredes del caso de 2023

Subred del enunciado Máscara Red Rango de hosts Broadcast Hosts
Usuarios 192.168.193.0 /24 192.168.193.0 .1 – .254 192.168.193.255 254
Telefonía 10.42.96.0 255.255.240.0 (/20) 10.42.96.0 10.42.96.1 – 10.42.111.254 10.42.111.255 4.094
Registro 192.168.16.16 255.255.255.240 (/28) 192.168.16.16 .17 – .30 192.168.16.31 14
Internet libre 192.168.122.0 /23 192.168.122.0 192.168.122.1 – 192.168.123.254 192.168.123.255 510
Cámaras 172.16.47.0 /24 172.16.47.0 .1 – .254 172.16.47.255 254

Cómo se calcula la de telefonía: máscara 255.255.240.0 → octeto interesante el tercero, salto 256 − 240 = 16. Las subredes empiezan en 96 (múltiplo de 16) y la siguiente en 112, así que el broadcast es 10.42.111.255.

💡 Para el caso práctico
Fíjate en el tamaño de cada subred: la de registro (/28) solo admite 14 equipos (2 AP + tabletas + la puerta de enlace). Si te piden añadir dispositivos, comprueba que caben. La de Internet libre (/23) es grande porque los invitados por wifi son muchos y su IP es dinámica (DHCP).

VLSM y superredes

  • VLSM (Variable Length Subnet Mask): usar máscaras distintas según el tamaño de cada subred (/30 para enlaces punto a punto entre routers, /24 para usuarios, /28 para dispositivos). Ahorra direcciones.
  • Sumarización (superred): agrupar varias redes contiguas en una sola ruta. Por ejemplo, 192.168.0.0/24 + 192.168.1.0/24 = 192.168.0.0/23. Reduce las tablas de rutas.

7. Asignación de direcciones: estática y DHCP

  • Estática: se configura a mano (IP, máscara, puerta de enlace, DNS). Se usa en servidores, impresoras, cámaras, PLC, electrónica de red: equipos que deben tener siempre la misma IP. En el caso de 2023, todo salvo telefonía, wifi e Internet libre.
  • Dinámica con DHCP (Dynamic Host Configuration Protocol, UDP 67/68): un servidor entrega la configuración por un tiempo (concesión o lease). Proceso DORA: Discover (broadcast) → Offer → Request → Ack.
  • Reserva DHCP: el servidor entrega siempre la misma IP a una MAC concreta (lo mejor de ambos mundos).
  • DHCP Relay (ip helper-address): como el Discover es un broadcast y no atraviesa routers, el router o switch de capa 3 de cada VLAN lo reenvía al servidor DHCP central.
  • Opciones DHCP: además de IP, máscara, puerta de enlace (opción 3) y DNS (opción 6), el DHCP puede dar a los teléfonos IP la dirección de su servidor de aprovisionamiento (opciones 66/150) o su VLAN de voz.
⚠️ TRAMPA DE EXAMEN
Sin puerta de enlace configurada un equipo solo se comunica con su propia subred. Sin DNS, se comunica por IP pero no resuelve nombres: ping 8.8.8.8 funciona y ping google.com, no.

8. NAT

NAT (Network Address Translation) traduce direcciones IP al pasar por el router o el cortafuegos. Nació para paliar el agotamiento de IPv4: muchas direcciones privadas comparten pocas públicas.

Tipo Qué hace Uso
NAT estático (1:1) Una IP privada ↔︎ una IP pública fija Publicar un servidor interno
NAT dinámico IP privadas ↔︎ un conjunto (pool) de públicas Poco usado hoy
PAT / NAT overload (masquerade) Muchas privadas → una pública, distinguidas por puerto Salida a Internet de una LAN; el router de casa
Port forwarding (DNAT de puerto) Un puerto de la IP pública → IP y puerto internos Acceso desde fuera a un servicio concreto (en el caso de 2023, una opción para el mantenedor del PLC, coordinada con Sistemas)
⚠️ TRAMPA DE EXAMEN
NAT no es una medida de seguridad por sí misma (oculta la red, pero no filtra). La seguridad la dan las reglas del cortafuegos (T14). Y NAT no tiene nada que ver con NAC (control de acceso a la red; T17).

9. IPv6

Por qué y cómo

IPv6 resuelve el agotamiento de IPv4 (la IANA asignó sus últimos bloques en 2011). Sus direcciones tienen 128 bits (≈ 3,4 × 10³⁸ direcciones).

  • Se escriben en 8 grupos de 4 dígitos hexadecimales separados por dos puntos: 2001:0db8:0000:0000:0000:ff00:0042:8329.
  • Simplificación: se pueden quitar los ceros a la izquierda de cada grupo, y una sola vez se puede sustituir una secuencia de grupos a cero por :: → 2001:db8::ff00:42:8329.
  • Prefijo con notación CIDR: una red de usuarios típica es un /64 (64 bits de red + 64 de identificador de interfaz).

Tipos de direcciones IPv6

Tipo Prefijo Equivale en IPv4 a
Unicast global (GUA) 2000::/3 (empiezan por 2 o 3) Dirección pública
Link-local FE80::/10 169.254.x.x (pero en IPv6 siempre existe en cada interfaz)
Unique local (ULA) FC00::/7 (en la práctica FD00::/8) Privadas RFC 1918
Multicast FF00::/8 224.0.0.0/4
Loopback ::1 127.0.0.1
No especificada :: 0.0.0.0
Documentación 2001:db8::/32 Ejemplos en manuales
📌 Imprescindible
En IPv6 no existe el broadcast: se usa multicast (por ejemplo, FF02::1 = todos los nodos del enlace).
Tampoco hay ARP: la resolución de vecinos y el descubrimiento de routers los hace NDP (ICMPv6).

Autoconfiguración

  • SLAAC (Stateless Address Autoconfiguration): el router anuncia el prefijo (Router Advertisement) y el equipo genera él mismo su identificador de interfaz (por EUI-64, derivado de la MAC, o aleatorio por privacidad). No necesita servidor.
  • DHCPv6: con estado (asigna direcciones, como el DHCP de IPv4) o sin estado (solo da DNS y otras opciones).

Diferencias clave IPv4 / IPv6

IPv4 IPv6
Longitud 32 bits 128 bits
Notación Decimal con puntos Hexadecimal con dos puntos
Cabecera Variable (20–60 B), con checksum Fija de 40 B, sin checksum, con cabeceras de extensión
Broadcast Sí No (multicast)
Resolución de MAC ARP NDP
Autoconfiguración DHCP SLAAC y/o DHCPv6
Fragmentación Routers y origen Solo el origen (descubrimiento de MTU de ruta)
NAT Imprescindible en la práctica Innecesario (sobran direcciones)
IPsec Opcional Soportado de forma nativa (su uso sigue siendo opcional)

Transición IPv4 → IPv6

  • Doble pila (dual stack): el equipo tiene a la vez IPv4 e IPv6. Es el mecanismo preferido.
  • Túneles: IPv6 encapsulado dentro de IPv4 (6in4, 6to4, Teredo…).
  • Traducción: NAT64 + DNS64, para que equipos solo IPv6 alcancen servicios solo IPv4.

12. Anclas de memoria

  • IPv4 = 32 bits · IPv6 = 128 bits · MAC = 48 bits · puerto = 16 bits.
  • Privadas: 10/8 · 172.16/12 · 192.168/16. 169.254 = sin DHCP.
  • Hosts = 2ⁿ − 2 · salto = 256 − máscara.
  • ARP: IP → MAC (broadcast); en IPv6, NDP.
  • TCP: SYN, SYN-ACK, ACK. UDP: DNS, DHCP, VoIP, SNMP, NTP.
  • 22 SSH · 53 DNS · 80 HTTP · 443 HTTPS · 25 SMTP · 3389 RDP.
  • IPv6: sin broadcast, sin ARP, sin NAT; FE80 link-local; :: una sola vez.

13. No confundir

Esto No es esto
ARP (IP → MAC) RARP, obsoleto (MAC → IP) y DNS (nombre → IP)
ICMP (control, sin puertos) TCP/UDP (transporte, con puertos)
NAT (traduce direcciones) NAC (controla quién entra en la red)
Dirección de red (bits de host a 0) Puerta de enlace (un host, normalmente la .1)
/23 (510 hosts, ocupa dos «/24») /32 (un único host)
Link-local IPv6 (FE80, siempre presente) APIPA IPv4 (169.254, solo si falla el DHCP)

14. Posibles trampas de examen

  • Contar la red y el broadcast como hosts (los hosts útiles son 2ⁿ − 2).
  • Elegir .127 o .255 como broadcast de un /26 que empieza en .0.
  • Decir que ICMP usa el puerto 7 o el 0 (no usa puertos).
  • Pensar que DNS solo usa UDP (las transferencias de zona y respuestas grandes usan TCP 53).
  • Comprimir con :: dos veces en la misma dirección IPv6.
  • Creer que IPv6 elimina por completo la necesidad de DHCP o que IPv6 tiene broadcast.
  • Confundir 172.16.0.0/12 (hasta 172.31.255.255) con 172.16.0.0/16.

15. Posibles preguntas tipo test

  1. ¿Cuántos hosts útiles tiene una subred /28? → 14.
  2. ¿Qué rango es privado? → 172.20.5.0 sí (dentro de 172.16/12); 172.32.0.0, no.
  3. ¿Qué protocolo usa el three-way handshake? → TCP.
  4. ¿Cuál es la dirección de loopback en IPv6? → ::1.
  5. ¿Qué tipo de NAT permite que toda la LAN salga con una sola IP pública? → PAT (NAT overload).

16. Posibles preguntas cortas (con esquema de respuesta)

1. Diferencias entre TCP y UDP, con ejemplos de uso (2 puntos).

  • Conexión (sí/no), fiabilidad (ACK y retransmisión / ninguna), orden, control de flujo.
  • Cabecera de 20 B frente a 8 B; latencia.
  • Ejemplos TCP: HTTPS, SMTP, SSH. Ejemplos UDP: DNS, DHCP, VoIP-RTP, SNMP.
  • Criterio: fiabilidad (TCP) frente a tiempo real (UDP).

2. Explica las principales diferencias entre IPv4 e IPv6 (2 puntos).

  • 32 frente a 128 bits y notación.
  • Sin broadcast (multicast), NDP en lugar de ARP, SLAAC.
  • Cabecera fija de 40 B y fragmentación solo en origen.
  • Sin necesidad de NAT; transición por doble pila, túneles y NAT64.

17. Supuesto práctico

Enunciado: un PC recién instalado en la planta primera tiene la IP 169.254.33.10 y no navega. Los demás puestos de la planta funcionan.

Esquema de respuesta:

  1. Interpretación: 169.254.x.x = APIPA: el equipo no ha recibido respuesta del DHCP.
  2. Nivel físico: luz de enlace en la tarjeta y en el puerto; latiguillo y roseta; seguir la toma en el patch panel hasta el puerto del switch.
  3. Nivel de enlace: comprobar en el switch que el puerto está activo y en la VLAN correcta (usuarios, 23); si está en una VLAN sin DHCP o el puerto está desactivado (shutdown, err-disabled), el DHCP no llega.
  4. Nivel de red: ipconfig /release y /renew; comprobar que el DHCP relay de la VLAN está configurado en el switch principal o el cortafuegos y que el ámbito tiene direcciones libres.
  5. Escalado: si el puerto o el relay requieren cambios, coordinación con el grupo de comunicaciones o sistemas y registro de la incidencia.

19. Resumen final: si mañana fuera el examen

TCP/IP tiene cuatro capas: aplicación, transporte (TCP fiable y con conexión; UDP rápido y sin conexión), Internet (IP, con ICMP para control) y acceso a la red; ARP traduce IP a MAC. Una IPv4 tiene 32 bits: con la máscara se calculan red, broadcast (bits de host a 1) y hosts (2ⁿ − 2), usando el salto = 256 − máscara. Las privadas (10/8, 172.16/12, 192.168/16) salen a Internet con NAT/PAT. IPv6 usa 128 bits en hexadecimal; no tiene broadcast ni ARP (usa NDP) y se autoconfigura con SLAAC. Para diagnosticar, ve de abajo arriba: IP válida → puerta de enlace → IP externa → nombre.
