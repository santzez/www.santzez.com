Mapa del tema

T2 explica cómo viajan los datos por encima de Ethernet: la pila TCP/IP (IP, ICMP, ARP, TCP, UDP), el direccionamiento IPv4 (máscaras, subredes, privadas, asignación) y el direccionamiento IPv6. Es el tema más «de cálculo» del bloque 1 y el que más preguntas de test aporta.

Si la pregunta trata de… Está en Desde T2 solo…
Ethernet, tramas, direcciones MAC, switch T1 se usa la MAC como dirección del salto local
Configurar interfaces, VLAN, rutas en Cisco/Aruba T4 se dice qué es una puerta de enlace y una ruta
DNS, DHCP como servicios, correo, web T10 se explica DHCP como forma de asignar direcciones

VPN e IPsec T15 se cita IPsec
Metodología de diagnóstico T19 se usan los comandos básicos de comprobación IP

Cada apartado sigue tres niveles: concepto, explicación y aplicación práctica.

1. El modelo TCP/IP y la encapsulación

Concepto. TCP/IP es la familia de protocolos de Internet, normalizada por el IETF en documentos RFC. Se organiza en cuatro capas: aplicación, transporte, internet y acceso a la red.

Explicación.

Capa TCP/IP Protocolos Unidad de datos Dirección que usa
Aplicación HTTP/S, DNS, DHCP, SMTP, IMAP, SSH, SNMP, SIP Datos / mensaje —
Transporte TCP, UDP Segmento (TCP) / datagrama (UDP) Puerto (16 bits)
Internet IP (v4, v6), ICMP Paquete IP (32 / 128 bits)
Acceso a la red Ethernet, wifi (T1, T5); ARP hace de puente con IP Trama MAC (48 bits)

Algunos autores hablan de cinco capas (separan la física). La correspondencia con OSI es aproximada: aplicación ≈ 5-7, transporte = 4, internet = 3, acceso a la red ≈ 1-2.

Encapsulación: cada capa añade su cabecera a lo que le entrega la superior. Un correo viaja como datos SMTP dentro de un segmento TCP, dentro de un paquete IP, dentro de una trama Ethernet. El destino desencapsula en orden inverso.

Aplicación práctica. Para que un paquete llegue hacen falta tres direcciones: la MAC para el salto local, la IP para el destino final y el puerto para el programa concreto. Si una de ellas falla, falla la comunicación, y cada una se diagnostica de forma distinta.

🧠 Para memorizar
Puerto → aplicación · IP → equipo en Internet · MAC → interfaz en la red local.
Trama ⊃ paquete ⊃ segmento ⊃ datos.

2. El protocolo IP

Concepto. IP (Internet Protocol) lleva cada paquete de una red a otra (enrutamiento) usando direcciones lógicas jerárquicas (red + host).

Explicación.

  • Sin conexión: cada paquete viaja de forma independiente.
  • No fiable (best effort): no garantiza entrega, orden ni ausencia de duplicados; eso lo hace TCP si se necesita.
  • Fragmentación (IPv4): si un paquete no cabe en la MTU de un enlace, se trocea, salvo que lleve el bit DF (Don't Fragment), en cuyo caso se descarta y se avisa con ICMP.

Campos de la cabecera IPv4 que hay que conocer (20 bytes sin opciones):

Campo Para qué sirve
TTL (Time To Live) Cada router lo resta en 1; al llegar a 0 descarta el paquete y avisa con ICMP. Evita que un paquete circule para siempre en un bucle
Protocolo Qué lleva dentro: 1 = ICMP, 6 = TCP, 17 = UDP
DSCP Marca de prioridad (QoS); la voz se marca para tener preferencia (T9)
IP origen / IP destino 32 bits cada una
Suma de comprobación Solo de la cabecera

Aplicación práctica. Un traceroute funciona gracias al TTL (apartado 3), y la marca DSCP es lo que permite que la telefonía IP tenga prioridad en la red municipal.

3. ICMP

Concepto. ICMP (Internet Control Message Protocol) transporta mensajes de control y de error de IP. Va directamente sobre IP (protocolo 1) y no usa puertos.

Explicación.

Uso Mensajes ICMP
ping Echo Request (tipo 8) y Echo Reply (tipo 0): comprueba si un destino responde y mide el RTT
Traceroute Se envían paquetes con TTL 1, 2, 3…; cada router que agota el TTL responde Time Exceeded (tipo 11) y así se descubre la ruta
Errores Destination Unreachable (tipo 3: red, host o puerto inalcanzable), Redirect, «hace falta fragmentar»

Matiz útil: tracert de Windows envía Echo Request ICMP; traceroute de Linux envía por defecto datagramas UDP. Ambos se basan en el TTL y en las respuestas Time Exceeded.

Aplicación práctica. Que un ping no responda no prueba que el equipo esté apagado: muchos cortafuegos (incluido el de Windows) bloquean ICMP. Los asteriscos en un traceroute indican saltos que no responden, no necesariamente una avería.

⚠️ TRAMPA DE EXAMEN
ICMP no usa puertos (ni TCP ni UDP). «Ping usa el puerto 7» es falso.

4. ARP

Concepto. ARP (Address Resolution Protocol) obtiene la dirección MAC (capa 2) a partir de una dirección IP (capa 3) dentro de la red local.

Explicación.

  1. El equipo A quiere enviar a 192.168.1.20 y no conoce su MAC.
  2. Envía un ARP Request en broadcast (FF:FF:FF:FF:FF:FF): «¿quién tiene 192.168.1.20?». Lo reciben todos los equipos de la VLAN.
  3. Solo el dueño de esa IP responde con un ARP Reply en unicast con su MAC.
  4. A guarda la correspondencia en su caché ARP durante un tiempo (arp -a en Windows, ip neigh en Linux).

Si el destino está en otra red, el equipo no pregunta por la MAC del destino, sino por la de su puerta de enlace: la trama va al router y el paquete IP sigue hacia el destino.

Variantes y riesgos:

  • ARP gratuito: un equipo anuncia su propia IP; sirve para detectar IP duplicadas y para actualizar cachés tras un cambio.
  • ARP spoofing: un atacante responde con su MAC para interceptar tráfico. Se mitiga en el switch con Dynamic ARP Inspection (T4, T17).
📌 Imprescindible — examen 2023, pregunta 7
El protocolo que obtiene la MAC a partir de la IP es ARP. En IPv6 no hay ARP: lo hace NDP (Neighbor Discovery Protocol, sobre ICMPv6).
⚠️ No confundir — ARP vs DNS vs DHCP
ARP: IP → MAC, en la red local. DNS: nombre → IP (T10). DHCP: entrega la configuración IP al equipo (apartado 8).

5. TCP, UDP y puertos

Concepto. La capa de transporte entrega los datos a la aplicación correcta (por puerto). TCP lo hace de forma fiable y con conexión; UDP, de forma rápida y sin conexión.

Explicación.

Característica TCP UDP
Conexión Orientado a conexión (three-way handshake) Sin conexión
Fiabilidad Confirmaciones (ACK), retransmisión, orden, control de flujo y de congestión Ninguna: si se pierde, se pierde
Cabecera 20 bytes mínimo 8 bytes
Latencia Mayor Mínima
Usos Web (HTTP/S), correo (SMTP, IMAP), SSH, transferencia de ficheros, RDP DNS (consultas), DHCP, voz y vídeo (RTP), SNMP, NTP, syslog, TFTP

Conexión TCP: SYN → SYN-ACK → ACK. El cierre ordenado usa FIN y ACK en cada sentido; un RST corta de golpe (por ejemplo, si el puerto está cerrado).

Puertos. Un puerto (16 bits, de 0 a 65.535) identifica la aplicación. Una conexión queda definida por IP y puerto de origen + IP y puerto de destino + protocolo.

Rango Nombre
0 – 1023 Bien conocidos (well-known), asignados por la IANA
1024 – 49151 Registrados
49152 – 65535 Dinámicos o efímeros: los usa el cliente como origen
Puerto Servicio Puerto Servicio
20/21 TCP FTP (datos/control) 110 TCP POP3
22 TCP SSH, SFTP, SCP 123 UDP NTP
23 TCP Telnet (inseguro) 143 TCP IMAP
25 TCP SMTP 161/162 UDP SNMP / traps
53 UDP y TCP DNS 443 TCP HTTPS
67/68 UDP DHCP (servidor/cliente) 445 TCP SMB (compartición Windows)
69 UDP TFTP 514 UDP Syslog
80 TCP HTTP 3389 TCP RDP
5060 / 5061 SIP / SIP sobre TLS 993 / 995 IMAPS / POP3S

Aplicación práctica. Abrir o cerrar un servicio en el cortafuegos es abrir o cerrar un puerto y un protocolo (T14). La voz va por UDP porque un paquete retransmitido llegaría tarde y no serviría.

📌 Imprescindible — examen 2023, pregunta 8
Para configurar un switch de forma remota con SSH se usa el puerto 22.
⚠️ No confundir — TCP vs UDP
TCP = correo certificado: conexión, acuse de recibo, reenvío y orden. UDP = buzoneo: rápido y sin garantías.
DNS usa los dos: UDP para las consultas normales y TCP para las respuestas grandes y las transferencias de zona.

6. Direccionamiento IPv4

Concepto. Una dirección IPv4 tiene 32 bits, escritos como cuatro números de 0 a 255 (192.168.193.25). La máscara indica qué bits son de red y cuáles de host.

Explicación.

  • Dirección de red: todos los bits de host a 0. Identifica la subred; no se asigna a equipos.
  • Dirección de broadcast: todos los bits de host a 1. Llega a todos los equipos de la subred.
  • Hosts útiles = 2ⁿ − 2, siendo n los bits de host. Excepciones: un /31 se usa en enlaces punto a punto con sus 2 direcciones útiles y un /32 identifica un único equipo (por ejemplo, una interfaz de loopback de un router).
Prefijo Máscara Bits de host Hosts útiles Salto
/30 255.255.255.252 2 2 4
/29 255.255.255.248 3 6 8
/28 255.255.255.240 4 14 16
/27 255.255.255.224 5 30 32
/26 255.255.255.192 6 62 64
/25 255.255.255.128 7 126 128
/24 255.255.255.0 8 254 1 en el 3.er octeto
/23 255.255.254.0 9 510 2 en el 3.er octeto
/22 255.255.252.0 10 1.022 4 en el 3.er octeto
/20 255.255.240.0 12 4.094 16 en el 3.er octeto
/16 255.255.0.0 16 65.534 —

Clases (histórico). Antes de CIDR, la máscara venía dada por el primer octeto:

Clase Bits iniciales Primer octeto Máscara por defecto
A 0 0 – 127 (útiles 1 – 126) /8
B 10 128 – 191 /16
C 110 192 – 223 /24
D 1110 224 – 239 Multicast
E 1111 240 – 255 Reservada

El 0 y el 127 no se usan como redes normales (el 127 es loopback). Hoy se usa CIDR: cualquier longitud de máscara (/26, /20…); las clases quedan como referencia de examen.

Direcciones privadas y especiales:

Rango Uso
10.0.0.0/8 Privada (RFC 1918)
172.16.0.0/12 (172.16.0.0 – 172.31.255.255) Privada (RFC 1918)
192.168.0.0/16 Privada (RFC 1918)
127.0.0.0/8 Loopback (127.0.0.1 = el propio equipo)
169.254.0.0/16 Link-local (APIPA): la toma un equipo que no recibe respuesta del DHCP
100.64.0.0/10 CGNAT de operadores (RFC 6598)
224.0.0.0/4 Multicast
192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24 Reservadas para documentación y ejemplos
0.0.0.0/0 · 255.255.255.255 Ruta por defecto · broadcast limitado

Aplicación práctica. Las privadas no se enrutan en Internet: para salir hace falta NAT (apartado 9). Todas las redes del caso de 2023 eran privadas. Y un PC con 169.254.x.x es la pista clásica de fallo de DHCP.

🧠 Para memorizar los valores de máscara
128 · 192 · 224 · 240 · 248 · 252 · 254 · 255 (1, 2, 3… bits a 1 en el octeto).
Salto = 256 − valor de la máscara en el octeto que no es 255. Hosts = 2ⁿ − 2.
⚠️ TRAMPA DE EXAMEN
172.16.0.0/12 llega hasta 172.31.255.255: 172.20.x.x es privada; 172.32.x.x, no.

7. Cálculo de subredes paso a paso

Concepto. Calcular una subred es encontrar su dirección de red, su broadcast y su rango de hosts a partir de una IP y una máscara.

Explicación — método del salto:

  1. Localiza el octeto interesante: el primero de la máscara que no es 255.
  2. Salto = 256 − valor de la máscara en ese octeto.
  3. Las subredes empiezan en múltiplos del salto (0, 64, 128, 192…).
  4. Red = el múltiplo igual o inferior a la IP. Broadcast = siguiente red − 1. Hosts = lo que queda entre ambas.
📌 Imprescindible — examen 2023, pregunta 5
Red 213.114.93.0 con máscara 255.255.255.192 (/26): salto 64, la primera subred va de .0 a .63 → broadcast 213.114.93.63. Las otras opciones eran trampas: .127 (broadcast de la segunda /26), .31 (de una /27) y .255 (de una /24).

Las subredes del caso de 2023:

Subred del enunciado Máscara Rango de hosts Broadcast Hosts
Usuarios 192.168.193.0 /24 .1 – .254 192.168.193.255 254
Telefonía 10.42.96.0 255.255.240.0 (/20) 10.42.96.1 – 10.42.111.254 10.42.111.255 4.094
Registro 192.168.16.16 255.255.255.240 (/28) .17 – .30 192.168.16.31 14
Internet libre 192.168.122.0 /23 192.168.122.1 – 192.168.123.254 192.168.123.255 510
Cámaras 172.16.47.0 /24 .1 – .254 172.16.47.255 254

Telefonía: máscara 255.255.240.0 → octeto interesante el tercero, salto 16; 96 es múltiplo de 16 y la siguiente red empieza en 112, así que el broadcast es 10.42.111.255.

VLSM y sumarización.

  • VLSM (Variable Length Subnet Mask): máscaras distintas según el tamaño de cada subred (/30 o /31 para enlaces entre routers, /24 para usuarios, /28 para un grupo pequeño de dispositivos). Ahorra direcciones.
  • Sumarización (superred): agrupar redes contiguas en una sola ruta: 192.168.0.0/24 + 192.168.1.0/24 = 192.168.0.0/23.

Aplicación práctica. Comprueba siempre el tamaño: la subred de registro (/28) solo admite 14 equipos, contando la puerta de enlace. Si te piden añadir dispositivos, mira primero si caben.

💡 Para el caso práctico
Ante una tabla de subredes, calcula para cada una rango, broadcast y número de hosts, y di si se asigna por DHCP (usuarios, wifi, invitados, telefonía) o estática (servidores, impresoras, cámaras, electrónica de red).

8. Asignación de direcciones: estática y DHCP

Concepto. Un equipo obtiene su configuración IP (dirección, máscara, puerta de enlace y DNS) a mano (estática) o automáticamente por DHCP.

Explicación.

  • Estática: para equipos que deben tener siempre la misma IP: servidores, impresoras, cámaras, PLC, electrónica de red.
  • DHCP (Dynamic Host Configuration Protocol, UDP 67/68): un servidor presta la configuración durante un tiempo (concesión o lease). Proceso DORA: Discover → Offer → Request → Ack.
  • Reserva DHCP: el servidor da siempre la misma IP a una MAC concreta. Cuidado con las MAC aleatorias (T1).
  • DHCP relay (ip helper-address): el Discover es un broadcast y no atraviesa routers; el switch de capa 3 o el cortafuegos de cada VLAN lo reenvía al servidor central.
  • Opciones DHCP: además de la puerta de enlace (opción 3) y el DNS (opción 6), puede dar a los teléfonos IP la dirección de su servidor de configuración (opción 66; la 150 es propia de Cisco).

Aplicación práctica. Sin puerta de enlace, un equipo solo habla con su propia subred. Sin DNS, se comunica por IP pero no resuelve nombres: ping 8.8.8.8 funciona y ping www.donostia.eus no. El servidor DHCP en sí se estudia en T10.

⚠️ No confundir — red, broadcast y puerta de enlace
Dirección de red: bits de host a 0, no es de nadie. Broadcast: bits de host a 1, es de todos. Puerta de enlace: un host normal de la subred (a menudo la .1 o la .254), el router.

9. NAT (concepto)

Concepto. NAT (Network Address Translation) traduce direcciones IP al atravesar un router o cortafuegos. Nació para paliar el agotamiento de IPv4: muchas privadas comparten pocas públicas.

Explicación.

Tipo Qué hace Uso típico
NAT estático (1:1) Una privada ↔︎ una pública fija Publicar un servidor interno
NAT dinámico Privadas ↔︎ un conjunto de públicas Poco usado hoy
PAT / NAT overload Muchas privadas → una pública, distinguidas por puerto Salida a Internet de una LAN
Redirección de puertos (DNAT) Un puerto de la IP pública → IP y puerto internos Dar acceso desde fuera a un servicio concreto

Aplicación práctica. En el caso de 2023, el acceso remoto del mantenedor del PLC podía resolverse con VPN (lo recomendable, T15) o con una redirección de puerto en el cortafuegos, coordinada con Sistemas. La configuración de NAT en el cortafuegos se estudia en T14.

⚠️ No confundir — NAT vs NAC vs cortafuegos
NAT traduce direcciones; no es una medida de seguridad por sí misma. El cortafuegos filtra con reglas (T14). NAC controla qué equipos pueden entrar en la red (T17).

10. IPv6

Concepto. IPv6 usa direcciones de 128 bits para resolver el agotamiento de IPv4 (la IANA repartió los últimos bloques IPv4 en 2011).

Explicación — notación. Ocho grupos de cuatro dígitos hexadecimales separados por dos puntos. Para abreviar:

  1. Se quitan los ceros a la izquierda de cada grupo.
  2. Una sola vez por dirección, una secuencia de grupos a cero se sustituye por ::.

Una red de usuarios es normalmente un /64: 64 bits de prefijo y 64 de identificador de interfaz.

Tipos de direcciones:

Tipo Prefijo Equivalente aproximado en IPv4
Unicast global (GUA) 2000::/3 (empiezan por 2 o 3) Pública
Link-local FE80::/10 169.254.x.x, pero en IPv6 existe siempre en cada interfaz
Unique local (ULA) FC00::/7 (en la práctica FD00::/8) Privadas RFC 1918
Multicast FF00::/8 224.0.0.0/4
Loopback ::1 127.0.0.1
No especificada :: 0.0.0.0

Sin broadcast y sin ARP. IPv6 usa multicast (FF02::1 = todos los nodos del enlace) y NDP (ICMPv6) para descubrir vecinos y routers.

Autoconfiguración:

  • SLAAC: el router anuncia el prefijo (Router Advertisement) y el equipo genera su identificador de interfaz, derivado de la MAC (EUI-64) o aleatorio por privacidad. No necesita servidor.
  • DHCPv6: con estado (asigna direcciones) o sin estado (solo da DNS y otras opciones).
IPv4 IPv6
Longitud 32 bits 128 bits
Notación Decimal con puntos Hexadecimal con dos puntos
Cabecera Variable (20–60 B), con suma de comprobación Fija de 40 B, sin suma de comprobación
Broadcast Sí No (multicast)
Resolución de MAC ARP NDP
Autoconfiguración DHCP SLAAC y/o DHCPv6
Fragmentación Origen y routers Solo el origen
NAT Habitual Innecesario en general

Transición: doble pila (el equipo usa IPv4 e IPv6 a la vez; es lo preferido), túneles (IPv6 dentro de IPv4) y traducción NAT64 + DNS64 (equipos solo IPv6 que acceden a servicios solo IPv4).

Aplicación práctica. Aunque la red municipal sea IPv4, los equipos actuales tienen IPv6 activado y siempre muestran una dirección FE80:: en ipconfig: es normal y no indica avería.

⚠️ No confundir — APIPA vs link-local IPv6
169.254.x.x en IPv4 aparece solo cuando falla el DHCP: es síntoma de avería. FE80:: en IPv6 aparece siempre: es normal.
⚠️ TRAMPA DE EXAMEN
El :: solo puede usarse una vez en una dirección; si se usara dos veces no se sabría cuántos ceros hay en cada hueco.

11. Situaciones profesionales: comprobar la conectividad IP

Concepto. La mayoría de los avisos «no tengo red» se ordenan comprobando la conectividad IP de abajo arriba. La metodología completa de diagnóstico está en T19.

Explicación — comandos:

Windows · Linux Para qué
ipconfig /all · ip addr IP, máscara, puerta de enlace, DNS, MAC
ipconfig /release y /renew Pedir de nuevo la configuración al DHCP
ping Alcanzabilidad y RTT
tracert · traceroute Ruta salto a salto
arp -a · ip neigh Caché ARP
nslookup · dig Consultas DNS
netstat -an · ss -tuln Conexiones y puertos abiertos
route print · ip route Tabla de rutas del equipo

Aplicación práctica — situaciones típicas:

Situación Lectura en clave de T2 Primera comprobación
IP 169.254.x.x No hay respuesta del DHCP Enlace, VLAN del puerto, relay, direcciones libres en el ámbito
Navega por IP pero no por nombre DNS Servidores DNS configurados; nslookup
Llega a su subred pero no fuera Puerta de enlace ausente o errónea, o máscara mal puesta ipconfig; ping a la puerta de enlace
Aviso de IP duplicada Dos equipos con la misma IP (estática mal puesta o fuera de la reserva) arp -a para ver qué MAC responde; buscarla en el switch (T1)
Ping no responde pero el servicio funciona ICMP filtrado Probar el servicio (puerto) en lugar de ICMP
Asteriscos en traceroute Saltos que no responden a ICMP Ver si el destino final responde
💡 Para el caso práctico
Responde siempre con la escalera: IP válida → puerta de enlace → IP externa → nombre. El primer paso que falla te dice la capa y justifica a quién se escala (comunicaciones, sistemas u operador).

13. Anclas de memoria

  • IPv4 = 32 bits · IPv6 = 128 bits · MAC = 48 bits · puerto = 16 bits.
  • Privadas: 10/8 · 172.16/12 (hasta 172.31) · 192.168/16 · 169.254 = sin DHCP.
  • Hosts = 2ⁿ − 2 · salto = 256 − máscara · broadcast = siguiente red − 1.
  • ARP: IP → MAC, request en broadcast y reply en unicast; en IPv6, NDP.
  • ICMP: protocolo 1, sin puertos · TCP = 6 · UDP = 17.
  • TCP: SYN, SYN-ACK, ACK · UDP: DNS, DHCP, voz, SNMP, NTP, syslog.
  • 22 SSH · 25 SMTP · 53 DNS · 80 HTTP · 443 HTTPS · 3389 RDP.
  • DHCP: DORA, UDP 67/68, relay porque el broadcast no cruza routers.
  • IPv6: sin broadcast, sin ARP · FE80 siempre presente · :: una sola vez.

14. No confundir

Esto No es esto
ARP (IP → MAC) DNS (nombre → IP) y DHCP (entrega la configuración)
ICMP (control, sin puertos) TCP/UDP (transporte, con puertos)
TCP (fiable, con conexión) UDP (rápido, sin conexión)
Dirección de red (host a 0) Broadcast (host a 1) y puerta de enlace (un host, el router)
NAT (traduce) Cortafuegos (filtra) y NAC (controla el acceso a la red)
APIPA 169.254 (falla el DHCP) Link-local FE80:: (siempre presente en IPv6)
/23 (510 hosts, dos «/24» seguidas) /32 (un único equipo)
Ping (¿responde?, RTT) Traceroute (¿por dónde pasa?)

15. Posibles trampas de examen

  • Contar la red y el broadcast como hosts útiles.
  • Elegir .127 o .255 como broadcast de un /26 que empieza en .0.
  • Decir que ICMP usa un puerto.
  • Pensar que DNS solo usa UDP.
  • Creer que 172.32.x.x es privada (el rango acaba en 172.31).
  • Comprimir con :: dos veces en la misma dirección IPv6.
  • Creer que IPv6 tiene broadcast o usa ARP.
  • Pensar que NAT protege la red por sí mismo.
  • Deducir que un equipo está apagado porque no responde al ping.

18. Posibles preguntas cortas (con esquema de respuesta)

1. Diferencias entre TCP y UDP, con ejemplos.
Conexión (sí/no) · fiabilidad (ACK, retransmisión, orden / ninguna) · cabecera 20 frente a 8 B · latencia · ejemplos TCP: HTTPS, SMTP, SSH; UDP: DNS, DHCP, voz, SNMP · criterio: fiabilidad frente a tiempo real.

2. Explica cómo funciona ARP.
IP → MAC en la red local · request en broadcast, reply en unicast · caché ARP · destino en otra red → MAC de la puerta de enlace · ARP gratuito e IP duplicada · ARP spoofing y DAI · en IPv6, NDP.

Máscara 255.255.255.240 · salto 16 · red 192.168.16.16 · broadcast 192.168.16.31 · hosts .17 a .30 (14) · método: octeto interesante y múltiplos del salto.

Qué equipos van fijos y por qué · DORA y concesión · reserva · relay entre VLAN · opciones (puerta de enlace, DNS, opción 66 para teléfonos).

5. Principales diferencias entre IPv4 e IPv6.
32 frente a 128 bits y notación · sin broadcast (multicast) · NDP en lugar de ARP · SLAAC · cabecera fija de 40 B · fragmentación solo en origen · NAT innecesario · transición: doble pila, túneles, NAT64.

Traducción de direcciones por agotamiento de IPv4 · estático, dinámico, PAT, redirección de puertos · PAT distingue por puerto · NAT oculta pero no filtra: las reglas del cortafuegos (T14).

19. Casos prácticos

Mini caso 1 — PC con 169.254. Un PC recién instalado tiene 169.254.33.10 y no navega; los demás de la planta funcionan.
Esquema: APIPA = sin respuesta del DHCP · enlace y latiguillo · en el switch, puerto activo y en la VLAN correcta · relay de esa VLAN y direcciones libres en el ámbito · ipconfig /release y /renew · escalado al grupo de comunicaciones si hay que tocar el switch.

Mini caso 2 — Sale por IP pero no por nombre. Un usuario no abre ninguna web por nombre, pero ping 8.8.8.8 responde.
Esquema: la red y la salida funcionan · fallo de DNS · ipconfig /all para ver los servidores DNS · nslookup contra el DNS corporativo · si el DNS es correcto, revisar el servidor DNS (T10).

Mini caso 3 — No caben más equipos. Hay que añadir 6 tabletas a la subred de registro 192.168.16.16/28, que ya tiene 2 AP, 8 tabletas y la puerta de enlace.
Esquema: /28 = 14 hosts útiles · ocupados 11 · libres 3 → no caben 6 · ampliar a /27 (30 hosts) si el plan de direccionamiento lo permite, o crear otra subred · cambio coordinado con comunicaciones (T20).

Supuesto desarrollado — Plan de direcciones de un edificio municipal (supuesto). Un edificio va a tener cuatro VLAN: usuarios (90 puestos), telefonía (90 teléfonos), cámaras (12) y gestión de la electrónica de red (8 equipos). Se dispone del bloque privado 10.20.0.0/16 y la salida a Internet es por el cortafuegos municipal.

a) Diseño de subredes.
Usuarios y telefonía: /25 (126 hosts) o /24 si se prevé crecimiento · cámaras y gestión: /27 (30 hosts) o /28 (14) · ejemplo: usuarios 10.20.1.0/24, telefonía 10.20.2.0/24, cámaras 10.20.3.0/27, gestión 10.20.3.32/28 · justificar con 2ⁿ − 2 y dejar margen.

b) Asignación.
Usuarios y telefonía por DHCP con relay en cada VLAN; la de telefonía con la opción 66 para el aprovisionamiento de los teléfonos · cámaras y gestión con IP estática (o reservas) y documentadas · la puerta de enlace de cada VLAN, en el switch de capa 3 o en el cortafuegos (T4).

c) Salida a Internet.
Las direcciones son privadas: salida con PAT en el cortafuegos · ningún equipo interno expuesto salvo necesidad justificada (redirección de puerto o, mejor, VPN, T15) · reglas del cortafuegos por VLAN (T14).

d) Incidencia.
Tras la puesta en marcha, varios teléfonos muestran 169.254.x.x. Por la escalera: tienen enlace, pero no reciben DHCP → revisar que su puerto está en la VLAN de voz, que el relay de esa VLAN apunta al servidor y que el ámbito tiene direcciones libres. Se corrige, se verifica con ipconfig en un equipo de prueba y se registra la incidencia (T20).

21. Resumen final: si mañana fuera el examen

TCP/IP tiene cuatro capas y cada una encapsula a la superior: el puerto identifica la aplicación, la IP el equipo y la MAC la interfaz local. IP es sin conexión y best effort; el TTL evita bucles y hace posible el traceroute. ICMP (ping, traceroute) no usa puertos. ARP traduce IP a MAC con un request en broadcast; si el destino está fuera, pregunta por la puerta de enlace. TCP es fiable (SYN, SYN-ACK, ACK) y UDP rápido (DNS, DHCP, voz). Una IPv4 tiene 32 bits: con la máscara se calculan red, broadcast y hosts (2ⁿ − 2) usando el salto = 256 − máscara. Las privadas (10/8, 172.16/12, 192.168/16) salen con PAT; NAT no es seguridad. DHCP sigue DORA y necesita relay entre VLAN; 169.254 = sin DHCP. IPv6 tiene 128 bits, se abrevia con :: una vez, no tiene broadcast ni ARP (NDP) y se autoconfigura con SLAAC. Para diagnosticar: IP válida → puerta de enlace → IP externa → nombre.
