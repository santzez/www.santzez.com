Mapa del tema

T14 trata el cortafuegos y enseña a pensar en flujos: ¿quién inicia?, ¿desde qué IP y zona?, ¿hacia qué destino, protocolo y puerto?, ¿hay ruta?, ¿qué regla coincide?, ¿es stateful?, ¿hay NAT y qué traducción?, ¿existe estado?, ¿vuelve por el mismo camino?, ¿el servicio escucha?, ¿qué dicen los logs? Incluye los tipos (stateless, stateful, NGFW), las reglas y su orden, las zonas y la DMZ, el NAT desde el cortafuegos y el antispoofing. Cayó como pregunta corta en 2023 (explicar cinco reglas). Tres trampas centrales: stateful no es «solo TCP», NAT no es un cortafuegos y ALLOW no garantiza la conectividad.

Si la pregunta trata de… Está en Desde T14 solo…
TCP/IP, puertos, IP privadas, NAT básico T2 se aplica en el cortafuegos
Routing, VLAN, ACL, DHCP snooping, DAI T4 se usan para segmentar y para el antispoofing en la LAN
DNS y servicios publicados T10 se tienen en cuenta en el diagnóstico
Malware T13 se cita el filtrado de salida
VPN (túneles, IPsec, TLS) T15 aquí, solo la política del cortafuegos
IDS/IPS, filtrado web, antispam, inspección TLS T17 son funciones que puede integrar un NGFW
Gestión de cambios T20 cada regla nueva es un cambio

Cada apartado sigue tres niveles: concepto, explicación y aplicación práctica.

1. Qué es un cortafuegos

Concepto. Un cortafuegos (firewall: hardware, software, virtual o función de red) controla el tráfico entre redes, zonas, interfaces o sistemas según una política: permite, deniega, registra, inspecciona y, a menudo, traduce direcciones. No está solo entre la LAN e Internet: también entre usuarios y servidores, entre VLAN, entre la DMZ y la red interna, entre sedes y el CPD, o entre la nube y la red local.

Explicación.

  • De red (entre redes o zonas) y de host (en cada equipo: Windows Defender Firewall, nftables): coexisten.
  • Cortafuegos ≠ router: el router decide por dónde va el paquete; el cortafuegos decide si se permite. ≠ NAT (traduce). ≠ antivirus (protege el puesto, T13). ≠ IDS/IPS (detecta o bloquea actividad maliciosa, T17), aunque un NGFW pueda integrar IPS. ≠ proxy (intermedia a nivel de aplicación). Un mismo equipo puede hacer varias funciones, pero función ≠ dispositivo.

Anatomía de una regla y de un flujo:

  • Una regla combina origen + destino + servicio (protocolo y puerto) + zona o interfaz + acción + registro.
  • La 5-tupla (IP origen, IP destino, puerto origen, puerto destino, protocolo) identifica un flujo; los cortafuegos actuales pueden usar además usuario, aplicación o contenido.
  • Puerto origen ≠ puerto destino: el cliente usa un puerto efímero (alto, aleatorio); el servidor, el puerto del servicio (443). En la respuesta se invierten.

Aplicación práctica. En el caso de 2023, «el routing se hace en el cortafuegos y el switch principal» y «un cortafuegos gestiona la seguridad del tráfico entre VLAN»: el cortafuegos no solo protege el perímetro, también segmenta por dentro.

📌 Imprescindible — examen 2023, pregunta 33 (reserva)
Un cortafuegos de red se ocupa de prevenir y proteger a nuestra red privada de intrusiones o ataques de otras redes. Elegir la mejor ruta es del router; convertir nombres en IP, del DNS.
⚠️ TRAMPA DE EXAMEN
«Un cortafuegos solo puede instalarse entre Internet y una LAN» es falso.
🔀 No confundir — cortafuegos vs router vs NAT vs proxy · de red vs de host
Cortafuegos: filtra. Router: enruta (T4). NAT: traduce (T2). Proxy: intermedia. De red: entre zonas. De host: en el equipo.

2. Tipos de cortafuegos: stateless y stateful

Concepto. Los cortafuegos se diferencian por cuánta información usan para decidir: los campos de cada paquete, el estado de la conexión o el contenido y la aplicación.

Explicación.

Tipo Cómo decide Ventajas Inconvenientes
Sin estado (stateless, filtro de paquetes) Cada paquete por separado: IP, protocolo, puertos, interfaz, flags (como una ACL) Muy rápido, sencillo El tráfico de vuelta necesita reglas explícitas
Con estado (stateful) Mantiene una tabla de estados o sesiones y reconoce el tráfico de las conexiones autorizadas Reglas más simples y control del contexto Más recursos; tabla saturable (SYN flood)
Pasarela de aplicación (proxy) Intermediario que entiende el protocolo y rehace la conexión Inspección profunda Más lento; uno por protocolo
NGFW Stateful + identificación de aplicaciones y usuarios + IPS + filtrado web + antimalware + inspección TLS, según producto Política por aplicación y usuario Coste y complejidad
WAF Protege aplicaciones web (inyección SQL, XSS) Específico para web Solo HTTP/HTTPS
De host En cada equipo Protección dentro de la LAN Gestión distribuida

«Stateless = inseguro» y «stateful = seguro» son simplificaciones: la seguridad depende de la política. La evolución filtro de paquetes → stateful → NGFW no ha hecho desaparecer a los anteriores (las ACL siguen en switches y routers).

La tabla de estados:

  • Cada entrada anota direcciones, puertos, protocolo, estado, temporizador, NAT y zonas.
  • TCP: el cortafuegos sigue el saludo (SYN → SYN/ACK → ACK) y el cierre.
  • UDP no tiene conexión, pero el cortafuegos crea un pseudoestado de flujo con temporizador; ICMP también se sigue. «Stateful solo funciona con TCP» es falso.
  • Established / related: tráfico de una sesión existente o relacionado con ella (términos habituales, no idénticos en todos los fabricantes).
  • Temporizadores: las entradas caducan; las sesiones largas o el UDP pueden cortarse si el temporizador es corto (los valores dependen del producto).
  • ICMP: bloquearlo todo no mejora la seguridad: sirve para diagnóstico, avisos de error, descubrimiento de MTU (PMTUD) y es imprescindible en IPv6 (ICMPv6). La política se razona por tipos.

Aplicación práctica. Las ACL de switches y routers (T4) son filtrado sin estado: sirven para restricciones sencillas (por ejemplo, quién gestiona un switch), pero el perímetro y la segmentación entre zonas los protege un cortafuegos con estado o NGFW.

🧠 Para memorizar
Stateless = paquete (portero con lista). Stateful = sesión (portero con memoria: sabe quién ha salido y le deja volver).
⚠️ TRAMPA DE EXAMEN
El NGFW no se define simplemente como «cortafuegos de capa 7»: es un término de la industria que combina el filtrado con estado con aplicaciones, usuarios, IPS y otras funciones. «Un stateless no mira los puertos» es falso.
🔀 No confundir — stateless vs stateful · paquete vs sesión · ACL vs cortafuegos
Stateless: cada paquete. Stateful: el contexto de la conexión. Una ACL es una función de filtrado; un cortafuegos es el concepto completo.

3. Reglas y política

Concepto. Las reglas dicen qué tráfico se permite o deniega. En la mayoría de las plataformas se evalúan de arriba abajo y la primera que coincide decide (first match), aunque depende del producto.

Explicación.

Campo Ejemplo
Zona de origen y destino LAN → WAN
Origen 192.168.193.0/24 (usuarios)
Destino cualquiera
Servicio HTTPS (TCP 443)
Acción Permitir / denegar en silencio (drop) / rechazar con aviso (reject)
Opciones Registro, perfiles de seguridad (IPS, antivirus), horario, usuario

Principios:

  • Primera coincidencia: las reglas específicas van antes que las generales. Si la regla 1 es «denegar todo hacia el servidor» y la 2 «permitir HTTPS al servidor», la 2 nunca se alcanza.
  • Denegación por defecto (default deny): lo que no está expresamente permitido, se deniega. Es la buena práctica coherente con el mínimo privilegio; muchos productos la aplican de forma implícita al final, pero no todos vienen así de fábrica.
  • Allowlist (permitir solo lo necesario; «lista blanca») frente a denylist (permitir todo salvo lo prohibido): la primera da más control.
  • Mínimo privilegio: solo los orígenes, destinos y servicios necesarios. Una regla any-any-any-permitir es de alto riesgo y exige una justificación excepcional.
  • Filtrar también la salida (egress): limita lo que puede hacer un equipo infectado.
  • Objetos y grupos (SERVIDORES_WEB, RED_USUARIOS, SERVICIO_HTTPS) para que la política sea legible; los objetos por nombre (FQDN) dependen del DNS y su caché.
  • Documentar cada regla (motivo, propietario, fecha), revisar las obsoletas y poner caducidad a las temporales.
  • El contador de aciertos (hit count) ayuda a ver si una regla se usa; cero aciertos no prueba por sí solo que sobre, si el periodo observado es corto.

Aplicación práctica — pregunta corta 2 del examen de 2023:

  1. Regla 1: 172.16.44.39 puede consultar el DNS público de Google (8.8.8.8); probablemente es el servidor DNS de la organización que reenvía lo que no resuelve.
  2. Regla 2: cualquiera puede consultar el DNS de 172.16.44.39 (autoritativo de los dominios municipales o resolutor interno).
  3. Reglas 3 y 4: cualquiera accede al servidor web 172.16.44.23 por HTTP y HTTPS: servidor publicado, probablemente en una DMZ y con NAT desde una IP pública (172.16.x.x es privada).
  4. Regla 5: deniega todo lo demás.
  5. Orden: se evalúan secuencialmente; lo no permitido por las reglas 1–4 lo bloquea la 5 (ningún otro equipo puede consultar 8.8.8.8 ni navegar).
  6. Stateful: las respuestas se permiten automáticamente.
📌 Imprescindible — criterios del tribunal
Explicar cada regla (0,75), saber qué es 8.8.8.8 (0,5) y explicar que la secuencialidad es fundamental y la última regla deniega todo lo no permitido (0,75).
⚠️ TRAMPA DE EXAMEN
«Una regla any-any es coherente con el mínimo privilegio» es falso. Abrir «any-any para probar» no es un procedimiento: los cambios se justifican, aprueban, prueban, documentan y pueden revertirse (T20).
🔀 No confundir — drop vs reject · allowlist vs denylist
Drop: descarta en silencio. Reject: descarta y avisa (RST o ICMP). Allowlist: solo lo permitido. Denylist: todo salvo lo prohibido.

4. Zonas, DMZ y arquitecturas

Concepto. El cortafuegos agrupa las redes en zonas de seguridad con políticas parecidas; la DMZ es la zona separada para los servicios que reciben conexiones desde fuera sin exponer la red interna.

Explicación.

Zona Confianza Contenido
LAN interna (trust) Alta, no absoluta Usuarios, servidores internos
DMZ Media Servidores publicados (proxy inverso, web, pasarela de correo, DNS público)
Internet (untrust) Ninguna Exterior
Invitados Baja Wifi de Internet libre
Especiales Según el caso Cámaras, telegestión/OT (PLC), gestión de equipos, servidores
  • «Trusted» no significa «todo permitido»: la red interna también puede estar comprometida; se aplican mínimo privilegio y segmentación.
  • Segmentación: la VLAN (T4) separa; el cortafuegos aplica la política entre segmentos. Una VLAN sin política no es una zona de seguridad. Reduce la exposición, el movimiento lateral y el alcance de un incidente.
  • Microsegmentación: políticas más finas entre cargas o servicios (no es «crear muchas VLAN»). Norte-sur (lo que entra y sale) y este-oeste (tráfico lateral interno).
  • La DMZ no es una «red abierta»: cada flujo (Internet → DMZ, DMZ → LAN, LAN → DMZ) se controla. Si un servicio de la DMZ necesita hablar con la red interna, se permiten solo los flujos necesarios, nunca DMZ → LAN «cualquiera».
  • Tres patas (lo habitual), DMZ entre dos cortafuegos, varias zonas, virtualización o nube: ningún diseño es obligatorio.

Alta disponibilidad y routing asimétrico. Dos cortafuegos en clúster (activo-pasivo o activo-activo, según la plataforma) sincronizan las sesiones para que el otro nodo continúe las conexiones si uno falla. Dos cortafuegos no son alta disponibilidad automática: hay que revisar el resto de puntos únicos (switch, enlace, alimentación, operador, routing).

  • Rendimiento: los límites reales (caudal, conexiones por segundo, sesiones simultáneas) bajan al activar IPS, inspección TLS o VPN; la velocidad de las interfaces no es el caudal real.
  • Fail-closed (ante un fallo, bloquear) o fail-open (ante un fallo, dejar pasar): ninguno es siempre correcto; depende del riesgo y del servicio.

Aplicación práctica — el PLC del caso de 2023 (pregunta 4). El PLC está en una zona securizada (VLAN de telegestión). Para el mantenedor: VPN nominativa (T15) o NAT de puertos restringido a la IP de origen del mantenedor y al puerto concreto; en ambos casos, coordinación con Sistemas, que gestiona el cortafuegos. Nunca «abrir RDP desde Internet».

⚠️ TRAMPA DE EXAMEN
«Una DMZ es una red sin protección» y «una DMZ siempre requiere dos cortafuegos» son falsos.
🔀 No confundir — DMZ vs red de invitados · VLAN vs zona de seguridad · LAN vs zona de confianza absoluta
DMZ: servidores que reciben conexiones desde fuera. Invitados: usuarios que solo salen. VLAN: separación lógica; zona: separación con política.

5. NAT en el cortafuegos

Concepto. NAT (Network Address Translation) modifica direcciones IP (y, en algunos tipos, puertos) al atravesar el equipo. Se extendió para ahorrar direcciones IPv4, no como medida de seguridad: NAT traduce; el cortafuegos filtra. T2 introdujo el concepto; aquí se ve desde el cortafuegos.

Explicación.

Tipo Qué cambia Uso
SNAT (Source NAT) El origen, al salir Salida a Internet de las redes internas
PAT / NAT overload Origen + puertos: muchas privadas → una pública Lo habitual en la salida a Internet
Masquerade SNAT hacia la IP de la interfaz de salida (útil si es dinámica) Término de algunas plataformas, no sinónimo universal de PAT
DNAT (Destination NAT) El destino, al entrar Publicar un servicio
Redirección de puertos (port forwarding) DNAT de un puerto, que puede cambiar (pública:8443 → interna:443) Publicar un servicio concreto
NAT estático 1:1 Una pública ↔︎ una privada, estable Servidores con IP pública propia
NAT dinámico Un pool de públicas Concepto clásico; hoy menos habitual que PAT
Hairpin NAT (NAT loopback) Acceso desde dentro por la IP pública Que la URL pública funcione desde la LAN (ampliación)
  • Tabla NAT: asocia cada traducción (10.0.0.10:51500 ↔︎ 203.0.113.5:40001) para devolver la respuesta al equipo correcto.
  • IPv6 tiene direcciones de sobra y no necesita NAT44 para ahorrar direcciones (aunque existen mecanismos de traducción en casos concretos). IPv6 sigue necesitando cortafuegos, y la política debe cubrir IPv4 e IPv6: IPv6 puede estar activo aunque nadie lo use conscientemente.

Publicar un servicio:

  • Pre-NAT y post-NAT: al diagnosticar, saber si se está viendo la IP o el puerto antes o después de la traducción. El orden interno entre NAT y política depende del fabricante: no hay una secuencia universal.

Aplicación práctica. Publicar un servidor exige dos cosas: la traducción (DNAT o redirección) y la regla que permita ese tráfico, con origen restringido si es posible.

⚠️ TRAMPA DE EXAMEN
NAT no sustituye al cortafuegos: oculta direcciones, pero no aplica una política. «La redirección de puertos y la regla de cortafuegos son lo mismo» es falso. «IPv6 no necesita cortafuegos porque no usa NAT» también es falso.
🔀 No confundir — SNAT vs DNAT · PAT vs NAT 1:1 · NAT estático vs redirección de puertos · NAT vs routing, proxy o VPN
SNAT: origen, al salir. DNAT: destino, al entrar. PAT: muchas → una con puertos. 1:1: una ↔︎ una. NAT traduce; el routing elige el camino; el proxy intermedia; la VPN crea un túnel (T15).

6. Antispoofing

Concepto. El IP spoofing es falsificar la IP de origen de los paquetes para ocultarse, saltarse controles, suplantar a un equipo de confianza o lanzar ataques de reflexión. El antispoofing descarta los paquetes cuyo origen no es coherente con la interfaz, la zona o la ruta por la que llegan.

Explicación.

Medida Qué hace
Filtrado de entrada (ingress) Descartar desde Internet los orígenes que no pueden venir de ahí: privadas RFC 1918 (10/8, 172.16/12, 192.168/16), loopback, multicast, reservadas (bogons) y las propias
Filtrado de salida (egress, BCP 38 / RFC 2827) Solo salen paquetes con origen en nuestras redes: un origen imposible en la salida indica error, spoofing o un equipo comprometido
uRPF (Unicast Reverse Path Forwarding) Comprueba que la ruta hacia el origen es coherente: en modo estricto, que llega por la interfaz de la vuelta; en modo laxo, que existe una ruta
Interfaz–red en el cortafuegos Cada zona solo acepta como origen las redes que tiene detrás
En la LAN DHCP snooping, DAI e IP Source Guard en los switches (T4)
  • uRPF ayuda, pero no elimina todo el spoofing, y el modo estricto puede bloquear tráfico legítimo con rutas asimétricas.
  • El antispoofing no es solo de entrada y no se limita a las direcciones privadas.

Aplicación práctica. Un paquete que entra desde Internet con origen 10.x, 172.16–31.x, 192.168.x o con una IP de nuestra red es falso: el cortafuegos lo descarta y lo registra.

📌 Imprescindible
Desde fuera nunca pueden llegar orígenes privados ni propios, y desde dentro no deben salir orígenes ajenos.

Otros ataques que mitiga el cortafuegos: escaneo de puertos (IPS), SYN flood (agota la tabla de estados; defensa con SYN cookies y límites), DDoS (los volumétricos se mitigan con el operador o servicios anti-DDoS), paquetes malformados y fragmentación (el cortafuegos debe tratar bien los fragmentos para poder inspeccionar).

⚠️ TRAMPA DE EXAMEN
«El antispoofing solo se aplica al tráfico entrante» es falso. «uRPF puede verse afectado por el routing asimétrico» es verdadero.
🔀 No confundir — IP spoofing vs ARP spoofing vs DNS spoofing · ingress vs egress · antispoofing vs antimalware
IP: origen falso (T14). ARP: IP–MAC en la LAN (T4). DNS: resolución (T10). Ingress: lo que entra. Egress: lo que sale. El antispoofing no detecta virus.

7. Gestión, diagnóstico y situaciones profesionales

Concepto. El cortafuegos es un equipo crítico y un objetivo prioritario: su gestión exige control de cambios, actualizaciones y registro, y su diagnóstico, seguir el flujo paso a paso.

Explicación — gestión. Fabricantes habituales (sin depender de ninguno): Fortinet, Palo Alto Networks, Check Point, Cisco, Sophos, WatchGuard; de código abierto, pfSense, OPNsense y nftables. Buenas prácticas: administración solo desde la red de gestión y con MFA; copia de la configuración antes de cada cambio; gestión de cambios (T20); firmware al día; logs a un SIEM; revisión periódica de reglas.

  • Registro (log): fecha y hora, origen, destino, puertos, protocolo, acción, regla, zona o interfaz, NAT y sesión; algunas plataformas registran al inicio, al final (con bytes y duración) o ambos.
  • Log ≠ captura de paquetes: el log resume el evento; la captura (Wireshark, tcpdump) muestra los paquetes reales.
  • Ping que falla no significa equipo caído (ICMP puede estar bloqueado); ping que funciona no significa que el 443 funcione. Una prueba de puerto (Test-NetConnection, nc) dice si el puerto responde, no si la aplicación funciona.

9. Anclas de memoria

  • Cortafuegos filtra · router enruta · NAT traduce.
  • Stateless = paquete · stateful = sesión (tabla de estados; también UDP e ICMP) · NGFW = combina aplicación, usuario, IPS…
  • Reglas: primera coincidencia (habitual), específicas arriba, denegación por defecto al final.
  • DMZ = zona separada para lo publicado; cada flujo, controlado.
  • SNAT cambia el origen · DNAT cambia el destino · PAT = muchas → una con puertos · redirección ≠ regla.
  • NAT ≠ cortafuegos · IPv6 sin NAT44, pero con cortafuegos.
  • Antispoofing = origen coherente · ingress y egress (BCP 38) · uRPF con límites · DHCP snooping/DAI en la LAN.
  • Routing asimétrico rompe el stateful.
  • ALLOW ≠ conectividad garantizada · ping ≠ servicio.
  • 8.8.8.8 = DNS público de Google.

Afirmación V/F Por qué
Un cortafuegos solo puede instalarse entre Internet y una LAN F También entre VLAN, DMZ, sedes, nube, host
Un stateless analiza cada paquete sin el contexto de sesión de un stateful V —

15. Casos prácticos

Cada mini caso sigue el esquema síntoma → flujo → hipótesis → política → NAT → routing → estado → servicio → solución.

Mini caso 1 — Web publicada que no funciona. La web de la DMZ funciona desde dentro pero no desde Internet.
Esquema: DNS público e IP pública · DNAT · regla WAN → DMZ y su orden · logs y aciertos · ruta de retorno · servicio.

Mini caso 2 — Nueva VLAN sin Internet. Los equipos de una VLAN recién creada no salen a Internet.
Esquema: puerta de enlace (SVI) · routing hacia el cortafuegos · regla de salida · SNAT para esa red · DNS.

Mini caso 3 — DNAT correcto, regla incorrecta. La traducción existe, pero los logs muestran denegaciones.
Esquema: la política deniega · crear o corregir la regla WAN → DMZ con origen restringido · comprobar el orden.

Mini caso 4 — Regla correcta, DNAT incorrecto. La regla tiene aciertos, pero la conexión acaba en otro servidor.
Esquema: el DNAT apunta a una IP o puerto equivocados · corregir la traducción · verificar post-NAT.

Mini caso 5 — Stateful y asimetría. Tras un cambio de rutas, unas conexiones salen por un nodo y vuelven por otro.
Esquema: routing asimétrico · el segundo nodo no tiene la sesión · simetría o sincronización de estado.

Mini caso 6 — Tráfico falsificado por la WAN. Los registros muestran tráfico entrante con origen 10.0.0.0/8.
Esquema: spoofing · comprobar que el antispoofing descarta · registrar · si hay volumen, valorar con el operador.

Mini caso 7 — Regla sin aciertos. Se crea una regla y el contador sigue a cero.
Esquema: el tráfico no llega (ruta) · otra regla anterior coincide · zona, objeto o servicio equivocados.

Mini caso 8 — ALLOW con el servicio caído. La regla permite y tiene aciertos, pero el servidor no responde.
Esquema: el servicio no escucha · cortafuegos local del servidor · aplicación · no tocar el cortafuegos.

Mini caso 9 — Hairpin NAT. La web se ve desde fuera, pero no desde la LAN usando su nombre público.
Esquema: el nombre resuelve a la IP pública · hairpin NAT o DNS dividido · decidir y documentar.

Mini caso 10 — Proveedor externo. Un proveedor pide abrir RDP desde Internet a un servidor.
Esquema: no exponer RDP · VPN (T15) o, como mucho, DNAT restringido a su IP con MFA, horario y registro · mínimo privilegio · gestión de cambios.

Supuesto desarrollado 1 — Aplicación HTTPS en la DMZ que no funciona desde Internet (supuesto). Una aplicación municipal está en la DMZ. Desde la LAN funciona; desde Internet, no. Hay IP pública y el administrador asegura que «la regla está creada».

a) Comprobaciones por orden.\

  1. DNS público → 2) IP pública → 3) ruta y interfaz WAN → 4) DNAT → 5) puerto externo → 6) IP y puerto internos → 7) política WAN → DMZ → 8) orden de reglas → 9) logs y aciertos → 10) servidor → 11) cortafuegos local → 12) ruta de retorno → 13) captura.

b) Idea clave.
Regla ≠ NAT ≠ routing ≠ servicio: «la regla está creada» no basta; cada eslabón puede fallar por separado.

c) Cierre.
Corregir lo que falle · probar desde fuera · documentar el cambio (T20).

Supuesto desarrollado 2 — VLAN de cámaras con exceso de acceso (supuesto). Tras crear una VLAN para las cámaras municipales, estas llegan a Internet y a servidores internos que no necesitan.

a) Diagnóstico.
Exceso de privilegios: la VLAN existe, pero sin política de zona.

b) Política.
Definir la zona de cámaras · permitir solo lo necesario: grabador (NVR), DNS y NTP internos, actualizaciones del fabricante si se aprueban · SNAT solo si necesitan salir · denegar el acceso a la LAN de usuarios y al resto de servidores · registrar.

c) Verificación y documentación.
Probar los flujos permitidos y que los demás se bloquean · revisar logs · documentar y revisar periódicamente.

Supuesto desarrollado 3 — Asimetría tras cambiar la alta disponibilidad (supuesto). Tras modificar el routing de alta disponibilidad, algunas conexiones salen por un nodo del cortafuegos y las respuestas llegan por el otro, que las descarta.

a) Diagnóstico.
Routing asimétrico + inspección con estado: el nodo que recibe la vuelta no tiene la sesión.

b) Soluciones.
Revisar el routing para que sea simétrico · comprobar el modo del clúster (activo-pasivo o activo-activo) y la sincronización de estado · revisar la arquitectura · probar la conmutación y documentar.

17. Resumen final: si mañana fuera el examen

El cortafuegos aplica una política al tráfico entre redes, zonas o equipos (no solo entre la LAN e Internet): filtra, mientras el router enruta y el NAT traduce. Una regla combina origen, destino, servicio, zona, acción y registro; en la mayoría de plataformas se evalúan de arriba abajo (primera coincidencia), con las específicas arriba y una denegación por defecto al final. El stateless evalúa cada paquete (como una ACL); el stateful mantiene una tabla de estados (también para UDP e ICMP) y deja pasar las respuestas; el routing asimétrico lo rompe. El NGFW combina el estado con aplicación, usuario e IPS. Las zonas separan LAN, DMZ, Internet, invitados, gestión y OT; la DMZ aloja lo publicado y cada flujo se controla. El NAT se extendió para ahorrar IPv4, no es un cortafuegos: SNAT/PAT para salir, DNAT/redirección para publicar (siempre con su regla). IPv6 no necesita NAT44, pero sí cortafuegos. El antispoofing exige un origen coherente: ingress (privadas, bogons, propias), egress (BCP 38), uRPF (con límites) y, en la LAN, DHCP snooping y DAI. ALLOW no garantiza la conectividad y ping no prueba el servicio. 8.8.8.8 es el DNS público de Google.
