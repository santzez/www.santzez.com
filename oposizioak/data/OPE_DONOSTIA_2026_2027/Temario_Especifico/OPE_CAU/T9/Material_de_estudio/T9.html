1. Concepto y funciones de un sistema operativo

Un sistema operativo (SO) es el software de sistema que gestiona los recursos del ordenador y proporciona servicios a las aplicaciones, actuando de intermediario entre el hardware y los programas o las personas usuarias. Se carga al arrancar el equipo y permanece en ejecución mientras este funciona.

Clásicamente se explica su papel desde dos visiones complementarias:

  • SO como gestor de recursos: reparte de forma ordenada y eficiente los recursos limitados (tiempo de CPU, memoria, dispositivos) entre los programas que compiten por ellos, evitando conflictos.
  • SO como máquina virtual extendida (máquina abstracta): oculta la complejidad real del hardware, ofreciendo una interfaz más sencilla y uniforme («guardar un fichero» en lugar de manejar el controlador del disco).

Funciones

  • Gestión de procesos: crear, planificar y terminar procesos (apartados 5 y 6).
  • Gestión de memoria: asignar, proteger y liberar la memoria (apartado 4).
  • Gestión de la entrada/salida: intermediar con los dispositivos (apartado 7).
  • Sistema de archivos: organizar la información persistente (apartado 8).
  • Usuarios y seguridad: identificar usuarios y controlar el acceso a los recursos.
  • Interfaz de usuario: línea de comandos o interfaz gráfica para interactuar con el sistema.
💡 Analogía
El SO es como el personal de un hotel: los huéspedes (los programas) piden recursos (habitación, ascensor, comedor) y el personal organiza el acceso a lo compartido para que todos lo usen sin chocar, sin que el huésped necesite saber cómo funciona la caldera. Útil para entender; las definiciones formales son las de arriba.

2. Clasificación de los sistemas operativos

Se combinan varios criterios independientes — no deben mezclarse entre sí — y un mismo SO puede describirse con varias etiquetas a la vez:

Criterio Tipos Idea clave
Número de usuarios Monousuario / Multiusuario Cuántos usuarios puede atender simultáneamente
Número de tareas Monotarea / Multitarea Cuántos programas puede ejecutar «a la vez»
Número de procesadores Uniprocesador / Multiprocesador Cuántas CPU/núcleos es capaz de gestionar
Gestión del tiempo Por lotes / Tiempo compartido / Tiempo real Cómo organiza el tiempo de proceso
Ámbito de uso Escritorio / Servidor / Embebido / Móvil Para qué entorno está diseñado

Como ejemplo histórico útil: MS-DOS es un ejemplo clásico de sistema monousuario y monotarea. Los sistemas de escritorio y servidor actuales son multitarea y, en general, multiusuario y de tiempo compartido.

Tiempo compartido frente a tiempo real

  • Tiempo compartido (time-sharing): la CPU se reparte entre usuarios/procesos para proporcionar interacción y capacidad de respuesta; es el modelo habitual de escritorio y servidor.
  • Tiempo real (RTOS): lo esencial es el cumplimiento de restricciones temporales — que la tarea se complete antes de su plazo.
📌 Imprescindible para el examen
Tiempo real duro: incumplir el plazo puede implicar un fallo del sistema (control de un airbag, sistemas industriales críticos).
Tiempo real blando: el incumplimiento degrada el servicio, pero no lo invalida (reproducción de vídeo en streaming).

3. Arquitectura de un sistema operativo

El núcleo o kernel es la parte central del SO: el componente que se ejecuta con el máximo nivel de privilegio y accede directamente al hardware.

Modos de ejecución y llamadas al sistema

  • Modo usuario (user mode): privilegios restringidos — un programa no puede acceder directamente al hardware ni a la memoria de otros procesos.
  • Modo núcleo (kernel mode): privilegios elevados y acceso a los recursos protegidos del sistema.
  • Llamada al sistema (system call): el mecanismo mediante el que una aplicación solicita servicios al SO (leer un fichero, reservar memoria): provoca un cambio controlado a modo núcleo, el SO atiende la petición y se retorna a modo usuario con el resultado.

Matiz de precisión: no todo el software del SO se ejecuta en modo núcleo — muchas utilidades y servicios del propio sistema funcionan en modo usuario; el reparto exacto depende de la arquitectura.

Tipos de kernel

  • Monolítico: la mayor parte de los servicios (procesos, memoria, sistemas de archivos, drivers) se ejecutan en espacio de núcleo. Puede reducir la sobrecarga de comunicación entre servicios al mantenerlos juntos en el núcleo; a cambio, un fallo puede afectar a más componentes y el núcleo tiende a crecer.
  • Microkernel: el núcleo se reduce al mínimo (comunicación entre procesos, planificación básica) y el resto de servicios se ejecutan como procesos en modo usuario. Puede introducir sobrecostes de comunicación entre servicios, aunque proporciona mayor aislamiento y modularidad (un servicio que falla no arrastra necesariamente al sistema).
  • Híbrido: combina ambos enfoques, manteniendo en el núcleo los servicios críticos y externalizando otros.

Estas categorías describen diseños, no leyes universales de rendimiento: el resultado real depende de cada implementación.

🔍 Para ampliar — ejemplos (no núcleo del tema)
Linux → monolítico modular: admite cargar y descargar módulos (p. ej., drivers) sin recompilar; los módulos cargados se ejecutan en modo núcleo, así que no es un microkernel. Windows NT → generalmente clasificado como híbrido. XNU (macOS) → híbrido. El detalle de estos sistemas pertenece a los Temas 11-13.

4. Administración de memoria

El SO gestiona la memoria principal: decide la asignación (qué procesos residen en memoria y dónde), garantiza la protección (el espacio de cada proceso queda aislado del resto) y administra el espacio de direcciones de cada proceso.

Memoria virtual

La memoria virtual es una técnica de gestión que da a cada proceso un espacio de direcciones virtual propio y continuo, que el SO traduce a memoria física de forma transparente. Aporta aislamiento entre procesos y permite utilizar almacenamiento secundario como extensión cuando corresponde.

📌 Imprescindible para el examen
MEMORIA VIRTUAL ≠ RAM FÍSICA ADICIONAL. Es una abstracción/técnica de gestión: no añade memoria real, organiza y traduce la existente (y puede apoyarse en disco, mucho más lento).

Paginación y segmentación

  • Paginación: divide la memoria en bloques de tamaño fijo — páginas (en el espacio lógico del proceso) y marcos (en la memoria física); una tabla de páginas traduce unas a otros. Puede generar fragmentación interna (espacio sobrante dentro del bloque asignado).
  • Segmentación: divide la memoria en bloques lógicos de tamaño variable (código, datos, pila...), fieles a la estructura del programa. Puede generar fragmentación externa (huecos libres dispersos demasiado pequeños).
📌 Imprescindible para el examen
PÁGINA = FIJA → fragmentación interna posible · SEGMENTO = VARIABLE → fragmentación externa posible.
Y la formulación actual: la paginación es fundamental en la memoria virtual de muchos sistemas actuales; la segmentación clásica tiene hoy un papel más limitado que en los modelos tradicionales.

Swapping y thrashing

  • Swapping (intercambio): traslado temporal de información entre la RAM y el almacenamiento (zona de intercambio o swap) para liberar RAM. Según el esquema, lo que se mueve pueden ser páginas o procesos completos — no son términos equivalentes. Tiene un coste de rendimiento: el disco es mucho más lento que la RAM.
  • Thrashing (hiperpaginación): el sistema dedica una parte excesiva del tiempo a paginación/intercambio en lugar de a trabajo útil; el rendimiento se desploma.
💡 Caso CAU
Equipo con poca RAM, disco constantemente activo y respuesta lentísima: cuadro típico de thrashing. Las vías de mejora habituales son ampliar la RAM o reducir la carga simultánea (también puede influir el estado del propio sistema); no hay una única solución universal.

5. Procesos y subprocesos

Un proceso es una instancia de un programa en ejecución junto con los recursos que tiene asignados (memoria, archivos abiertos, tiempo de CPU...). El SO representa cada proceso mediante el PCB (Process Control Block): la estructura donde guarda su estado, su contador de programa, sus registros y demás información de gestión.

Estados de un proceso

  • Nuevo: en creación.
  • Listo (ready): preparado, esperando a que el planificador le asigne la CPU.
  • En ejecución (running): usando la CPU.
  • Bloqueado / en espera (waiting): no puede continuar; espera un evento externo.
  • Terminado: finalizado; el SO libera sus recursos.
📌 Imprescindible para el examen
La transición estrella: EJECUCIÓN → BLOQUEADO cuando el proceso espera una operación de E/S. (Y de bloqueado pasa a listo cuando el evento llega — no directamente a ejecución.)

Hilos (subprocesos, threads)

Un hilo es una unidad de ejecución dentro de un proceso. Los hilos de un mismo proceso comparten el espacio de memoria y los recursos del proceso, pero cada hilo mantiene información propia de ejecución, como su contador de programa y su pila.

Multithreading (multihebra): ejecución concurrente de varios hilos dentro de un mismo proceso — por ejemplo, un editor que corrige la ortografía mientras el usuario escribe.

Criterio Proceso Hilo
Papel Unidad de asignación de recursos Unidad de ejecución dentro del proceso
Memoria Espacio propio e independiente Compartida con los demás hilos del proceso
Coste de creación y cambio Alto Bajo
Aislamiento ante fallos Alto Bajo: un fallo puede afectar a todo el proceso

Deadlock y starvation

  • Interbloqueo (deadlock): procesos bloqueados esperando recursos de manera circular: A tiene la impresora y espera el escáner; B tiene el escáner y espera la impresora — ninguno avanzará. El SO puede prevenir, evitar o detectar y resolver (por ejemplo, abortando un proceso).
  • Inanición (starvation): un proceso espera indefinidamente porque otros obtienen los recursos o turnos de forma continuada — podría avanzar, pero nunca le llega la vez (típico con prioridades mal gestionadas).

6. Planificación y gestión multitarea

El planificador (scheduler) decide qué proceso o hilo listo recibe la CPU en cada momento. El cambio de contexto (context switch) guarda el estado de ejecución del saliente y restaura el del entrante; gracias a esa alternancia rápida, una única CPU da sensación de simultaneidad.

Multitarea cooperativa frente a expulsiva

  • Cooperativa: cada proceso cede voluntariamente la CPU; uno mal programado puede bloquear el sistema.
  • Expulsiva/apropiativa (preemptive): el SO puede interrumpir al proceso en ejecución. Es el modelo de los sistemas modernos.

Algoritmos clásicos de planificación

Algoritmo Criterio Observación
FCFS (First Come, First Served) Orden de llegada Sencillo; un proceso largo retrasa a los demás (efecto convoy)
SJF (Shortest Job First) Menor duración estimada primero Puede minimizar el tiempo medio de espera bajo las condiciones clásicas del algoritmo y con estimaciones apropiadas de duración
Round Robin Turnos rotatorios con quantum Reparto equitativo; el rendimiento depende del quantum
Por prioridades Prioridad del proceso Respuesta rápida a lo importante; riesgo de inanición de los de baja prioridad
📌 Imprescindible para el examen — el quantum
QUANTUM → intervalo de CPU asignado a un proceso antes de producirse la expulsión/cambio.
Demasiado corto → muchos cambios de contexto (sobrecoste).
Demasiado largo → comportamiento parecido a FCFS (pierde capacidad de respuesta).

7. Entrada/salida

El SO intermedia entre los procesos y los dispositivos mediante los drivers (controladores específicos de cada dispositivo) y utiliza buffers — zonas de memoria intermedia — para compensar la diferencia de velocidad entre la CPU y los periféricos.

Método Qué ocurre Intervención de la CPU
Polling (E/S programada) La CPU pregunta repetidamente al dispositivo si ha terminado Alta
Interrupciones El dispositivo avisa a la CPU cuando termina Menor: la CPU hace otras tareas mientras tanto
DMA (Direct Memory Access) Transferencia directa entre dispositivo y memoria mediante un controlador DMA Muy baja durante la transferencia (configura al inicio, interrupción al final)
📌 Imprescindible para el examen
El DMA reduce de forma significativa la intervención de la CPU en las transferencias de bloques: un controlador dedicado mueve los datos entre el dispositivo y la memoria, y la CPU solo configura la operación y recibe la interrupción final. Formúlalo así — no como «el método más eficiente en cualquier circunstancia».

8. Sistemas de archivo

El sistema de archivos (file system) es el componente del SO responsable de la organización persistente de la información sobre el almacenamiento: cómo se nombran, almacenan, localizan y protegen los ficheros y directorios.

  • Organiza los ficheros en una jerarquía en árbol a partir de un directorio raíz.
  • Mantiene los metadatos de cada fichero: tamaño, fechas, propietario, permisos.
⚠️ No confundir
Tema 4 → la estructura lógica de la información dentro del fichero (registros, claves, métodos de acceso).
Tema 9 → la función del sistema de archivos del SO para gestionar ficheros y directorios sobre el almacenamiento.
Como ejemplos de sistemas de archivos pueden citarse NTFS (Windows), ext4 (Linux) o APFS (macOS); su desarrollo, y el de los permisos y ACL, corresponde a los temas de cada sistema concreto.

9. Datos y anclas de memoria

  • SO = GESTIONA RECURSOS + CREA UNA ABSTRACCIÓN (gestor de recursos · máquina virtual extendida).
  • USER = LIMITADO · KERNEL = PRIVILEGIADO · SYSTEM CALL = pedir servicios al SO (cambio controlado de modo).
  • Kernels: monolítico (junto en el núcleo) · microkernel (mínimo + servicios en modo usuario) · híbrido — diseños, no leyes de rendimiento.
  • Memoria virtual = abstracción, NO RAM extra.
  • PÁGINA = FIJA (fragmentación interna) · SEGMENTO = VARIABLE (fragmentación externa).
  • Swapping = RAM ↔ disco (coste) · Thrashing = paginar más que trabajar.
  • PROCESO = RECURSOS (PCB) · HILO = EJECUCIÓN (comparte memoria; pila y contador propios).
  • Estados: nuevo → listo → ejecución → bloqueado/terminado; E/S ⇒ ejecución → bloqueado.
  • DEADLOCK = ESPERA CIRCULAR · STARVATION = NO LE LLEGA EL TURNO.
  • Multitarea: cooperativa (cede) · expulsiva (el SO interrumpe — la moderna).
  • Algoritmos: FCFS (llegada) · SJF (más corto) · ROUND ROBIN = QUANTUM · prioridades (riesgo de inanición).
  • POLLING = PREGUNTA · INTERRUPCIÓN = AVISA · DMA = TRANSFIERE (controlador dedicado).
  • Sistema de archivos = ficheros + directorios + jerarquía + metadatos.

11. Posibles trampas de examen

  • «El tiempo real consiste en repartir la CPU equitativamente» — falso: eso es tiempo compartido; el tiempo real va de cumplir plazos.
  • «La memoria virtual añade RAM al equipo» — falso: es una abstracción de gestión; puede apoyarse en disco, mucho más lento.
  • «Proceso e hilo son sinónimos» — falso: el proceso es la unidad de recursos; el hilo, la de ejecución, y comparte la memoria del proceso.
  • «Multitarea y multithreading son lo mismo» — falso: procesos alternándose vs. hilos dentro de un proceso.
  • «La paginación usa bloques variables» — invertido: la paginación es de bloques fijos; la segmentación, variables.
  • «La fragmentación interna es típica de la segmentación» — invertido: interna → paginación; externa → segmentación.
  • «En un deadlock, los procesos avanzan lentamente» — falso: no avanzan en absoluto (espera circular); avanzar «cuando le toque» es la inanición.
  • «Las aplicaciones acceden directamente al hardware en modo usuario» — falso: necesitan una system call que cambie a modo núcleo.
  • «En el polling, el dispositivo avisa a la CPU» — invertido: en polling pregunta la CPU; el aviso es la interrupción.
  • «Con DMA, la CPU realiza la transferencia de datos» — falso: la realiza el controlador DMA; la CPU configura y recibe la interrupción final.
  • «Fichero y sistema de archivos son lo mismo» — falso: el fichero es la unidad; el sistema de archivos, el componente del SO que gestiona el conjunto.
  • «Linux es un microkernel porque es modular» — falso: es monolítico modular; sus módulos se ejecutan en modo núcleo.
  • «El monolítico es siempre más rápido y el microkernel siempre más lento» — matiz: son compromisos de diseño, no leyes universales.

14. Supuestos prácticos

Supuesto 1 — El equipo lentísimo con el disco al 100 %

Escenario: un usuario reporta que su equipo «va a pedales»; observas poca RAM libre y el disco trabajando sin descanso.

  • a) ¿Qué fenómeno encaja? Thrashing: el sistema pasa más tiempo paginando (RAM ↔ swap) que ejecutando trabajo útil.
  • b) ¿Por qué el disco «no para»? El swapping traslada continuamente páginas entre RAM y almacenamiento, mucho más lento que la RAM.
  • c) ¿Vías de mejora? Ampliar RAM o reducir la carga simultánea (cerrar aplicaciones, revisar procesos), valorando el estado del sistema — no hay una única solución universal.

Supuesto 2 — La aplicación «congelada» que espera al disco

Escenario: una aplicación deja de responder unos segundos mientras guarda un archivo muy grande.

  • a) ¿En qué estado está su proceso (o hilo) mientras tanto? Bloqueado/en espera: aguarda el resultado de la operación de E/S.
  • b) ¿Qué transición se ha producido y cuál vendrá? Ejecución → bloqueado; al completarse la E/S, bloqueado → listo (y el planificador le devolverá la CPU).
  • c) ¿Cómo evitaría el programa «congelarse»? Con multithreading: un hilo atiende la interfaz mientras otro realiza la escritura.

Supuesto 3 — Dos procesos que se esperan mutuamente

Escenario: el proceso A retiene la impresora y solicita el escáner; el proceso B retiene el escáner y solicita la impresora. Ninguno avanza.

  • a) ¿Qué situación es? Interbloqueo (deadlock): espera circular de recursos.
  • b) ¿Es lo mismo que si un proceso de baja prioridad nunca recibe la CPU? No: eso sería inanición (starvation) — podría avanzar, pero no le llega el turno.
  • c) ¿Qué puede hacer el SO? Prevenir, evitar, o detectar y resolver (por ejemplo, abortando uno de los procesos implicados).

Supuesto 4 — Transferencia masiva sin ahogar la CPU

Escenario: hay que volcar grandes bloques de datos desde un dispositivo de captura a memoria sin degradar el resto del sistema.

  • a) ¿Qué mecanismo de E/S conviene? DMA: un controlador dedicado transfiere directamente entre dispositivo y memoria.
  • b) ¿Qué papel juega la CPU? Configura la operación al inicio y atiende la interrupción final — interviene mínimamente durante la transferencia.
  • c) ¿Por qué no polling? Mantendría a la CPU preguntando continuamente, con alta ocupación improductiva.

Supuesto 5 — Repartir la CPU con justicia

Escenario: en un sistema interactivo, varios procesos de importancia similar deben compartir la CPU sin que ninguno monopolice.

  • a) ¿Qué algoritmo encaja? Round Robin: turnos rotatorios con quantum.
  • b) ¿Qué pasa si el quantum es muy corto? ¿Y muy largo? Corto → demasiados cambios de contexto (sobrecoste); largo → comportamiento casi FCFS, peor respuesta interactiva.
  • c) ¿Qué riesgo tendría planificar solo por prioridades? Inanición de los procesos de baja prioridad.

Supuesto 6 — El programa que necesita un servicio privilegiado

Escenario: una aplicación de usuario necesita leer un fichero del disco.

  • a) ¿Puede acceder directamente al hardware del disco? No: en modo usuario los privilegios están restringidos.
  • b) ¿Qué mecanismo utiliza? Una llamada al sistema (system call): cambio controlado a modo núcleo, el SO atiende la petición (vía sistema de archivos y driver) y retorna el resultado.
  • c) ¿Qué gana el sistema con esta separación? Protección y estabilidad: las aplicaciones no pueden corromper el hardware ni la memoria de otros procesos.

16. Resumen final: si mañana fuera el examen

  • SO = gestor de recursos + máquina virtual extendida; funciones: procesos, memoria, E/S, archivos, seguridad, interfaz.
  • Clasificación por criterios independientes: usuarios, tareas, procesadores, tiempo (lotes/compartido/real — duro vs. blando), ámbito. MS-DOS = ejemplo histórico mono/mono.
  • Arquitectura: kernel privilegiado; user mode restringido; system call como puente. Kernels monolítico/microkernel/híbrido — compromisos de diseño, sin absolutismos (Linux = monolítico modular; NT y XNU = híbridos, como ejemplos).
  • Memoria: memoria virtual = abstracción (≠ RAM extra); página fija → frag. interna · segmento variable → frag. externa; la paginación es central hoy, la segmentación clásica tiene papel limitado. Swapping con coste; thrashing cuando la paginación domina.
  • Procesos: instancia + recursos, con PCB; estados nuevo/listo/ejecución/bloqueado/terminado; E/S ⇒ ejecución → bloqueado. Hilo = unidad de ejecución dentro del proceso (memoria compartida; pila y contador propios); multithreading.
  • Deadlock (espera circular) ≠ starvation (nunca le toca).
  • Planificación: scheduler + cambio de contexto; cooperativa vs. expulsiva (moderna); FCFS · SJF (condicionado a estimaciones) · Round Robin con quantum · prioridades (riesgo de inanición).
  • E/S: drivers y buffers; polling (pregunta) → interrupciones (avisa) → DMA (controlador transfiere, CPU casi liberada).
  • Sistema de archivos: ficheros, directorios, jerarquía, metadatos; los concretos (NTFS, ext4...) en los Temas 11-13; la organización interna del fichero, en el Tema 4.
