1. Windows Server: características y ediciones

Un sistema operativo de servidor está optimizado para prestar servicios, atender múltiples conexiones simultáneas y administrar recursos compartidos, con vocación de funcionamiento continuo. Se diferencia del sistema operativo cliente (Tema 11), pensado para el trabajo individual en un puesto: cambian el propósito, el modelo de licenciamiento, las funciones disponibles y las herramientas de administración.

Server Core y Desktop Experience

Server Core Desktop Experience
Interfaz Instalación mínima, sin escritorio gráfico completo Entorno gráfico completo
Administración Consola local, PowerShell o administración remota Consolas gráficas locales, además de remota y PowerShell
Ventajas Menor superficie de ataque, menos componentes instalados y menor mantenimiento asociado a la interfaz gráfica Mayor comodidad para tareas puntuales y herramientas que exigen GUI

Server Core reduce componentes y mantenimiento asociado a la interfaz, pero no elimina automáticamente todos los reinicios ni los problemas de mantenimiento: el servidor sigue necesitando actualizaciones y ventanas de servicio.

Ediciones Standard y Datacenter

Edición Orientación Derechos de virtualización (por licencia)
Standard Entornos con virtualización limitada Derecho a ejecutar 2 OSE/VM virtuales por licencia
Datacenter Entornos altamente virtualizados y funciones avanzadas OSE/VM virtuales ilimitadas por licencia
⚠️ No confundir
Las «2 VM» de Standard son un derecho por licencia, no un límite absoluto del servidor: pueden asignarse licencias adicionales conforme al modelo de licenciamiento para ejecutar más máquinas virtuales. El detalle del licenciamiento no es objeto de este tema.

2. Instalación, roles y características

La instalación admite los mismos métodos vistos para el cliente en el Tema 11 —medios físicos, instalación por red, imágenes con Sysprep y DISM—, eligiendo además entre Server Core o Desktop Experience. La diferencia esencial llega después:

📌 Imprescindible para el examen
Tras instalar Windows Server, el sistema base se especializa mediante roles y características. Un servidor «recién instalado» no hace nada en particular hasta que se le añade el rol correspondiente.
Rol Característica
Qué es Función principal que presta el servidor a la red Componente de soporte que amplía o complementa funcionalidades
Ejemplos AD DS · DNS · DHCP · IIS · Hyper-V · RDS Herramientas de copia de seguridad · Failover Clustering · RSAT
Idea clave Define qué servicio ofrece el servidor Da apoyo al sistema o a otros roles

Administración

  • Server Manager (Administrador del servidor): administración de roles, características y servidores, incluida la gestión de varios servidores desde un único punto.
  • PowerShell: administración y automatización, especialmente útil en Server Core y en tareas repetitivas.
  • Ambas vías admiten administración remota del servidor.

3. Mantenimiento: actualizaciones y monitorización

Actualizaciones

  • Microsoft publica actualizaciones mensuales; el Patch Tuesday (segundo martes) es la referencia habitual del ciclo, aunque no toda actualización sigue ese calendario (existen publicaciones fuera de ciclo).
  • Buena práctica en servidores: probar previamente en un entorno de preproducción, aplicar en una ventana de mantenimiento planificada y disponer de copia de seguridad o snapshot previo cuando proceda, para poder revertir.

WSUS

WSUS (Windows Server Update Services) es el rol de Windows Server que permite gestionar centralizadamente las actualizaciones de los equipos de la organización: se descargan una vez, se aprueban y se distribuyen de forma controlada.

📌 Imprescindible para el examen — el estado de WSUS
WSUS está deprecated (deprecado): no recibirá nuevas funcionalidades. Pero sigue soportado para despliegues en producción y continúa recibiendo actualizaciones de seguridad y calidad conforme a su ciclo de vida. «Deprecated» no significa «fuera de servicio», ni implica que haya sido simplemente sustituido por otra herramienta. (Como ampliación, existen alternativas modernas de gestión en la nube.)

Monitorización

  • Monitor de rendimiento (Performance Monitor): contadores de rendimiento en tiempo real e histórico — prioridad alta.
  • Monitor de recursos (Resource Monitor): uso detallado de CPU, memoria, disco y red por proceso — prioridad alta.
  • Visor de eventos: registros de sistema, seguridad y aplicaciones (su manejo detallado, en el Tema 15) — prioridad alta.
  • Administrador de tareas: vista rápida del consumo de recursos y procesos.
  • Windows Admin Center: consola moderna basada en navegador para administrar varios servidores, incluido Server Core — prioridad media.
  • SCOM (System Center Operations Manager): solución de monitorización a gran escala con alertado proactivo, propia de entornos con muchos servidores — prioridad media, sin desarrollo.

4. Fundamentos de Directorio Activo (AD DS)

📌 Imprescindible para el examen — definición precisa
AD DS (Active Directory Domain Services) es un servicio de directorio basado en una base de datos distribuida y jerárquica que almacena y administra información sobre los objetos de la red (usuarios, equipos, grupos, impresoras...). Es el servicio de Windows Server que implementa el Directorio Activo clásico/on-premise.
Evita describirlo como «una base de datos centralizada» sin más: la información se replica entre varios controladores de dominio, de modo que es distribuida y replicada, aunque la administración sea centralizada.

Para qué sirve

  • Autenticación: verificar la identidad de usuarios y equipos del dominio.
  • Autorización: determinar a qué recursos puede acceder cada identidad.
  • Organización de objetos: estructurar usuarios, equipos y grupos de forma jerárquica.
  • Gestión centralizada: aplicar configuraciones y políticas de forma homogénea en lugar de equipo por equipo.

Protocolos: LDAP y Kerberos

  • LDAP (Lightweight Directory Access Protocol): protocolo de acceso, consulta y modificación del directorio.
  • Kerberos: protocolo de autenticación en el dominio.
🧠 Para memorizar
LDAP → DIRECTORIO · KERBEROS → AUTENTICACIÓN.

AD DS y DNS

📌 Imprescindible para el examen
AD DS depende de DNS: los equipos localizan los controladores de dominio y los servicios relacionados mediante consultas DNS. Sin un DNS correctamente configurado, el dominio no funciona (inicios de sesión, aplicación de directivas, replicación). Por eso es habitual que los propios controladores de dominio actúen también como servidores DNS. AD DS + DNS van estrechamente ligados (el detalle de DNS, en el bloque de redes).
🔍 Para ampliar — AD DS y Microsoft Entra ID
AD DS → servicio de directorio clásico/on-premise, basado en dominios, árboles y bosques.
Microsoft Entra ID → servicio de identidad en la nube, orientado a aplicaciones y servicios en línea, que no organiza los objetos en esa estructura.
Pueden coexistir en escenarios híbridos. Este tema trata los fundamentos de AD DS, no la administración de Entra ID.

5. Estructura lógica y física del Directorio Activo

Estructura lógica

  • Dominio: unidad lógica de administración y seguridad; agrupa objetos que comparten directorio y políticas.
  • Árbol: conjunto de dominios con espacio de nombres DNS contiguo (por ejemplo, organizacion.local y sedes.organizacion.local).
  • Bosque: conjunto de uno o más árboles que comparten elementos estructurales del directorio (esquema y catálogo global comunes). Es el límite de seguridad del despliegue.
  • OU (unidad organizativa): contenedor administrativo dentro de un dominio para organizar objetos y aplicar GPO de forma selectiva. No es un dominio: no tiene directorio propio ni es límite de seguridad.
  • Trust (relación de confianza): vínculo que permite el acceso a recursos entre dominios o bosques distintos.
🧠 Para memorizar — la gran ancla del tema
DOMINIO → ÁRBOL → BOSQUE (de menor a mayor).
OU → organiza y permite aplicar GPO · BOSQUE → límite de seguridad.
Una OU no es un dominio.

Estructura física

  • Sitio (site): agrupación de una o varias subredes bien conectadas, habitualmente correspondiente a una ubicación física. Finalidad: optimizar la replicación entre controladores y favorecer el uso del DC adecuado o más cercano por parte de los clientes.
  • Controlador de dominio (DC): servidor que aloja una réplica de la información de AD DS y presta los servicios de autenticación y directorio.
⚠️ No confundir — dominio vs. sitio
DOMINIO → concepto lógico: administración y seguridad.
SITIO → concepto físico/topológico: subredes y conectividad.
Un dominio puede abarcar varios sitios (varias sedes), y un mismo sitio puede alojar controladores de más de un dominio del bosque.

6. Controladores de dominio, catálogo global, esquema y FSMO

Replicación multimaestro

Un dominio suele contar con varios controladores de dominio que se replican entre sí. La mayoría de las operaciones de AD DS se gestionan de forma multimaestro: un cambio puede realizarse en un DC y replicarse a los demás. Solo determinados cambios están reservados a los roles FSMO.

Catálogo global y esquema

  • Catálogo global (Global Catalog, GC): réplica parcial de los objetos del bosque, disponible en determinados controladores de dominio. Finalidad: acelerar las búsquedas a escala de bosque.
  • Esquema (schema): define las clases de objetos y los atributos que pueden existir en AD DS. Es común a todo el bosque.
⚠️ No confundir — GC vs. esquema
GC → BÚSQUEDA: qué objetos hay (réplica parcial para localizarlos rápido en todo el bosque).
ESQUEMA → CLASES + ATRIBUTOS: qué tipos de objeto pueden existir y qué características tienen.
Uno guarda contenido resumido; el otro define la estructura.

GPO (concepto)

Una GPO (directiva de grupo) es un conjunto de configuraciones que puede vincularse a un sitio, a un dominio o a una OU, y se aplica a los usuarios y equipos incluidos en su ámbito. (El detalle de usuarios y grupos corresponde al Tema 14.)

Los cinco roles FSMO

Aunque AD DS es multimaestro para la mayoría de operaciones, existen cinco roles con responsabilidades únicas —FSMO (Flexible Single Master Operations)—, que residen en un solo controlador de dominio a la vez: dos de bosque y tres de dominio.

Rol Ámbito Idea clave
Schema Master Bosque Modifica el esquema
Domain Naming Master Bosque Añade y elimina dominios del bosque
RID Master Dominio Asigna bloques de RID (identificadores para crear objetos)
PDC Emulator Dominio Tiempo, contraseñas y compatibilidad
Infrastructure Master Dominio Referencias entre dominios
🧠 Para memorizar — el ancla FSMO
2 BOSQUE + 3 DOMINIO = 5 FSMO.
Bosque: Schema (estructura) y Naming (dominios).
Dominio: RID (identificadores), PDC (tiempo/contraseñas), Infrastructure (referencias).
🔍 Para ampliar — LAPS
LAPS (Local Administrator Password Solution) permite administrar y rotar de forma controlada las contraseñas de los administradores locales de los equipos del dominio, evitando contraseñas idénticas y estáticas en todo el parque. Contenido de ampliación.

7. Datos y anclas de memoria

  • SERVER CORE → MENOS INTERFAZ (menor superficie de ataque; administración por PowerShell/remota).
  • ROL → SERVICIO (AD DS, DNS, DHCP, IIS, Hyper-V, RDS) · CARACTERÍSTICA → APOYO (Backup, Failover Clustering, RSAT).
  • Standard → 2 OSE/VM por licencia · Datacenter → ilimitadas (derecho por licencia, no límite del servidor).
  • LDAP → DIRECTORIO · KERBEROS → AUTENTICACIÓN.
  • DOMINIO → ÁRBOL → BOSQUE; OU → ORGANIZA/GPO; BOSQUE → límite de seguridad.
  • SITE → RED/UBICACIÓN (subredes bien conectadas); dominio = lógico, sitio = físico.
  • DC = réplica de AD DS + autenticación y directorio; AD DS es multimaestro salvo FSMO.
  • GC → BÚSQUEDA (réplica parcial del bosque) · SCHEMA → CLASES + ATRIBUTOS (común al bosque).
  • FSMO → 2 BOSQUE + 3 DOMINIO: Schema → estructura · Naming → dominios · RID → identificadores · PDC → tiempo/contraseñas · Infrastructure → referencias.
  • AD DS depende de DNS para localizar los controladores de dominio.
  • WSUS = rol de gestión centralizada de actualizaciones; deprecated pero soportado.
  • Monitorización: Performance Monitor · Resource Monitor · Visor de eventos (alta) · Windows Admin Center · SCOM (media).

9. Posibles trampas de examen

  • «AD DS es una base de datos centralizada» — impreciso: es un servicio de directorio basado en información distribuida y replicada entre controladores de dominio.
  • «Dominio y sitio son sinónimos» — falso: lógico/administrativo vs. físico/topológico.
  • «Una OU es un tipo de dominio» — falso: es un contenedor dentro del dominio para organizar y aplicar GPO.
  • «Árbol y bosque son lo mismo» — falso: el árbol comparte espacio de nombres contiguo; el bosque agrupa árboles y es el límite de seguridad.
  • «El catálogo global define las clases de objetos» — falso: eso es el esquema; el GC es una réplica parcial para búsquedas.
  • «LDAP autentica a los usuarios del dominio» — impreciso: LDAP es el protocolo de directorio; la autenticación en el dominio es de Kerberos.
  • «Failover Clustering es un rol» — falso: es una característica; los roles son AD DS, DNS, DHCP, IIS...
  • «Standard no permite más de 2 máquinas virtuales» — impreciso: son 2 OSE/VM por licencia; pueden asignarse licencias adicionales.
  • «WSUS está obsoleto y ya no funciona» — falso: deprecated, pero soportado y operativo en producción.
  • «Los roles FSMO son cuatro / seis» — son cinco: 2 de bosque + 3 de dominio.
  • «Schema Master añade dominios al bosque» — falso: eso es el Domain Naming Master.
  • «El RID Master sincroniza la hora del dominio» — falso: la referencia horaria y los cambios de contraseña con prioridad son del PDC Emulator.
  • «AD DS puede funcionar sin DNS» — falso: depende de DNS para localizar los controladores de dominio y los servicios asociados.
  • «Server Core elimina los reinicios y el mantenimiento» — falso: reduce componentes y superficie de ataque, no elimina el mantenimiento.

11. Posibles preguntas cortas (con esquema de respuesta)

1. Diferencie Server Core y Desktop Experience

  • Definición de cada modalidad de instalación.
  • Ventajas de Server Core: menor superficie de ataque, menos componentes, menor mantenimiento de la interfaz; administración por consola/PowerShell o remota.
  • Matiz: no elimina reinicios ni mantenimiento.

2. Diferencie roles y características

  • Rol: función principal que presta el servidor (ejemplos).
  • Característica: componente de apoyo (ejemplos).
  • Cierre: se añaden desde Server Manager o PowerShell; el servidor «se especializa» tras la instalación.

3. Explique qué es AD DS

  • Definición precisa (servicio de directorio, base distribuida y jerárquica de objetos de red).
  • Funciones: autenticación, autorización, organización de objetos, gestión centralizada.
  • Protocolos: LDAP (directorio) y Kerberos (autenticación); dependencia de DNS.

4. Explique dominio, árbol y bosque

  • Dominio: unidad lógica de administración y seguridad.
  • Árbol: dominios con espacio de nombres DNS contiguo.
  • Bosque: uno o más árboles con estructura común (esquema, GC); límite de seguridad.
  • Cierre: papel de las relaciones de confianza.

5. Diferencie dominio y sitio

  • Dominio: lógico (administración, seguridad).
  • Sitio: físico (subredes bien conectadas); finalidad de replicación y localización del DC adecuado.
  • Cierre: un dominio puede abarcar varios sitios y viceversa.

6. Explique el papel de un controlador de dominio

  • Aloja una réplica de AD DS; presta autenticación y servicios de directorio.
  • Varios DC por dominio; replicación multimaestro para la mayoría de operaciones.
  • Cierre: algunos alojan el catálogo global y/o roles FSMO.

7. Explique el catálogo global y el esquema

  • GC: réplica parcial de los objetos del bosque en determinados DC; acelera búsquedas de bosque.
  • Esquema: define clases de objetos y atributos; común al bosque; su modificación corresponde al Schema Master.
  • Cierre: no confundir contenido (GC) con definición estructural (esquema).

8. Explique LDAP y Kerberos

  • LDAP: acceso, consulta y modificación del directorio.
  • Kerberos: autenticación de usuarios y equipos del dominio.
  • Cierre: ambos son estándares en los que se apoya AD DS.

9. Enumere y explique los cinco roles FSMO

  • Punto de partida: AD DS es multimaestro salvo estas cinco operaciones.
  • Bosque: Schema Master (esquema) y Domain Naming Master (añadir/eliminar dominios).
  • Dominio: RID Master (bloques de RID), PDC Emulator (tiempo, contraseñas, compatibilidad) e Infrastructure Master (referencias entre dominios).
  • Cierre: reparto 2 + 3 = 5.

12. Supuestos prácticos

Supuesto 1 — Varias sedes con enlaces desiguales

Escenario: un ayuntamiento tiene la sede central y cuatro sedes de barrio, algunas con enlaces lentos. Los usuarios de las sedes se quejan de inicios de sesión lentos.

  • a) ¿Qué elemento de AD DS interviene? Los sitios: agrupan subredes bien conectadas y permiten que los clientes se autentiquen contra el DC más adecuado/cercano en lugar de contra uno remoto.
  • b) ¿Qué otra ventaja aportan? Optimizan el tráfico de replicación entre controladores de dominio a través de los enlaces.
  • c) ¿Implica esto crear un dominio por sede? No: el dominio es lógico y puede abarcar varios sitios; multiplicar dominios no resuelve un problema de topología física.

Supuesto 2 — Configuraciones distintas por departamento

Escenario: se quiere aplicar una configuración concreta a los equipos de Recaudación y otra distinta a los de Biblioteca.

  • a) ¿Cómo se organiza? Creando OU por departamento y colocando en ellas los objetos correspondientes.
  • b) ¿Cómo se aplican las configuraciones? Vinculando una GPO a cada OU; la directiva se aplica a los usuarios y equipos de su ámbito.
  • c) ¿A qué otros elementos puede vincularse una GPO? A un sitio y a un dominio, además de a OU. (El detalle de usuarios y grupos, en el Tema 14.)

Supuesto 3 — Añadir un dominio nuevo al bosque

Escenario: por motivos organizativos se va a incorporar un nuevo dominio al bosque existente.

  • a) ¿Qué rol FSMO es imprescindible? El Domain Naming Master, único que controla la adición y eliminación de dominios; es rol de bosque.
  • b) ¿Y si en vez de añadir un dominio hubiera que modificar clases o atributos del directorio? Sería el Schema Master, el otro rol de bosque.
  • c) ¿Podría hacerse desde cualquier DC? No: son operaciones reservadas a un único titular del rol, aunque el resto de cambios sí sea multimaestro.

Supuesto 4 — Problemas al crear objetos nuevos

Escenario: en un dominio empiezan a fallar las altas de usuarios y equipos con errores relacionados con la asignación de identificadores.

  • a) ¿Qué rol conviene revisar? El RID Master del dominio: asigna los bloques de RID que los DC necesitan para crear objetos con identificador único.
  • b) ¿Es un rol de bosque o de dominio? De dominio — como PDC Emulator e Infrastructure Master.
  • c) ¿Qué otros síntomas apuntarían al PDC Emulator? Problemas de hora en el dominio o de cambios de contraseña.

Supuesto 5 — Usuarios que no pueden iniciar sesión

Escenario: varios usuarios de una sede no consiguen iniciar sesión en el dominio, mientras que otros sí.

  • a) ¿Qué comprobaciones básicas plantea el tema? Disponibilidad y alcance del controlador de dominio desde esa sede; configuración de DNS en los clientes (AD DS depende de DNS para localizar los DC); estado del servicio de autenticación Kerberos y sincronización horaria.
  • b) ¿Por qué la hora es relevante? Porque la autenticación Kerberos es sensible al desfase horario; el PDC Emulator actúa como referencia de tiempo del dominio.
  • c) ¿Dónde buscar evidencias? En el Visor de eventos del cliente y del DC (su análisis detallado, en el Tema 15).

Supuesto 6 — Buscar objetos en todo el bosque

Escenario: una aplicación necesita localizar objetos que pueden estar en cualquiera de los dominios del bosque.

  • a) ¿Qué componente lo hace posible? El catálogo global: réplica parcial de los objetos del bosque alojada en determinados DC, pensada para acelerar esas búsquedas.
  • b) ¿Contiene todos los atributos? No: es una réplica parcial, con los atributos más consultados.
  • c) ¿Sería el esquema el responsable? No: el esquema define qué clases y atributos pueden existir, no almacena el contenido para búsquedas.

Supuesto 7 — Actualizaciones controladas en los servidores

Escenario: se quiere aprobar y distribuir las actualizaciones desde la propia organización, evitando que cada servidor se actualice por su cuenta.

  • a) ¿Qué rol encaja? WSUS: descarga y aprobación centralizada, con distribución controlada.
  • b) ¿Sigue siendo una opción válida? Sí: está deprecated (sin nuevas funciones) pero soportado para producción — no está fuera de servicio.
  • c) ¿Qué buena práctica acompaña al despliegue? Probar en preproducción, aplicar en ventana de mantenimiento y disponer de copia/snapshot previo para poder revertir.

14. Resumen final: si mañana fuera el examen

  • Windows Server: SO orientado a servicios y conexiones múltiples. Server Core (sin GUI completa; menos superficie de ataque) vs. Desktop Experience. Ediciones Standard (2 OSE/VM por licencia) y Datacenter (ilimitadas) — derechos por licencia, no límite del servidor.
  • Tras instalar, el servidor se especializa con roles y características: rol = servicio (AD DS, DNS, DHCP, IIS, Hyper-V, RDS) · característica = apoyo (Backup, Clustering, RSAT). Administración con Server Manager y PowerShell.
  • Actualizaciones: ciclo mensual (Patch Tuesday como referencia), pruebas previas, ventana de mantenimiento y copia/snapshot. WSUS = rol de gestión centralizada; deprecated pero soportado. Monitorización: Performance Monitor, Resource Monitor y Visor de eventos (alta); Windows Admin Center y SCOM (media).
  • AD DS = servicio de directorio con base distribuida y jerárquica de objetos de red; hace autenticación, autorización, organización y gestión centralizada. LDAP → directorio · Kerberos → autenticación. Depende de DNS.
  • Estructura lógica: dominio → árbol → bosque (límite de seguridad); OU organiza y permite aplicar GPO (no es un dominio); trusts entre dominios/bosques. Estructura física: sitios (subredes bien conectadas) y DC.
  • Multimaestro salvo los 5 FSMO: 2 de bosque (Schema → estructura; Naming → dominios) + 3 de dominio (RID → identificadores; PDC → tiempo/contraseñas; Infrastructure → referencias).
  • GC → búsqueda (réplica parcial del bosque) · esquema → clases y atributos (común al bosque). GPO se vincula a sitio, dominio u OU.
