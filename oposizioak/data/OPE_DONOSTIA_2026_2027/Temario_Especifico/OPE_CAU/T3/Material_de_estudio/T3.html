1. La informática y su objeto de estudio

La informática es la ciencia que estudia el tratamiento automático y racional de la información mediante ordenadores. El propio término viene de «información» + «automática». Su objeto de estudio no es el ordenador en sí, sino la información: cómo se representa, se almacena, se procesa y se transmite. El ordenador es la herramienta que hace posible ese tratamiento automático.

Para entender el resto del tema (y buena parte del Bloque II) conviene distinguir tres niveles: el dato, la información y el sistema que los gestiona.

2. Datos e información

📌 Imprescindible para el examen (núcleo del tema)
Dato: representación simbólica de un hecho o valor (número, letra, símbolo), sin contexto suficiente para interpretarlo.
Información: conjunto de datos ya procesados, organizados y contextualizados, que aportan significado y son útiles para tomar una decisión.

Ejemplos sencillos:

  • «23» es un dato. «Hoy hace 23 grados en Donostia» es información: tiene contexto y sirve para decidir (por ejemplo, si salir con abrigo).
  • «412» es un dato. «El CAU registró 412 incidencias en enero, un 20 % más que en diciembre» es información.
  • Un DNI suelto en una celda de una hoja de cálculo es un dato; asociado a un expediente y a un trámite concreto, forma parte de información.
⚠️ No confundir: dato vs. información
El dato es la materia prima; la información es el producto elaborado. La frontera está en el contexto y el significado: si aquello permite interpretar y decidir, es información; si es un valor en bruto, es un dato. Preparado para test, pregunta corta y supuesto práctico.

Calidad de la información (contenido complementario)

Para que la información sea útil a una organización debe reunir una serie de cualidades. Las que se citan habitualmente (no es una clasificación normativa cerrada) son:

  • Exactitud (precisión): refleja fielmente la realidad, sin errores.
  • Completitud: no le faltan elementos relevantes.
  • Oportunidad: llega cuando se necesita; la información tardía pierde valor.
  • Relevancia (pertinencia): es adecuada para quien la recibe y para la decisión que debe tomar.
  • Accesibilidad: puede obtenerse con esfuerzo razonable por quien está autorizado.

De dato a conocimiento: el modelo DIKW (contenido secundario)

Un modelo conceptual útil para situar la progresión: Data → Information → Knowledge → Wisdom (datos → información → conocimiento → sabiduría). El conocimiento añade experiencia y relaciones; la sabiduría, criterio para decidir.

🧠 Para memorizar
Dato → bruto · Información → contexto · Conocimiento → relaciones · Sabiduría → decisión. La escalera sube en valor: cada nivel «cocina» el anterior.
💡 Ejemplo
En un CAU: cada ticket individual es un dato; el informe «el 40 % de las incidencias son de impresión» es información; saber que ese 40 % se concentra en un modelo concreto de impresora y por qué es conocimiento; decidir sustituir ese modelo en la próxima renovación es sabiduría.

3. Representación de la información: bits, bytes y códigos

Para que un ordenador procese información, esta debe representarse en el sistema binario, con solo dos símbolos (0 y 1) que se corresponden físicamente con dos estados eléctricos.

Unidades básicas: bit y byte

  • Bit (binary digit): la unidad mínima de información; un 0 o un 1. Se abrevia con b minúscula.
  • Byte (u octeto): agrupación de 8 bits. Se abrevia con B mayúscula. Es la unidad básica de la capacidad de almacenamiento; tradicionalmente permite representar un carácter.
📌 Imprescindible para el examen — b ≠ B
b = bit · B = byte · 1 B = 8 bits.
Las velocidades de transmisión se expresan en bits por segundo (Mbps, Gbps); los tamaños y capacidades, en bytes y sus múltiplos (MB, GB, TB). Por eso 100 Mbps ≈ 12,5 MB/s (100 ÷ 8): equivalencia ideal de unidades, sin contar sobrecargas de protocolo. (Las redes se estudian en el Bloque IV.)

Múltiplos: decimales (SI) y binarios (IEC)

Múltiplo decimal (SI) Valor Múltiplo binario (IEC) Valor
Kilobyte (KB) 10³ = 1.000 bytes Kibibyte (KiB) 2¹⁰ = 1.024 bytes
Megabyte (MB) 10⁶ bytes Mebibyte (MiB) 2²⁰ = 1.048.576 bytes
Gigabyte (GB) 10⁹ bytes Gibibyte (GiB) 2³⁰ bytes
Terabyte (TB) 10¹² bytes Tebibyte (TiB) 2⁴⁰ bytes
📌 Imprescindible para el examen
KB ≠ KiB · MB ≠ MiB · GB ≠ GiB. Secuencia: byte → KB → MB → GB → TB (×1.000) o KiB → MiB → GiB → TiB (×1.024). Este doble criterio explica el clásico «mi disco de 1 TB muestra unos 931 GiB»: el fabricante mide en base 10 y el sistema operativo suele medir en base 2.

Sistemas de numeración

Sistema Base Dígitos válidos Relación con los bits
Binario 2 0, 1 El sistema nativo del ordenador: cada dígito es un bit
Octal 8 0-7 1 dígito octal = 3 bits
Decimal 10 0-9 El sistema humano habitual; sin correspondencia exacta con los bits
Hexadecimal 16 0-9 y A-F 1 dígito hex = 4 bits → 2 dígitos hex = 1 byte

Tres conversiones sencillas de nivel test:

  • Decimal 10 = binario 1010 = hexadecimal A.
  • Binario 1101 = decimal 13 (8+4+0+1) = hexadecimal D.
  • Hexadecimal FF = binario 11111111 = decimal 255 (el valor máximo de un byte).
💡 Ejemplo
Una dirección MAC como 5C:26:0A:2B:31:F0 son 6 bytes escritos en hexadecimal (12 dígitos, 2 por byte). Un código de color web como #FF0000 (rojo) son 3 bytes: FF de rojo, 00 de verde, 00 de azul.

Codificación de caracteres

  • ASCII: código de caracteres clásico de 7 bits, con 128 valores, pensado para el inglés; sus extensiones a 8 bits añadían caracteres regionales según la variante.
  • Unicode: estándar (conjunto de caracteres) actual, que asigna un código único a los caracteres de prácticamente todos los idiomas.
  • UTF-8: una codificación de Unicode — la forma concreta de escribir esos códigos en bytes. De longitud variable (1 a 4 bytes por carácter), compatible con ASCII, y estándar de facto en la web y los sistemas modernos.
⚠️ No confundir
Unicode y UTF-8 no son sinónimos: Unicode es el estándar que dice «qué número corresponde a cada carácter»; UTF-8 es una de las codificaciones de ese estándar (existen otras, como UTF-16 o UTF-32), que dice «cómo se escriben esos números en bytes».
🔍 Para ampliar — contexto útil, menor probabilidad de pregunta directa
Cuando en un texto aparecen caracteres extraños en lugar de tildes o eñes («Ã±» en vez de «ñ»), casi siempre se debe a una confusión de codificaciones: el texto se guardó con una codificación y se está leyendo con otra. Problema clásico que un técnico de CAU se encuentra en la práctica.

4. Concepto de Sistema de Información

Un Sistema de Información (SI) es el conjunto organizado de elementos —personas, procesos, datos y tecnología— que interactúan entre sí con el objetivo de captar, procesar, almacenar y distribuir información para apoyar la toma de decisiones y el funcionamiento de una organización.

Su importancia organizativa es directa: sin sistemas de información fiables, una organización no puede convertir sus datos en decisiones. Y fíjate en el matiz clave: un SI no es solo «el programa» ni solo «el ordenador» — es todo el conjunto que hace posible que un dato se convierta en información útil y llegue a quien la necesita.

📌 Imprescindible para el examen — prioridad
Sistema de Información ≠ Sistema Informático.
Sistema Informático → el componente tecnológico: hardware + software.
Sistema de Información → el conjunto más amplio que integra personas, procesos/procedimientos, datos y tecnología.
Todo SI moderno contiene un sistema informático, pero no se reduce a él. Es una de las distinciones más preguntables del tema.

Funciones de un Sistema de Información

1. Captar → 2. Almacenar → 3. Procesar → 4. Distribuir (secuencia de memoria)

  • Captar (o capturar) datos, internos y externos a la organización.
  • Almacenarlos de forma organizada y recuperable.
  • Procesarlos, transformándolos en información con valor.
  • Distribuirlos a las personas o sistemas que los necesitan, en el momento adecuado.
💡 Ejemplo
El padrón municipal es un Sistema de Información: capta datos (altas y cambios de domicilio en las oficinas de atención), los almacena (base de datos, Tema 5), los procesa (validaciones, estadísticas) y los distribuye (certificados de empadronamiento, cifras oficiales de población). Incluye la tecnología, pero también al personal que lo usa y los procedimientos administrativos que regulan su uso.

Componentes de un Sistema de Información

  • Hardware: los equipos físicos (apartado 6).
  • Software: los programas y aplicaciones que procesan los datos.
  • Datos: la materia prima que el sistema capta, almacena y transforma.
  • Personas (peopleware): quienes usan, administran y mantienen el sistema.
  • Procedimientos: las normas y métodos de trabajo que rigen cómo se usa el sistema.
  • Redes de comunicación: la infraestructura que permite intercambiar datos entre elementos y sistemas (se desarrollan en el Bloque IV).

5. Elementos constitutivos de un sistema

Parte directamente exigida por las bases. La idea general de «sistema» viene de la Teoría General de Sistemas: un conjunto de elementos interrelacionados que trabajan juntos para alcanzar un objetivo común. Sus elementos constitutivos, en el modelo general que usa este tema:

  • Entrada (input): lo que el sistema recibe del exterior para poder funcionar.
  • Proceso: la transformación que el sistema aplica sobre esa entrada.
  • Salida (output): el resultado que el sistema entrega tras el proceso.
  • Retroalimentación (feedback): la información sobre el resultado que vuelve al sistema para ajustar su funcionamiento.
  • Entorno: todo lo que rodea al sistema y con lo que interactúa, sin formar parte de él.
  • Límites (frontera): lo que separa al sistema de su entorno, delimitando qué está dentro y qué fuera.
🧠 Para memorizar
La historia completa en una frase: «Algo ENTRA, se PROCESA y SALE; el resultado RETROALIMENTA al sistema, que vive dentro de una FRONTERA rodeado de su ENTORNO». Seis piezas: 4 del flujo (entrada-proceso-salida-feedback) + 2 del contexto (entorno-frontera).
💡 Ejemplo
El propio CAU visto como sistema: la entrada son los avisos de los usuarios; el proceso, el diagnóstico y la resolución; la salida, el servicio restaurado y el ticket documentado; la retroalimentación, la encuesta de satisfacción que sirve para ajustar el servicio; el entorno, el resto del ayuntamiento y sus proveedores; y la frontera, lo que separa qué gestiona el CAU y qué no.
⚠️ No confundir — dos listas distintas
Elementos de cualquier sistema (Teoría General de Sistemas): entrada, proceso, salida, retroalimentación, entorno, límites.
Componentes de un Sistema de Información: hardware, software, datos, personas, procedimientos, redes.
Son clasificaciones diferentes que responden a preguntas diferentes: la primera describe cómo funciona un sistema; la segunda, de qué está hecho un SI. Un test puede mezclarlas a propósito.

6. Arquitectura de ordenadores: componentes y funciones

Los ordenadores de propósito general utilizan ampliamente arquitecturas derivadas del concepto de programa almacenado, asociado tradicionalmente al modelo propuesto por John von Neumann (1945): los datos y las instrucciones comparten una misma memoria. Es el modelo clásico que estudia este tema; las arquitecturas reales actuales incorporan numerosas optimizaciones sobre él.

Unidad Central de Proceso (CPU)

La CPU (Central Processing Unit) es el «cerebro» del ordenador: ejecuta las instrucciones de los programas. Internamente se compone de:

  • Unidad de Control (UC): dirige y coordina el resto de componentes, interpretando cada instrucción y generando las señales necesarias para ejecutarla.
  • Unidad Aritmético-Lógica (ALU): realiza las operaciones aritméticas (sumas, restas...) y lógicas (comparaciones, condiciones).
  • Registros: pequeñas unidades de almacenamiento interno muy rápido, integradas en la CPU, que guardan temporalmente los datos e instrucciones en proceso.

El trabajo de la CPU es un bucle constante llamado ciclo de instrucción: 1. Captación (fetch) → 2. Decodificación (decode) → 3. Ejecución (execute). El ritmo lo marca el reloj del sistema (frecuencia en GHz). Las CPU actuales son multinúcleo (multicore): varios núcleos completos en un mismo chip ejecutando instrucciones en paralelo.

🧠 Para memorizar
Ciclo de instrucción en castellano: CAPTAR → DECODIFICAR → EJECUTAR (fetch → decode → execute). Y el reparto de papeles: UC → coordina/interpreta · ALU → calcula · Registros → guardan temporalmente.

Memoria, firmware y caché

La memoria principal almacena los datos y programas que la CPU necesita tener accesibles mientras trabaja. No debe confundirse con el almacenamiento secundario (discos), que se estudia en el Tema 6.

  • RAM (Random Access Memory): memoria volátil — pierde su contenido al cortarse la alimentación. Es donde se cargan los programas en ejecución y sus datos.
  • Memoria no volátil: conserva su contenido sin alimentación. La ROM (Read Only Memory) es el ejemplo clásico de memoria no volátil de solo lectura.
  • Firmware: software de bajo nivel que inicializa y controla funciones básicas del hardware y arranca el equipo antes de cargar el sistema operativo. Memoria y firmware son cosas distintas: la memoria es el soporte; el firmware, el software que reside en ella. En los equipos actuales el firmware suele almacenarse en memoria flash no volátil (reescribible para actualizaciones), por lo que no debe presentarse como «ROM» en sentido estricto.
  • BIOS: el firmware tradicional de los PC. UEFI: la especificación de firmware moderna que ha sustituido progresivamente a la BIOS (más capacidades, arranque seguro, discos grandes). UEFI no es «un tipo de ROM»: es firmware de plataforma. Coloquialmente aún se dice «entrar en la BIOS» aunque el equipo lleve UEFI.
  • Memoria caché: memoria muy rápida y pequeña situada entre la CPU y la RAM, que guarda copias de los datos más usados para acelerar el acceso. En arquitecturas con varios niveles, L1 suele ser la más pequeña y rápida, L2 intermedia y L3 mayor y más lenta que L1/L2 (jerarquía habitual, no ley universal).
🧠 Para memorizar — jerarquía de memoria
De más rápida/pequeña/cara a más lenta/grande/barata:
REGISTROS → CACHÉ (L1→L2→L3) → RAM → ALMACENAMIENTO (Tema 6).
Regla: cuanto más cerca de la CPU, más rápida y más pequeña es la memoria.

Buses de comunicación

Los «canales» por los que circula la información entre componentes. En el modelo clásico se distinguen tres buses según lo que transportan:

  • Bus de datos: transporta los datos que se intercambian entre CPU, memoria y periféricos. Su anchura (32, 64 bits) determina cuántos bits se transfieren a la vez.
  • Bus de direcciones: transporta la dirección de memoria (o del dispositivo) a la que se quiere acceder. Su anchura determina la memoria máxima direccionable (con n líneas, 2ⁿ posiciones).
  • Bus de control: transporta las señales que coordinan y sincronizan el sistema (lectura/escritura, interrupciones, reloj).
📌 Imprescindible para el examen
Recurso de memoria: datos → QUÉ se transfiere · direcciones → DÓNDE · control → CÓMO/CUÁNDO.
Matiz de direccionalidad, tal como se formula en el modelo clásico de este tema: el bus de direcciones se considera unidireccional (la CPU indica la dirección) y el de datos, bidireccional.
Los buses e interfaces externas (USB y similares) pertenecen al Tema 8.

Placa base y chipset

  • La placa base (motherboard) es el circuito impreso principal que interconecta CPU, memoria, buses, ranuras de expansión y el resto de componentes.
  • El chipset (conjunto de lógica de la plataforma) facilita la interconexión y gestión de determinados dispositivos y buses de la placa. En arquitecturas modernas, algunas funciones que históricamente residían en el chipset (como el controlador de memoria) están integradas en el propio procesador.
🔍 Para ampliar — arquitectura Harvard
El modelo de Von Neumann se contrapone a la arquitectura Harvard, en la que datos e instrucciones tienen memorias físicamente separadas (habitual en microcontroladores). Para este tema basta con retener que el rasgo definitorio de Von Neumann es el programa almacenado: instrucciones y datos en la misma memoria.

7. Datos y anclas de memoria

  • DATO → bruto · INFORMACIÓN → contexto (· conocimiento → relaciones · sabiduría → decisión).
  • SI = personas + procesos + datos + tecnología · Sistema Informático = solo hardware + software.
  • Funciones del SI: CAPTAR → ALMACENAR → PROCESAR → DISTRIBUIR.
  • Elementos de un sistema: entrada → proceso → salida → retroalimentación, con entorno y frontera.
  • b = bit · B = byte · 1 B = 8 bits; redes en bits/s, capacidades en bytes; 100 Mbps ≈ 12,5 MB/s.
  • KB/MB/GB/TB ×1.000 · KiB/MiB/GiB/TiB ×1.024 (2¹⁰, 2²⁰, 2³⁰, 2⁴⁰).
  • Bases de numeración: 2 / 8 / 10 / 16; octal = 3 bits/dígito; hex = 4 bits/dígito; 1 byte = 2 dígitos hex; FF = 255.
  • ASCII = 7 bits/128 · Unicode = estándar · UTF-8 = codificación (variable, compatible ASCII).
  • UC → coordina · ALU → calcula · Registros → guardan temporalmente; ciclo CAPTAR → DECODIFICAR → EJECUTAR.
  • Jerarquía: Registros → Caché → RAM → Almacenamiento.
  • Buses: Datos → qué · Direcciones → dónde · Control → cómo/cuándo.
  • Von Neumann = programa almacenado (memoria común); Harvard = memorias separadas.

9. Posibles trampas de examen

  • Presentar un dato como información (o al revés): «412» no informa de nada sin contexto; la clave es si permite interpretar y decidir.
  • Mezclar bits y bytes: «100 Mbps = 100 MB/s» es falso; son 12,5 MB/s (÷8).
  • Dar por iguales KB y KiB: 1 KB = 1.000 bytes; 1.024 es el KiB.
  • Presentar Unicode y UTF-8 como sinónimos, o llamar a UTF-8 «estándar de caracteres»: es una codificación de Unicode.
  • Equiparar Sistema de Información y Sistema Informático: el SI incluye personas y procedimientos.
  • Cruzar las dos listas del sistema: «los elementos constitutivos de un sistema son hardware, software, datos y personas» mezcla los componentes del SI con los elementos generales (entrada, proceso, salida, feedback, entorno, límites).
  • Atribuir el cálculo a la UC: la UC interpreta y coordina; quien calcula es la ALU.
  • Confundir RAM con almacenamiento: la RAM es volátil; los documentos persisten en el almacenamiento secundario.
  • Identificar firmware con ROM estricta (o UEFI con «un tipo de ROM»): el firmware es software de bajo nivel, hoy en flash no volátil y actualizable.
  • Intercambiar los buses: decir que el bus de direcciones transporta los datos, o que el de datos indica la posición de memoria.
  • Cruzar Von Neumann y Harvard: «en Von Neumann datos e instrucciones van en memorias separadas» es exactamente al revés.
  • Desordenar la jerarquía de memoria o el ciclo de instrucción (captar → decodificar → ejecutar).

10. Posibles preguntas tipo test y cálculos rápidos

Preguntas conceptuales

  • Distinguir dato de información a partir de un ejemplo concreto.
  • El orden y significado de los niveles del modelo DIKW.
  • ¿Qué diferencia hay entre b y B? ¿Cuántos bits tiene un byte?
  • ¿En qué unidades se mide la velocidad de red y en cuáles la capacidad de almacenamiento?
  • Identificar la base y los dígitos válidos de binario, octal y hexadecimal.
  • ¿Qué es ASCII (bits y número de valores) y qué relación hay entre Unicode y UTF-8?
  • Diferencia entre Sistema de Información y Sistema Informático (pregunta prioritaria).
  • Las funciones del SI en orden: captar → almacenar → procesar → distribuir.
  • Identificar los elementos constitutivos de un sistema en un supuesto (y no confundirlos con los componentes del SI).
  • ¿Qué componente de la CPU calcula (ALU), cuál coordina (UC) y qué son los registros?
  • El orden del ciclo de instrucción.
  • ¿Qué memoria es volátil? ¿Qué es el firmware y qué relación hay entre BIOS y UEFI?
  • Emparejar cada bus con lo que transporta, y su direccionalidad en el modelo clásico.
  • ¿Cuál es el rasgo definitorio del modelo de Von Neumann?

Cálculos rápidos (con solución)

  • ¿Cuántos bits hay en 4 bytes? → 32.
  • ¿Cuántos bytes son 1 KiB y 1 KB? → 1.024 y 1.000.
  • ¿Cuántos valores distintos representa un byte? → 256 (0-255).
  • 100 Mbps ≈ ¿cuántos MB/s? → 12,5. ¿Y 1 Gbps? → 125.
  • Hexadecimal FF → ¿decimal? → 255; binario 1101 → ¿decimal y hex? → 13 y D.
  • Un disco de 1 TB, ¿cuántos GiB muestra aproximadamente el sistema? → ≈ 931 GiB.

1. Defina dato e información y explique su diferencia

  • Ejemplo («23» vs. «hoy hace 23 grados en Donostia»); opcional: mencionar DIKW como continuación.

2. Defina un Sistema de Información y enumere sus componentes

  • Definición: conjunto organizado de personas, procesos, datos y tecnología para captar, procesar, almacenar y distribuir información.
  • Componentes: hardware, software, datos, personas, procedimientos, redes.
  • Cierre: distinción con el sistema informático (solo hardware + software).

3. Explique las funciones de un Sistema de Información

  • Secuencia: captar → almacenar → procesar → distribuir, con una frase por fase.
  • Ejemplo del padrón municipal recorriendo las cuatro fases.

4. Explique los elementos constitutivos de un sistema

  • Origen: Teoría General de Sistemas.
  • Los seis elementos: entrada, proceso, salida, retroalimentación, entorno, límites — con una frase cada uno.
  • Ejemplo (el CAU como sistema) y advertencia: no confundir con los componentes del SI.

5. Describa los componentes y funciones principales de una CPU

  • Papel de la CPU (ejecutar instrucciones).
  • UC (coordina/interpreta), ALU (calcula), registros (almacenamiento interno rápido).
  • Ciclo de instrucción: captar → decodificar → ejecutar; reloj (GHz) y multinúcleo como apunte final.

6. Explique el modelo de Von Neumann

  • Idea central: programa almacenado — datos e instrucciones en memoria común.
  • Bloques: CPU (UC, ALU, registros), memoria, buses, entrada/salida.
  • Contraste breve con Harvard (memorias separadas) como ampliación.

7. Explique la jerarquía básica de memoria

  • Secuencia: registros → caché (L1/L2/L3) → RAM → almacenamiento secundario.
  • Criterios: proximidad a la CPU, velocidad, tamaño y coste.
  • Matiz: RAM volátil vs. almacenamiento persistente; el detalle de discos es del Tema 6.

12. Supuestos prácticos

Supuesto 1 — Del dato al informe

Escenario: la aplicación de registro de entrada de un ayuntamiento acumula miles de apuntes diarios. La jefatura pide «saber cómo va el servicio» y el sistema genera un informe mensual con totales por oficina y tiempos medios de espera.

  • a) Identifica datos e información. Cada apunte individual (fecha, hora, oficina) es un dato; el informe con totales, comparativas y tiempos medios es información: datos procesados y contextualizados que permiten decidir (reforzar una oficina, cambiar horarios).
  • b) Recorre las funciones del SI en el caso. Capta (cada apunte en ventanilla) → almacena (base de datos) → procesa (agregados, medias) → distribuye (informe a jefatura).
  • c) ¿Qué cualidades debe tener ese informe para ser útil? Exactitud, completitud, oportunidad (llegar a tiempo para decidir), relevancia y accesibilidad.

Supuesto 2 — Identificar los componentes del SI

Escenario: el sistema de gestión de tickets del CAU: la herramienta ITSM instalada en servidores municipales, la base de datos de incidencias, los técnicos que la usan, el procedimiento de registro y escalado, y la red que conecta las sedes.

  • a) Clasifica cada elemento como componente del SI. Servidores → hardware; herramienta ITSM → software; incidencias registradas → datos; técnicos → personas; procedimiento de registro/escalado → procedimientos; conexión entre sedes → redes.
  • b) ¿Es esto un Sistema de Información o un sistema informático? Un SI completo: incluye personas y procedimientos. El sistema informático es solo la parte hardware + software.
  • c) Descríbelo con los elementos generales de un sistema. Entrada: avisos de usuarios; proceso: diagnóstico y resolución; salida: servicio restaurado y ticket cerrado; retroalimentación: encuestas e indicadores; entorno: el resto del ayuntamiento; frontera: el alcance del CAU.

Supuesto 3 — «Mi ordenador va lento»

Escenario: una usuaria se queja de lentitud. Observas que con muchas aplicaciones abiertas el equipo apenas responde, y que al reiniciar mejora temporalmente.

  • a) ¿Qué papel juegan CPU, RAM y caché en el rendimiento? La CPU ejecuta las instrucciones (UC coordina, ALU calcula); la RAM aloja los programas en ejecución — si se agota, el rendimiento cae; la caché acelera el acceso a los datos más usados, pero no compensa una RAM saturada.
  • b) ¿Por qué mejora al reiniciar? La RAM es volátil: al reiniciar se vacía y los programas se cargan de nuevo, liberando la memoria ocupada.
  • c) ¿Dónde termina este tema? En el concepto: la ampliación de RAM o el análisis del disco (almacenamiento) y del sistema operativo corresponden a los Temas 6 y 9.

Supuesto 4 — Unidades en la práctica

Escenario: un usuario pregunta por qué su disco «de 1 TB» muestra unos 931 GB, y cuánto tardaría en copiar un archivo de 500 MB por una red de 100 Mbps.

  • a) El disco. El fabricante mide en base 10 (1 TB = 10¹² bytes); el sistema suele mostrar GiB (2³⁰): 10¹² ÷ 2³⁰ ≈ 931 GiB. No falta espacio: son unidades distintas.
  • b) La copia. 100 Mbps ≈ 12,5 MB/s (÷8); 500 ÷ 12,5 = 40 segundos en condiciones ideales, sin contar sobrecargas de protocolo.
  • c) Concepto que se evalúa. b ≠ B y prefijos decimales vs. binarios — los dos «no confundir» más rentables del tema.

14. Resumen final: si mañana fuera el examen

  • Informática = tratamiento automático y racional de la información; el ordenador es la herramienta.
  • Dato = bruto, sin contexto · información = procesada y contextualizada, sirve para decidir. Cualidades: exacta, completa, oportuna, relevante, accesible. DIKW como modelo conceptual: datos → información → conocimiento → sabiduría.
  • b = bit, B = byte, 1 B = 8 bits. Múltiplos: KB/MB/GB/TB ×1.000 · KiB/MiB/GiB/TiB ×1.024. Redes en bits/s: 100 Mbps ≈ 12,5 MB/s (ideal).
  • Numeración: bases 2 / 8 / 10 / 16; octal 3 bits/dígito; hex 4 bits/dígito, 2 dígitos = 1 byte, FF = 255.
  • ASCII (7 bits, 128) · Unicode (estándar) · UTF-8 (codificación de Unicode, variable, compatible ASCII).
  • SI = personas + procesos + datos + tecnología (captar → almacenar → procesar → distribuir) ≠ sistema informático. Componentes del SI: hardware, software, datos, personas, procedimientos, redes.
  • Elementos constitutivos de un sistema (lista distinta): entrada, proceso, salida, retroalimentación, entorno, límites.
  • Arquitectura clásica (Von Neumann): programa almacenado. CPU = UC + ALU + registros; ciclo captar → decodificar → ejecutar.
  • Memorias: RAM volátil · firmware = software de bajo nivel en flash no volátil (BIOS → UEFI) · caché L1/L2/L3. Jerarquía: registros → caché → RAM → almacenamiento.
  • Buses (modelo clásico): datos (qué, bidireccional) · direcciones (dónde, unidireccional) · control (cómo/cuándo). Placa base interconecta; el chipset facilita la interconexión.
  • Fronteras: almacenamiento → T6 · periféricos e interfaces → T8 · sistemas operativos → T9.
