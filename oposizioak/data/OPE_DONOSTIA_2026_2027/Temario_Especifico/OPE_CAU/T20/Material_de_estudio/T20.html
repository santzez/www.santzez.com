⚠️ No confundir — fronteras del tema
Este tema trata el navegador web como aplicación cliente: sus motores, sus funcionalidades y su uso y diagnóstico en un CAU.
Tema 19 → diseño de interfaz, usabilidad y accesibilidad. Tema 24 → certificados y criptografía. Tema 25 → phishing, malware y seguridad. Tema 31 → HTTP/HTTPS y arquitectura y protocolos de Internet.
Aquí no se desarrollan TCP/IP, DNS en profundidad, servidores web, el funcionamiento interno de HTTP ni HTML, CSS o JavaScript avanzados.

1. El navegador como aplicación cliente

📌 Imprescindible para el examen — definición
Navegador web → aplicación cliente que solicita recursos web y los procesa y renderiza para mostrarlos a la persona usuaria.
Dos verbos clave: SOLICITA (es cliente) y RENDERIZA (transforma código en representación visual).

El triángulo básico

Elemento Papel
Navegador Cliente: pide el recurso y lo presenta
Servidor web Recurso: entrega el contenido solicitado
URL Identifica el recurso solicitado
💡 Ejemplo
Cuando una persona escribe una dirección y pulsa Intro, el navegador actúa como cliente y solicita el recurso identificado por esa URL; el servidor web lo entrega; el navegador lo procesa y renderiza. El cómo viaja esa petición (protocolos, direccionamiento, resolución de nombres) corresponde al Tema 31.

Qué hace un navegador, en orden

  • Permite introducir una URL o seleccionar un enlace.
  • Solicita los recursos correspondientes.
  • Procesa HTML, CSS y JavaScript.
  • Renderiza el contenido en pantalla.
  • Gestiona la navegación y las sesiones (pestañas, historial, cookies, credenciales de sesión).

2. Motores de renderizado

📌 Imprescindible para el examen
Motor de renderizado → componente que interpreta HTML y CSS y construye la representación visual de la página.
Es el que dibuja. No ejecuta JavaScript: de eso se encarga otro motor distinto (apartado 3).
Motor de renderizado Navegadores que lo utilizan
Blink Chrome, Edge, Opera, Brave
WebKit Safari
Gecko Firefox
🧠 Para memorizar
Muchos navegadores comparten motor. Chrome, Edge, Opera y Brave usan Blink: son productos distintos con el mismo motor. Por eso una página puede comportarse igual en todos ellos y distinto en Firefox (Gecko) o Safari (WebKit).

3. Motores JavaScript

📌 Imprescindible para el examen — la distinción más preguntable del tema
MOTOR DE RENDERIZADO → interpreta HTML/CSS y construye la representación visual.
MOTOR JAVASCRIPT → ejecuta JavaScript.
Son componentes distintos con funciones distintas. Un navegador incorpora los dos.
Motor JavaScript Dónde se utiliza
V8 Chrome y Edge; también el entorno Node.js, fuera del navegador
JavaScriptCore Safari
SpiderMonkey Firefox

Tabla combinada — navegador, motor de renderizado y motor JavaScript

Navegador Motor de renderizado Motor JavaScript
Chrome Blink V8
Edge Blink V8
Opera Blink V8
Brave Blink V8
Safari WebKit JavaScriptCore
Firefox Gecko SpiderMonkey
💡 Ejemplo
Que V8 se utilice también en Node.js demuestra que un motor JavaScript no es exclusivo del navegador: es un componente que ejecuta código JavaScript y puede integrarse en otros entornos. Un motor de renderizado, en cambio, está ligado a la presentación de contenido web.

4. Navegadores habituales

Navegador Rasgos relevantes para el CAU
Chrome Multiplataforma; motor Blink + V8; ecosistema amplio de extensiones; perfiles y sincronización con cuenta
Edge Navegador de Microsoft; desde 2020 utiliza Blink (anteriormente EdgeHTML); habitual en entornos Windows corporativos, con opciones de gestión por directiva
Firefox Desarrollado por Mozilla; motor Gecko + SpiderMonkey; útil como segundo navegador de contraste porque su motor es distinto
Safari Navegador de Apple; motor WebKit + JavaScriptCore; propio de los entornos macOS e iOS
Opera Basado en Blink; incorpora funcionalidades propias añadidas sobre ese motor
⚠️ No confundir — Edge y EdgeHTML
Desde 2020, Edge utiliza Blink. El motor anterior, EdgeHTML, corresponde a la etapa previa del producto. Es una asociación clásica de examen: si una opción dice «Edge → EdgeHTML» como situación actual, es incorrecta.
Tampoco confundas Edge con Internet Explorer, que es un producto distinto y anterior.

Las cuotas de mercado no son contenido nuclear de este tema: cambian con el tiempo y no aportan nada a la comprensión del navegador como cliente. Si aparecen, deben tratarse como actualidad fechada (apartado 23).

5. Funcionalidades básicas

5.1 Omnibox

📌 Imprescindible para el examen
Omnibox → barra que permite tanto introducir una URL como realizar una búsqueda.
Es decir, unifica la barra de direcciones y la de búsqueda en un único campo. Término preguntable de forma directa.

5.2 Pestañas

Permiten mantener varias páginas abiertas dentro de una misma ventana, alternando entre ellas sin abrir ventanas independientes.

5.3 Historial

Registro local de las páginas visitadas. Permite recuperar una página consultada anteriormente y, en su caso, eliminar ese registro.

5.4 Marcadores (favoritos)

Enlaces guardados por la persona usuaria para acceso rápido, normalmente organizados en carpetas o en una barra de marcadores.

⚠️ No confundir — marcadores, historial, cookies y caché
Marcador → enlace guardado deliberadamente por la persona usuaria.
Historial → registro automático de páginas visitadas.
Cookie → dato que un sitio utiliza para mantener información entre solicitudes o visitas (sesión, preferencias).
Caché → copia local de recursos (imágenes, hojas de estilo, scripts) que evita descargarlos de nuevo y acelera la carga.
Son cuatro cosas distintas y es una confusión de examen muy frecuente.

5.5 Gestor de descargas

Permite consultar y controlar las descargas realizadas y su destino en el equipo. La gestión avanzada de archivos no forma parte de este tema.

5.6 Otras funcionalidades habituales

  • Zoom y ajustes de presentación del contenido.
  • Búsqueda dentro de la página.
  • Impresión y generación de PDF desde la página.
  • Gestión de contraseñas y autocompletado de formularios.
  • Configuración de permisos por sitio: cámara, micrófono, ubicación, notificaciones.

6. Navegación privada (incógnito)

📌 Imprescindible para el examen — definición precisa
Modo privado o incógnito → modo que limita los datos de navegación que el navegador guarda localmente durante esa sesión.
Formulación cuidadosa: limita lo que se guarda en local. No conviene afirmar que elimina absolutamente todo dato local de cualquier tipo, porque el comportamiento concreto depende del navegador y de qué datos se trate.
⚠️ No confundir — INCÓGNITO ≠ ANONIMATO
El modo privado no oculta la actividad frente a:
· el proveedor de acceso a Internet;
· la red corporativa u organización desde la que se navega;
· los sitios web visitados;
· los servicios de seguridad o de monitorización que puedan estar en uso.
Regla: INCÓGNITO → MENOS RASTRO LOCAL. NO → ANONIMATO EN LA RED.

Por qué le interesa al CAU

Más allá de la privacidad, el modo privado es una herramienta de diagnóstico: al abrirse con un estado de sesión limpio, ayuda a distinguir si un problema procede de datos del sitio, cookies o sesión previa o si es un problema de la propia aplicación web. Su papel en el procedimiento de diagnóstico se detalla en el apartado 13.

7. Extensiones

📌 Imprescindible para el examen
Extensión (o complemento) → componente que añade funcionalidades al navegador.
  • Bloqueador de anuncios.
  • Gestor de contraseñas.
  • Corrector ortográfico o de estilo.

Permisos y riesgos

Una extensión puede solicitar permisos con acceso a las páginas y a su contenido. Ese acceso es lo que le permite funcionar, pero también lo que la convierte en un vector de riesgo.

Riesgo En qué consiste
Origen no confiable Instalación desde fuentes no verificadas o fuera de las tiendas oficiales del navegador
Permisos excesivos La extensión pide más acceso del que su función justifica
Código malicioso La extensión ejecuta comportamiento dañino, a veces introducido en una actualización posterior
Filtración de información Envío de datos de las páginas visitadas o del formulario a terceros
🧠 Para memorizar
Criterio práctico de CAU ante una extensión: origen · permisos · necesidad real. Si el origen no es confiable, si los permisos exceden la función declarada o si la funcionalidad no es realmente necesaria, procede no instalarla o retirarla conforme a la política de la organización.

El modelo de permisos y su evolución técnica (por ejemplo, los cambios de manifiesto de las extensiones) se tratan como actualidad en el apartado 23, no como contenido nuclear.

8. Perfiles

📌 Imprescindible para el examen
Perfil de navegador → conjunto separado de configuración, cookies, sesiones, extensiones, historial y otros datos dentro del mismo navegador.
Cada perfil se comporta como un entorno independiente.
💡 Ejemplo
Perfil personal y perfil laboral: sesiones distintas en el mismo servicio sin cerrar una para abrir la otra, extensiones distintas y marcadores separados. Es el escenario típico de quien atiende dos entornos (por ejemplo, una aplicación corporativa y una sede electrónica) con credenciales diferentes.
⚠️ No confundir — perfil de navegador y cuenta del sistema operativo
Perfil de navegador → separación dentro del navegador: sus datos, sus extensiones, sus sesiones.
Cuenta de usuario del sistema operativo → separación a nivel del equipo: sesión del sistema, permisos, ficheros y perfil de usuario del SO (Temas 14 y 15).
Tampoco es lo mismo un perfil que una ventana de incógnito: el perfil es persistente y se mantiene entre sesiones; el incógnito es temporal.

9. DevTools: la herramienta del CAU

📌 Imprescindible para el examen
DevTools (herramientas para desarrolladores) → herramientas integradas en el navegador para inspeccionar y diagnosticar aplicaciones web.
Ancla: F12 → DevTools.
Panel Para qué sirve Qué responde en el CAU
Elements (HTML/CSS) Inspeccionar la estructura de la página y sus estilos ¿El elemento existe? ¿Está oculto o mal presentado?
Console Ver mensajes y errores de ejecución de la página ¿Hay un error que impide que funcione un botón o una acción?
Network Ver las peticiones de recursos y su resultado ¿Falta un recurso? ¿Alguna petición falla o no llega a completarse?
Almacenamiento Consultar cookies y datos que el sitio guarda en el navegador ¿Hay datos de sesión o del sitio que estén provocando el problema?
🧠 Para memorizar — regla de oro del diagnóstico
CONSOLE → algo falla al ejecutarse.
NETWORK → algo falla al pedirse o al llegar.
Si la página carga pero un control no responde → Console. Si la página carga incompleta o faltan recursos → Network.

DevTools sirve para observar y diagnosticar; el desarrollo web como tal no pertenece a este tema.

10. HTTPS y certificados en el navegador

📌 Imprescindible para el examen
HTTPS → comunicación HTTP protegida mediante TLS.
El navegador valida el certificado del sitio según las reglas de confianza correspondientes y advierte cuando esa validación no es satisfactoria.
⚠️ No confundir — HTTPS ≠ SITIO SEGURO
HTTPS y un certificado válido NO garantizan:
· que el sitio sea legítimo;
· que el contenido sea seguro;
· que no sea phishing.
Regla: HTTPS → PROTEGE LA COMUNICACIÓN. NO → GARANTIZA LA LEGITIMIDAD DEL CONTENIDO.
Un sitio fraudulento puede disponer de certificado y mostrar HTTPS: la comunicación estará protegida, pero el sitio seguirá siendo fraudulento.

El razonamiento correcto ante una persona usuaria no debe apoyarse en la presencia o ausencia de un icono concreto en la barra de direcciones, porque la señalización visual varía entre navegadores y entre versiones. Lo que debe explicarse es qué protege HTTPS y qué no, y verificar la identidad real del sitio (dominio, origen del enlace, canal por el que llegó).

El funcionamiento de TLS y de los certificados corresponde al Tema 24; el phishing y la seguridad frente a fraude, al Tema 25; HTTP y HTTPS como protocolos, al Tema 31.

11. Cookies y datos del sitio

📌 Imprescindible para el examen
Cookie → pequeño dato que un sitio utiliza para mantener información entre solicitudes o entre visitas.
Su función esencial es mantener estado: sin ella, cada petición sería independiente de la anterior.
  • Sesión: mantener a la persona identificada mientras navega por el sitio.
  • Preferencias: idioma, tamaño de texto, opciones de presentación.
  • Identificación: reconocer al visitante entre visitas.

First-party y third-party

Tipo Definición Ejemplo
First-party (propia) Asociada al sitio visitado La cookie de sesión del portal en el que se ha iniciado sesión
Third-party (de terceros) Asociada a otro dominio o servicio incluido en la página Una cookie de un servicio externo insertado en la página que se está visitando
⚠️ No confundir
La distinción first-party / third-party depende de a qué dominio está asociada la cookie respecto del sitio que se visita, no de para qué se use ni de si es «buena» o «mala».
Las restricciones que los navegadores aplican a las cookies de terceros son materia cambiante: se tratan como actualidad fechada (apartado 23), nunca como contenido estable.

Borrar datos: criterio práctico de CAU

📌 Imprescindible — criterio de actuación
Cuando sea posible, es preferible borrar los datos del sitio afectado en lugar de eliminar indiscriminadamente todo el historial y los datos del navegador.
Advertencia: borrar cookies puede cerrar sesiones abiertas y eliminar preferencias guardadas. Conviene avisar a la persona usuaria antes de hacerlo, porque tendrá que volver a identificarse.

12. Actualización, sincronización y privacidad

Actualización

📌 Imprescindible para el examen
Actualizar el navegador es una medida básica de seguridad porque las nuevas versiones corrigen vulnerabilidades.
Las versiones concretas de Chrome, Firefox o Edge no son materia de examen: lo relevante es el principio.

Sincronización

Muchos navegadores permiten sincronizar datos (marcadores, historial, contraseñas, extensiones, configuración) asociados a una cuenta, de modo que estén disponibles en varios dispositivos. En entornos corporativos, su uso suele estar sujeto a la política de la organización, por las implicaciones que tiene almacenar y replicar credenciales y datos de navegación.

Privacidad y permisos por sitio

  • Gestión de permisos por sitio: cámara, micrófono, ubicación, notificaciones.
  • Control de cookies y datos de sitios.
  • Opciones de bloqueo de contenido y de seguimiento, cuyo alcance concreto depende del navegador y de su configuración.

13. Procedimiento de diagnóstico CAU de una incidencia web

Este es el apartado más orientado al puesto: convierte todo lo anterior en un método de trabajo ordenado. La lógica es ir de lo simple a lo complejo y aislar variables una a una.

Paso Acción Qué permite descartar o confirmar
1 Reproducir el problema Confirmar que el fallo existe, en qué pasos exactos y si es constante o intermitente
2 Probar en modo privado / incógnito Aislar el efecto de datos de sesión y del sitio (y, según la configuración, de las extensiones)
3 Comprobar datos del sitio, caché y cookies Detectar si el problema procede de datos locales antiguos o corruptos
4 Desactivar o descartar extensiones cuando proceda Identificar una extensión que interfiere con la página
5 Probar otro perfil si es necesario Separar la configuración y los datos del perfil actual del comportamiento de la aplicación
6 Probar otro navegador Determinar si el problema se limita a un navegador o afecta a todos
7 Abrir DevTools (F12) Pasar de la observación a la evidencia técnica
8 Revisar Console Ver errores de ejecución que expliquen que algo no responda
9 Revisar Network Ver peticiones que fallan o recursos que no llegan
10 Determinar dónde está el problema Cliente (equipo), navegador, aplicación web o servicio remoto — y escalar en consecuencia
⚠️ No confundir — dos cautelas del procedimiento
1) «El modo incógnito siempre desactiva las extensiones»: NO. Depende de la configuración del navegador, ya que las extensiones pueden habilitarse expresamente para el modo privado. Por eso el paso 4 (desactivar extensiones) no es redundante con el paso 2.
2) Probar otro navegador ayuda a aislar el problema, pero no demuestra automáticamente que sea un problema del motor. La diferencia puede deberse a extensiones, perfil, configuración, versión o datos locales del primer navegador.
🧠 Para memorizar — la lógica en cuatro capas
DATOS (incógnito, caché, cookies) → ENTORNO (extensiones, perfil) → PRODUCTO (otro navegador) → EVIDENCIA (DevTools: Console y Network).
Y una conclusión final obligada: ¿cliente, navegador, aplicación web o servicio remoto?

14. Navegador frente a buscador

Navegador Buscador
Aplicación cliente instalada o disponible en el dispositivo Servicio web al que se accede a través del navegador
Chrome, Edge, Firefox, Safari Google, Bing, DuckDuckGo
Solicita y renderiza recursos web Localiza y devuelve resultados de búsqueda
⚠️ Trampa de examen clásica
Que Google sea a la vez el nombre de un buscador y de la empresa que desarrolla Chrome favorece la confusión. En una pregunta que pida identificar navegadores, «Google» como opción se refiere al buscador y sería incorrecta.
Regla: se navega CON un navegador; se busca EN un buscador.

17. Posibles trampas de examen

  • «Chrome es un motor de renderizado» — falso: Chrome es el navegador; Blink es su motor de renderizado.
  • «Blink y V8 son lo mismo» — falso: Blink renderiza HTML/CSS; V8 ejecuta JavaScript.
  • «Safari utiliza Gecko» — falso: Safari usa WebKit; Gecko es de Firefox.
  • «Edge usa EdgeHTML» — falso como afirmación actual: desde 2020, Edge utiliza Blink.
  • «Firefox usa V8» — falso: Firefox usa SpiderMonkey.
  • «Google es un navegador» — falso: es un buscador; el navegador es Chrome.
  • «El modo incógnito hace anónima la navegación» — falso: incógnito ≠ anonimato.
  • «En incógnito no se guarda absolutamente ningún dato» — impreciso: limita los datos de navegación guardados localmente durante esa sesión.
  • «El modo incógnito siempre desactiva las extensiones» — falso: depende de la configuración del navegador.
  • «Si aparece HTTPS, el sitio es seguro» — falso: HTTPS protege la comunicación, no acredita la legitimidad del sitio.
  • «Un certificado válido garantiza que el contenido es legítimo» — falso: son cosas distintas; un sitio fraudulento puede tener certificado.
  • «Las cookies son el historial» — falso: la cookie mantiene estado; el historial es el registro de páginas visitadas.
  • «El historial es la caché» — falso: la caché es una copia local de recursos para acelerar la carga.
  • «Una extensión y un perfil son equivalentes» — falso: complemento funcional vs. entorno de datos separado.
  • «Abrir DevTools equivale a probar en otro navegador» — falso: DevTools inspecciona el mismo navegador; no cambia de entorno.
  • «Si funciona en otro navegador, el problema es del motor» — no automáticamente: ayuda a aislar, pero la causa puede ser extensiones, perfil, configuración o datos locales.
  • «Ante cualquier problema, borrar todo el historial y los datos» — mala práctica: preferible borrar los datos del sitio afectado, avisando de que se pueden cerrar sesiones y perder preferencias.
  • Colar contenido ajeno: cómo funciona TLS (T24), phishing y malware (T25) o HTTP como protocolo (T31) no se desarrollan aquí.

19. Posibles preguntas cortas (con esquema de respuesta)

1. Defina navegador web

  • Definición: aplicación cliente que solicita recursos web y los procesa y renderiza.
  • Triángulo: navegador (cliente) — servidor web (recurso) — URL (identifica el recurso).
  • Cierre: funciones principales (URL, solicitud, procesado, renderizado, navegación y sesiones).

2. Diferencie motor de renderizado y motor JavaScript

  • Motor de renderizado: interpreta HTML/CSS y construye la representación visual (Blink, WebKit, Gecko).
  • Motor JavaScript: ejecuta JavaScript (V8, JavaScriptCore, SpiderMonkey).
  • Cierre: un navegador incorpora ambos; V8 se usa además en Node.js, fuera del navegador.

3. Explique las principales funcionalidades de un navegador

  • Omnibox, pestañas, historial, marcadores, gestor de descargas.
  • Navegación privada, extensiones, perfiles, gestión de contraseñas y permisos por sitio.
  • Cierre: DevTools como herramienta de inspección y diagnóstico.

4. Explique la navegación privada

  • Qué es: limita los datos de navegación que el navegador guarda localmente durante esa sesión.
  • Qué no es: no oculta la actividad ante el proveedor de acceso, la red corporativa, los sitios web ni los servicios de seguridad.
  • Cierre: utilidad como paso de diagnóstico en el CAU, con la cautela de que las extensiones pueden seguir activas según la configuración.

5. Explique las funciones y riesgos de las extensiones

  • Qué son: componentes que añaden funcionalidades (bloqueador de anuncios, gestor de contraseñas, corrector).
  • Permisos: pueden solicitar acceso a las páginas y a su contenido.
  • Riesgos: origen no confiable, permisos excesivos, código malicioso, filtración de información.
  • Cierre: criterio de valoración — origen, permisos y necesidad real, conforme a la política de la organización.

6. Explique los perfiles de navegador

  • Qué son: conjunto separado de configuración, cookies, sesiones, extensiones, historial y otros datos.
  • Ejemplo: perfil personal y perfil laboral, con sesiones y extensiones independientes.
  • Cierre: no confundir con la cuenta del sistema operativo ni con una ventana de incógnito.

7. Explique qué indica HTTPS

  • Qué es: comunicación HTTP protegida mediante TLS; el navegador valida el certificado según las reglas de confianza correspondientes.
  • Qué no garantiza: legitimidad del sitio, seguridad del contenido ni ausencia de phishing.
  • Cierre: regla — protege la comunicación, no acredita la legitimidad; el razonamiento no debe apoyarse en un icono concreto.

8. Explique el procedimiento básico de diagnóstico de una incidencia web

  • Reproducir; probar en incógnito; comprobar datos del sitio, caché y cookies.
  • Descartar extensiones; probar otro perfil; probar otro navegador.
  • Abrir DevTools: Console (errores de ejecución) y Network (peticiones y recursos).
  • Cierre: concluir si el problema está en el cliente, el navegador, la aplicación web o el servicio remoto, y escalar.

9. Explique las cookies y su clasificación

  • Qué son: pequeño dato que un sitio utiliza para mantener información entre solicitudes o visitas (sesión, preferencias, identificación).
  • First-party (asociada al sitio visitado) frente a third-party (asociada a otro dominio incluido en la página).
  • Cierre: al borrarlas pueden cerrarse sesiones y perderse preferencias; es preferible actuar sobre el sitio afectado.

10. Diferencie navegador y buscador

  • Navegador: aplicación cliente (Chrome, Edge, Firefox, Safari).
  • Buscador: servicio web al que se accede desde el navegador (Google, Bing, DuckDuckGo).
  • Cierre: se navega con un navegador; se busca en un buscador.

20. Supuestos prácticos

Supuesto 1 — Funciona en incógnito pero no en navegación normal

Escenario: una persona usuaria no puede completar un trámite en la aplicación web corporativa; en una ventana de incógnito, el mismo trámite funciona.

  • a) ¿Qué indica ese comportamiento? Que la causa está muy probablemente en el entorno del perfil normal: datos del sitio, cookies o sesión previa, o bien alguna extensión.
  • b) ¿Cómo se continúa? Comprobar y, en su caso, borrar los datos del sitio afectado; después desactivar extensiones y, si es necesario, probar otro perfil.
  • c) Cautela. No cabe concluir que las extensiones estén descartadas por el hecho de que funcione en incógnito: pueden estar habilitadas en modo privado según la configuración.
  • d) Aviso a la persona usuaria. Al borrar cookies se cerrará la sesión y podrá perder preferencias del sitio.

Supuesto 2 — Funciona en Chrome pero no en Firefox

Escenario: una aplicación web se comporta correctamente en Chrome y presenta errores en Firefox.

  • a) ¿Qué aporta el dato? Aísla el problema a un entorno concreto y descarta que el servicio esté caído para todos.
  • b) ¿Se puede concluir que es un problema del motor? No automáticamente: puede deberse a extensiones, perfil, configuración, versión o datos locales de Firefox.
  • c) ¿Cómo se comprueba? Probar Firefox en incógnito y con un perfil limpio; si persiste, abrir DevTools y revisar Console y Network para documentar el error.
  • d) Escalado. Si el error es reproducible en un perfil limpio, se documenta como incompatibilidad de la aplicación con ese navegador y se traslada a quien corresponda.

Supuesto 3 — La página carga pero un botón no responde

Escenario: el formulario se muestra correctamente, pero al pulsar «Enviar» no ocurre nada.

  • a) ¿Qué panel de DevTools se revisa primero? Console: un botón que no responde apunta a un error de ejecución de JavaScript.
  • b) ¿Qué se recoge? El mensaje de error completo, el momento en que aparece y los pasos exactos de reproducción.
  • c) ¿Qué se comprueba después? Si el error se reproduce en incógnito y sin extensiones; si es así, apunta a la aplicación web.

Supuesto 4 — La página carga parcialmente y faltan recursos

Escenario: el portal se ve sin estilos y faltan imágenes.

  • a) ¿Qué panel se revisa primero? Network: el síntoma indica peticiones que fallan o recursos que no llegan.
  • b) ¿Qué se busca? Peticiones fallidas o incompletas y qué recursos concretos no se obtienen.
  • c) ¿Qué se descarta antes de escalar? Caché y datos del sitio desactualizados, y una extensión que bloquee contenido (por ejemplo, un bloqueador que filtre recursos).
  • d) Conclusión. Si falla igual en otro perfil y otro navegador, el problema apunta a la aplicación web o al servicio remoto.

Supuesto 5 — «Tiene candado, luego la web es segura»

Escenario: una persona usuaria ha introducido credenciales en un sitio al que llegó por un enlace recibido, argumentando que «tenía el candado».

  • a) ¿Qué hay que explicarle? Que HTTPS es comunicación HTTP protegida mediante TLS: protege la comunicación, pero no garantiza que el sitio sea legítimo, que el contenido sea seguro ni que no sea phishing.
  • b) ¿Por qué no basta el icono? Porque la señalización visual varía entre navegadores y versiones, y un sitio fraudulento puede disponer de certificado.
  • c) ¿Qué debe verificarse? La identidad real del sitio: dominio exacto, origen del enlace y canal por el que llegó.
  • d) Actuación. Tratarlo como posible compromiso de credenciales conforme al procedimiento de la organización (el desarrollo del fraude y su respuesta corresponde al Tema 25).

Supuesto 6 — Dos entornos con configuraciones separadas

Escenario: una persona necesita trabajar simultáneamente con dos sesiones distintas del mismo servicio y pierde continuamente la sesión al alternar.

  • a) ¿Qué solución corresponde? Utilizar dos perfiles de navegador, cada uno con su configuración, cookies, sesiones y extensiones.
  • b) ¿Por qué no basta el modo incógnito? Porque es temporal y no conserva configuración ni datos entre sesiones; el perfil es persistente.
  • c) ¿Es lo mismo que crear otra cuenta en el equipo? No: el perfil separa datos dentro del navegador; la cuenta del sistema operativo separa la sesión del equipo.

Supuesto 7 — Extensión con permisos excesivos

Escenario: una persona solicita instalar una extensión descargada de un sitio no oficial que pide acceso a los datos de todas las páginas visitadas.

  • a) ¿Qué riesgos concurren? Origen no confiable, permisos excesivos respecto a la función declarada, posible código malicioso y filtración de información.
  • b) ¿Qué criterio se aplica? Origen, permisos y necesidad real, y siempre conforme a la política de la organización sobre instalación de software.
  • c) ¿Qué alternativa se ofrece? Valorar una extensión equivalente de fuente oficial con permisos proporcionados, o una funcionalidad ya disponible en el navegador.
  • d) Cautela adicional. Una extensión puede volverse maliciosa en una actualización posterior: conviene revisar periódicamente las instaladas y retirar las que no se usan.

22. Resumen final: si mañana fuera el examen

  • Navegador = aplicación cliente que solicita recursos y los procesa y renderiza. Navegador → cliente · servidor web → recurso · URL → identifica el recurso.
  • Motor de renderizado (HTML/CSS → representación visual): Blink (Chrome, Edge, Opera, Brave) · WebKit (Safari) · Gecko (Firefox).
  • Motor JavaScript (ejecuta JS): V8 (Chrome, Edge; también Node.js) · JavaScriptCore (Safari) · SpiderMonkey (Firefox). No son la misma cosa que el motor de renderizado.
  • Edge usa Blink desde 2020 (antes EdgeHTML). Google es buscador; Chrome es navegador.
  • Funcionalidades: Omnibox (URL o búsqueda) · pestañas · historial · marcadores · descargas · permisos por sitio. Historial ≠ cookies ≠ caché ≠ marcadores.
  • Incógnito = limita los datos guardados localmente en esa sesión. NO es anonimato frente a proveedor, red corporativa, sitios web ni servicios de seguridad. No siempre desactiva las extensiones: depende de la configuración.
  • Extensión = añade funcionalidad y puede pedir acceso a páginas y contenido. Riesgos: origen no confiable, permisos excesivos, código malicioso, filtración.
  • Perfil = conjunto separado de configuración, cookies, sesiones, extensiones e historial. No es la cuenta del SO ni una ventana de incógnito.
  • DevTools (F12): Elements (estructura y estilos) · Console (errores de ejecución) · Network (peticiones y recursos) · almacenamiento (cookies y datos del sitio).
  • HTTPS = HTTP + TLS: protege la comunicación; no garantiza legitimidad del sitio ni del contenido, ni ausencia de phishing.
  • Cookie = mantiene estado. First-party (sitio visitado) vs. third-party (otro dominio incluido en la página).
  • Diagnóstico CAU: reproducir → incógnito → datos del sitio/caché/cookies → extensiones → otro perfil → otro navegador → DevTools → Console → Network → ¿cliente, navegador, aplicación web o servicio remoto?
  • Borrado selectivo: mejor los datos del sitio afectado que todo el historial; avisar de que se cerrarán sesiones y se perderán preferencias.

23. Actualidad de navegadores — datos fechados

📌 Información sujeta a cambio · Fecha de actualización de estos apuntes: agosto de 2026
Nada de este apartado desplaza a los conceptos estables. Las versiones concretas y las cuotas de mercado no son materia de examen; se recogen aquí solo para situar el contexto.
  • Evolución de motores: la tendencia consolidada es la concentración en torno a Blink (Chrome, Edge, Opera, Brave), frente a WebKit en Safari y Gecko en Firefox. La migración de Edge a Blink en 2020 es el hito que explica esta situación y es el único dato de fecha realmente preguntable.
  • Extensiones: el modelo de manifiesto de las extensiones ha evolucionado hacia esquemas con permisos más acotados (el llamado Manifest V3 en los navegadores basados en Blink). Es materia de ampliación: para la OPE basta con el principio — las extensiones piden permisos, y unos permisos excesivos son un riesgo.
  • Cookies de terceros: los navegadores han venido aplicando restricciones crecientes a las cookies third-party, con calendarios y decisiones que han cambiado varias veces y que difieren entre productos. Debe tratarse siempre como situación cambiante, nunca como regla estable. Lo que sí es estable es la definición de first-party y third-party.
  • Cuotas de mercado: varían por periodo, país y tipo de dispositivo. No deben afirmarse en un examen como dato absoluto ni como parte del contenido nuclear.
  • Versiones: los navegadores habituales siguen ciclos de actualización frecuente y en gran medida automática. Lo relevante para la OPE es el principio del apartado 12: actualizar corrige vulnerabilidades.
