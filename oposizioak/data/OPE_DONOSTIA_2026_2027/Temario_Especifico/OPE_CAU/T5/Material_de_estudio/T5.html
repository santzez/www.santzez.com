1. De los ficheros al Sistema Gestor de Bases de Datos (SGBD)

En el Tema 4 vimos los ficheros como forma de almacenar información de manera persistente. Cuando varias aplicaciones necesitan compartir esos datos, gestionar ficheros por separado empieza a dar problemas: la misma información se acaba duplicando en varios sitios (redundancia), esas copias se desincronizan entre sí (inconsistencia), y resulta difícil controlar quién accede a qué y evitar que dos procesos escriban a la vez sobre el mismo dato.

Para resolver esto surge el Sistema Gestor de Bases de Datos (SGBD o DBMS — Database Management System): el software que se sitúa entre las aplicaciones y los datos, centralizando su almacenamiento y ofreciendo mecanismos de control que un conjunto de ficheros sueltos no puede garantizar por sí mismo.

  • Base de datos: conjunto organizado de datos, estructurados y relacionados entre sí, almacenados de forma centralizada y gestionados por un SGBD.
  • SGBD: el software que crea, mantiene y controla el acceso a la base de datos, actuando de intermediario entre las aplicaciones y los datos.

Ventajas de una base de datos frente a ficheros independientes

  • Menor redundancia: los datos se almacenan una sola vez y se comparten entre aplicaciones.
  • Mayor integridad y consistencia: el SGBD aplica reglas que evitan datos contradictorios.
  • Control centralizado y seguridad: se puede definir con detalle quién accede a qué información y con qué permisos.
  • Acceso concurrente controlado: varios usuarios o procesos pueden trabajar a la vez sin pisarse los cambios.
  • Independencia entre datos y programas: las aplicaciones no necesitan conocer cómo se almacenan físicamente los datos para poder usarlos.
🔍 Para ampliar — contexto útil, menor probabilidad de pregunta directa
SGBD relacionales muy extendidos: Oracle Database, Microsoft SQL Server, MySQL, MariaDB, PostgreSQL y, como base de datos ligera embebida en aplicaciones, SQLite. En un entorno corporativo, el SGBD suele funcionar en modo cliente-servidor: la base de datos reside en un servidor y las aplicaciones (clientes) se conectan a él a través de la red.

2. Tipos de bases de datos

No todas las bases de datos organizan la información del mismo modo. Los modelos más habituales son:

  • Jerárquica: organiza los datos en forma de árbol, con relaciones de padre a hijo (un padre puede tener varios hijos, pero cada hijo tiene un único padre).
  • En red: similar a la jerárquica, pero permite que un registro tenga varios «padres», representando relaciones más complejas mediante punteros.
  • Relacional: organiza los datos en tablas vinculadas mediante claves. Es, con diferencia, el modelo más extendido hoy en día, y el que se desarrolla en el resto de este tema.
  • Orientada a objetos: almacena los datos como objetos, con sus atributos y comportamientos, de forma coherente con la programación orientada a objetos.
  • NoSQL («Not Only SQL»): familia de bases de datos no relacionales, pensadas para grandes volúmenes de datos, alta disponibilidad y esquemas más flexibles que el rígido esquema de tablas del modelo relacional.
📌 Nivel básico — imprescindible para el examen
Para el examen, lo importante es identificar el modelo dominante: la base de datos relacional organiza la información en tablas con filas y columnas, relacionadas mediante claves.
El resto de modelos (jerárquico, en red, orientado a objetos, NoSQL) conviene reconocerlos por su idea general y diferenciarlos del relacional. Truco: jerárquica = árbol con un solo padre; en red = permite varios padres.
🔍 Para ampliar — contexto útil, menor probabilidad de pregunta directa
Dentro de NoSQL existen varias familias según cómo almacenan la información: clave-valor (por ejemplo, Redis), documental (por ejemplo, MongoDB), columnar (por ejemplo, Cassandra) y de grafos (por ejemplo, Neo4j).
No hace falta memorizar estos ejemplos concretos: basta con saber que NoSQL no es un único modelo, sino una familia de alternativas al modelo relacional.

3. El modelo relacional: conceptos básicos

El modelo relacional fue propuesto por Edgar F. Codd en 1970 y se basa en representar toda la información mediante tablas (también llamadas relaciones), cada una de ellas dedicada a un tipo de entidad (por ejemplo, «empleados» o «departamentos»).

  • Tabla (o relación): estructura bidimensional que almacena los datos de una entidad, organizados en filas y columnas.
  • Fila (o tupla, o registro): cada una de las ocurrencias concretas almacenadas en la tabla.
  • Columna (o atributo, o campo): cada una de las características que describen a la entidad.
  • Dominio: el conjunto de valores posibles que puede tomar un atributo (por ejemplo, el dominio del atributo «edad» son los números enteros positivos razonables para una persona).
  • Valor NULL (nulo): ausencia de valor en un atributo; no es lo mismo que cero ni que una cadena vacía, significa «desconocido o no aplicable».
📌 Nivel básico — imprescindible para el examen
El modelo relacional reutiliza, con otro nombre, el mismo vocabulario del Tema 4: tabla = fichero, fila (tupla) = registro, columna (atributo) = campo.
Pensarlo así ayuda a no tratar este tema como algo completamente nuevo, sino como una forma más estructurada y potente de organizar la misma idea de fondo. Los emparejamientos «tupla-fila-registro» y «atributo-columna-campo» son pregunta directa de test.

4. Claves y relaciones entre tablas

  • Clave candidata: cualquier campo (o combinación) que podría identificar de forma única cada fila; de entre ellas se elige la primaria.
  • Clave primaria (PK — Primary Key): campo, o conjunto de campos, que identifica de forma única cada fila de una tabla. No puede repetirse ni quedar vacía (nula) — es la llamada integridad de entidad.
  • Clave foránea (o ajena, FK — Foreign Key): campo de una tabla que referencia la clave primaria de otra tabla (o de la misma), estableciendo así una relación entre ambas.
  • Integridad referencial: regla que garantiza que el valor de una clave foránea corresponde siempre a un valor existente en la clave primaria a la que hace referencia (o que queda vacío, si eso está permitido).
💡 Ejemplo
En una base de datos municipal: la tabla EMPLEADOS tiene como PK el número de empleado, y una FK «código de departamento» que apunta a la PK de la tabla DEPARTAMENTOS. La integridad referencial impide asignar a alguien un departamento que no existe, y evita borrar un departamento mientras tenga personal asignado.

Tipos de relación entre tablas

  • Uno a uno (1:1): cada fila de una tabla se relaciona con, como mucho, una fila de la otra.
  • Uno a muchos (1:N): una fila de una tabla puede relacionarse con varias filas de otra, pero cada fila de la segunda solo se relaciona con una de la primera (un departamento tiene varios empleados, pero cada empleado pertenece a un único departamento).
  • Muchos a muchos (N:M): varias filas de una tabla pueden relacionarse con varias filas de otra. Se resuelve mediante una tabla intermedia que combina las claves primarias de ambas tablas.
📌 Nivel básico — imprescindible para el examen
La relación N:M no puede representarse directamente en el modelo relacional: exige siempre una tabla intermedia (por ejemplo, EMPLEADOS ↔ CURSOS se resuelve con una tabla EMPLEADO-CURSO). Es uno de los detalles más preguntados de este tema.
⚠️ No confundir
El diseño detallado de bases de datos (normalización, formas normales, sintaxis SQL avanzada) no forma parte de un tema específico de este temario.
Quédate con la idea de fondo: cómo se identifica de forma única una fila (clave primaria) y cómo se conectan las tablas entre sí (clave foránea y tipos de relación), sin entrar a diseñar ni consultar bases de datos reales.

5. El lenguaje SQL y las transacciones

SQL (Structured Query Language) es el lenguaje estándar para definir, consultar y manipular bases de datos relacionales. Sin necesidad de dominar su sintaxis, conviene conocer sus tres grandes grupos de sentencias:

Grupo Para qué sirve Sentencias típicas
DDL (Data Definition Language) Definir la estructura (tablas, índices) CREATE, ALTER, DROP
DML (Data Manipulation Language) Consultar y modificar los datos SELECT, INSERT, UPDATE, DELETE
DCL (Data Control Language) Controlar permisos de acceso GRANT, REVOKE
🧠 Para memorizar
DDL define la estructura (Create/Alter/Drop) · DML manipula los datos (Select/Insert/Update/Delete) · DCL controla los permisos (Grant/Revoke). Emparejar cada sentencia con su grupo es pregunta habitual de test.

Transacciones y propiedades ACID

Una transacción es un conjunto de operaciones que se ejecutan como una unidad indivisible: o se completan todas, o no se aplica ninguna. El ejemplo clásico es una transferencia bancaria (restar de una cuenta y sumar en otra: nunca debe quedarse a medias). Las transacciones de un SGBD relacional cumplen las propiedades ACID:

  • Atomicidad: la transacción se ejecuta entera o no se ejecuta («todo o nada»).
  • Consistencia: la base de datos pasa de un estado válido a otro estado válido, respetando todas sus reglas de integridad.
  • Aislamiento (Isolation): las transacciones concurrentes no interfieren entre sí; cada una «cree» que trabaja sola.
  • Durabilidad: una vez confirmada (commit), la transacción persiste aunque falle el sistema inmediatamente después.

6. Estándares de conectividad

Una aplicación no siempre está escrita en el mismo entorno que el motor de base de datos al que necesita acceder. Para no depender de un SGBD concreto, existen estándares de conectividad: interfaces comunes que permiten a una aplicación dialogar con distintos motores de base de datos de manera uniforme, delegando en un driver específico las particularidades de cada uno.

  • ODBC (Open Database Connectivity): estándar de conectividad de propósito general, que permite a cualquier aplicación acceder a distintos SGBD a través de un driver ODBC específico para cada motor, usando siempre la misma API común. En los equipos Windows corporativos se administra desde el «Administrador de orígenes de datos ODBC» (DSN), algo que un técnico de CAU puede encontrarse al configurar aplicaciones antiguas.
  • JDBC (Java Database Connectivity): el equivalente a ODBC pensado específicamente para aplicaciones Java, mediante drivers JDBC que permiten conectar con distintos motores de base de datos desde código Java.
📌 Nivel básico — imprescindible para el examen
ODBC = estándar general (origen Microsoft) · JDBC = específico de Java. Ambos comparten la misma arquitectura: API común + driver específico de cada SGBD. Si la pregunta menciona Java, la respuesta es JDBC.
🔍 Para ampliar — contexto útil, menor probabilidad de pregunta directa
Hoy en día muchas aplicaciones añaden una capa adicional (ORM, mapeo objeto-relacional) por encima de estos estándares, y existen también puentes como ODBC-JDBC. No hace falta profundizar en ello para este tema.

7. Resumen para estudiar

  • Base de datos = datos centralizados y compartidos, gestionados por un SGBD; ventajas frente a ficheros: menos redundancia, integridad, seguridad, concurrencia, independencia datos-programas.
  • Tipos: jerárquica (árbol, un padre), en red (varios padres), relacional (tablas + claves, la dominante), orientada a objetos, NoSQL (clave-valor, documental, columnar, grafos).
  • Modelo relacional (Codd, 1970): tabla/relación = fichero · fila/tupla = registro · columna/atributo = campo · dominio = valores posibles · NULL = ausencia de valor.
  • PK: única y no nula (integridad de entidad) · FK: referencia una PK y crea la relación · integridad referencial: la FK siempre apunta a un valor existente.
  • Relaciones: 1:1, 1:N, N:M (esta última exige tabla intermedia).
  • SQL: DDL (Create/Alter/Drop), DML (Select/Insert/Update/Delete), DCL (Grant/Revoke).
  • Transacción = unidad todo-o-nada; propiedades ACID: Atomicidad, Consistencia, Aislamiento, Durabilidad.
  • Conectividad: ODBC (general) y JDBC (Java); arquitectura API común + driver por SGBD.

9. Posibles puntos de examen

  • Emparejar sinónimos del modelo relacional: tupla = fila = registro; atributo = columna = campo.
  • Propiedades de la clave primaria (única y no nula).
  • Qué garantiza la integridad referencial y qué la de entidad.
  • Cómo se resuelve una relación N:M (tabla intermedia).
  • Reconocer el modelo de BD por su descripción (árbol → jerárquica; varios padres → en red; tablas → relacional; esquema flexible → NoSQL).
  • Clasificar una sentencia SQL en su grupo: CREATE → DDL, SELECT → DML, GRANT → DCL.
  • El significado de cada letra de ACID.
  • Diferencia entre ODBC y JDBC (general vs. Java) y el papel del driver.
  • Autor y año del modelo relacional (Codd, 1970).
  • Qué significa el valor NULL (no es cero ni cadena vacía).
