1. La familia Windows de usuario: versiones y ediciones

Windows 10 (2015) se distribuyó bajo el modelo de servicio, con actualizaciones de características periódicas identificadas por año y semestre (21H1, 22H2...). Su última versión de características fue la 22H2. Windows 11 (2021) mantiene el mismo núcleo NT y gran parte de la compatibilidad de aplicaciones, introduce una interfaz rediseñada y, sobre todo, requisitos de hardware orientados a la seguridad. Windows 11 continúa evolucionando mediante actualizaciones de características, con un canal de mantenimiento que va publicando distintas versiones (ver apartado 16).

Ediciones

Edición Orientación y rasgos distintivos
Home Uso general. No permite la unión tradicional a un dominio de Active Directory ni actuar como host de Escritorio remoto
Pro Funciones profesionales/empresariales: unión a dominio, BitLocker, Client Hyper-V y posibilidad de actuar como host de Escritorio remoto
Enterprise / Education Ediciones de volumen con funciones adicionales de seguridad y administración (organizaciones y centros educativos)
Enterprise LTSC Canal especializado sin las actualizaciones de características periódicas, con ciclo de vida específico; pensado para equipos que exigen máxima estabilidad (equipos industriales, kioscos, cajeros)
📌 Imprescindible para el examen
Las dos limitaciones de Home son pregunta recurrente: no admite unión tradicional a dominio AD y no puede actuar como host RDP (sí como cliente). Todo lo demás — dominio, BitLocker, Hyper-V cliente, host de Escritorio remoto — aparece a partir de Pro.

2. Características técnicas y funcionalidades

Windows 10 y 11 se basan en el núcleo NT (su arquitectura general se estudia en el Tema 9), con 64 bits como estándar actual y soporte de ARM64 en determinados equipos.

Seguridad de plataforma: TPM 2.0 y Secure Boot

📌 Imprescindible para el examen — no son lo mismo
TPM 2.0 (Trusted Platform Module) → módulo/plataforma de seguridad para operaciones criptográficas y almacenamiento protegido de claves (lo usan BitLocker, Windows Hello...). Protege claves.
Secure Boot (arranque seguro) → mecanismo de UEFI que verifica la integridad/firma de los componentes de la cadena de arranque antes de cargar el sistema operativo. Protege el arranque.
Ambos figuran entre los requisitos característicos de Windows 11, pero cumplen funciones distintas.

Funcionalidades destacadas

  • Windows Update: descarga e instalación de actualizaciones de seguridad y de características en el equipo.
  • Microsoft Defender: protección antimalware integrada de serie (su desarrollo, en el Tema 25).
  • BitLocker: cifrado de disco completo, que puede apoyarse en el TPM para custodiar las claves. Disponible desde la edición Pro.
  • Windows Hello: autenticación mediante biometría (huella, rostro) o PIN, ligada al dispositivo.
  • UAC (Control de cuentas de usuario): mecanismo de elevación de privilegios que limita el uso normal de privilegios administrativos y solicita confirmación cuando una acción requiere elevación. Su función es reducir el impacto de las acciones que requieren privilegios elevados — no es un antivirus ni «bloquea malware» por sí mismo.
  • Hyper-V cliente (contenido secundario): hipervisor incluido desde Pro, útil para máquinas virtuales locales (Tema 10).
  • WSL (Windows Subsystem for Linux) (contenido secundario): entorno Linux integrado en Windows sin necesidad de una VM completa.

En la interfaz, la aplicación Configuración ha ido sustituyendo progresivamente al Panel de control clásico, que se mantiene disponible para determinadas opciones.

3. Servicios y recursos del sistema

Servicios

Un servicio es un proceso que se ejecuta en segundo plano, normalmente sin interacción directa del usuario y con independencia de que haya sesión iniciada (por ejemplo, el propio Windows Update). Se administran desde la consola services.msc, donde cada servicio tiene un tipo de inicio:

  • Automático: arranca con el sistema.
  • Automático (inicio retrasado): arranca poco después del inicio, para no penalizar el arranque.
  • Manual: arranca cuando se solicita.
  • Deshabilitado: no puede arrancar.

Administrador de tareas

Herramienta cotidiana de diagnóstico del CAU: muestra los procesos en ejecución y el consumo de CPU, memoria, disco y red, además de las aplicaciones de inicio y los usuarios con sesión. Permite identificar rápidamente un proceso que satura un recurso o una aplicación que ralentiza el arranque.

Registro de Windows y Visor de eventos

  • Registro (Windows Registry): base de datos jerárquica de configuración del sistema y las aplicaciones. Se edita con regedit; conviene exportar una copia antes de modificarlo. Sus ramas principales (hives): HKLM (HKEY_LOCAL_MACHINE), HKCU (HKEY_CURRENT_USER), HKCR (HKEY_CLASSES_ROOT), HKU (HKEY_USERS) y HKCC (HKEY_CURRENT_CONFIG).
  • Visor de eventos (Event Viewer): registros de los sucesos ocurridos en el sistema, la seguridad y las aplicaciones. Su uso en profundidad se desarrolla en el Tema 15.
⚠️ No confundir — gran trampa del tema
REGISTRO = CONFIGURACIÓN (cómo está configurado el sistema) · VISOR DE EVENTOS = SUCESOS (qué ha pasado). Ambos sirven para diagnosticar, pero son cosas distintas y se consultan con herramientas distintas (regedit vs. Visor de eventos).

MMC y PowerShell

  • MMC (Microsoft Management Console): marco común sobre el que se construyen las consolas de administración de Windows mediante módulos o snap-ins (la propia consola de servicios, la de usuarios y grupos locales...).
  • PowerShell: shell y lenguaje de scripting para la administración y la automatización, orientado a objetos (a diferencia del símbolo del sistema clásico).

4. Instalación

Métodos

  • Medio físico: instalación manual arrancando desde USB o DVD.
  • Instalación en red: arranque por red mediante PXE, apoyado en servicios de despliegue como WDS (Windows Deployment Services), un servicio de Windows Server que permite instalar Windows por red sin medios físicos individuales (el detalle de Windows Server, en el Tema 12).
  • Despliegue mediante imágenes: se prepara un equipo de referencia, se generaliza con Sysprep, se captura la imagen en formato WIM y se despliega en muchos equipos.

Tipos de instalación

  • Instalación limpia: sobre disco vacío o formateado; no conserva aplicaciones ni configuración previas.
  • Actualización in-place (in-place upgrade): instala la nueva versión sobre la existente, conservando aplicaciones, configuración y archivos.
📌 Imprescindible para el examen — Sysprep vs. DISM
SYSPREP → GENERALIZA: prepara el equipo de referencia (elimina identidad, SID, información específica) para poder clonarlo y desplegarlo.
DISM (Deployment Image Servicing and Management) → SIRVE LA IMAGEN: monta, modifica y mantiene imágenes o la propia instalación de Windows (por ejemplo, para inyectar controladores o actualizaciones).
No son herramientas intercambiables: Sysprep prepara el equipo; DISM trabaja sobre la imagen.

Activación por volumen

KMS (Key Management Service) MAK (Multiple Activation Key)
Cómo activa Contra un servicio de administración de claves de la organización Con una clave de activación múltiple, con un número determinado de activaciones
Escenario típico Muchos equipos conectados a la red de la organización, con renovación periódica Equipos que no contactan habitualmente con la red interna
🧠 Para memorizar
KMS → SERVIDOR (servicio interno que activa) · MAK → CLAVE MÚLTIPLE (número limitado de activaciones).

5. Administración y mantenimiento

Actualizaciones: Windows Update y WSUS

  • Windows Update: actualización del equipo cliente.
  • WSUS (Windows Server Update Services): gestión centralizada/local de las actualizaciones — se descargan una vez en un servidor interno y se distribuyen de forma controlada a los equipos.
📌 Imprescindible para el examen — el estado de WSUS
WSUS está deprecated (en desuso), pero sigue soportado y funcionando en producción: no recibirá nuevas funcionalidades. Microsoft orienta progresivamente la gestión moderna hacia servicios cloud (Windows Update for Business, Windows Autopatch, Intune), pero «deprecated» no significa «fuera de servicio» ni implica que WSUS haya sido simplemente sustituido. (Dato de estado del producto: ver apartado 16.)

Administración remota

  • RDP (Escritorio remoto): acceso remoto gráfico. Home no puede actuar como host; Pro, Enterprise y Education sí. Como cliente (el que se conecta) puede actuar cualquier edición.
  • PowerShell Remoting: administración remota mediante comandos y scripts, idónea para tareas desatendidas o sobre varios equipos.
  • GPO (directivas de grupo): configuración centralizada de equipos unidos a un dominio (su desarrollo, en el Tema 12).
  • Intune: gestión moderna de endpoints (su desarrollo, en el Tema 30).

Mantenimiento habitual

  • Limpieza de disco / sensor de almacenamiento: elimina temporales, restos de actualizaciones y otros datos prescindibles.
  • Optimización de unidades: en HDD, desfragmentación tradicional; en SSD, el sistema realiza la optimización mediante TRIM, informando a la unidad de qué bloques ya no contienen datos útiles. Windows sí optimiza los SSD, pero no aplicándoles la desfragmentación tradicional.
  • chkdsk: herramienta para comprobar y reparar errores del sistema de archivos y determinados problemas relacionados con el disco. No es una herramienta de recuperación universal ni sustituye a una copia de seguridad.
  • Monitor de rendimiento y fiabilidad: rendimiento en tiempo real e historial de estabilidad (bloqueos, errores, instalaciones).

6. Recuperación del sistema

  • Puntos de restauración: capturas de la configuración y el Registro del sistema en un momento dado.
  • Historial de archivos: copias de carpetas de usuario concretas.
  • Imagen del sistema: captura completa del sistema para restaurarlo íntegramente.
  • WinRE (Windows Recovery Environment): entorno de recuperación con reparación de inicio, restauración de sistema o de imagen, símbolo del sistema y acceso a las opciones de reinicio.
  • Medio USB de recuperación: creado desde el equipo cuando funciona correctamente; permite acceder a esas opciones aunque el sistema no arranque.
  • Modo seguro: arranque con un conjunto reducido de controladores y servicios. Uso típico: diagnóstico, eliminación de controladores problemáticos y solución de problemas de inicio.
  • Reiniciar este PC: reinstalación de Windows con opción de conservar o eliminar los archivos personales.
📌 Imprescindible para el examen — Restaurar sistema vs. Reiniciar este PC
RESTAURAR SISTEMA → VUELVE ATRÁS: revierte configuración, Registro y estado del sistema a un punto anterior. No sustituye a una copia de seguridad de los documentos personales.
REINICIAR ESTE PC → REINSTALA Windows, con opciones de conservar o eliminar los archivos personales.
Son procedimientos distintos: uno revierte cambios; el otro reinstala el sistema.

7. Gestión del software base: instalación y desinstalación

Formatos y mecanismos

  • Instaladores ejecutables (.exe): cada uno define su propia lógica de instalación.
  • MSI: formato/tecnología de Windows Installer. Ventajas: instalación silenciosa (sin intervención del usuario), mantenimiento, distribución centralizada y desinstalación normalizada. Desde línea de comandos, msiexec /x desinstala un paquete MSI.
  • MSIX: formato moderno de empaquetado de aplicaciones de Windows, con mejor aislamiento y un proceso de instalación/desinstalación más ordenado (no debe afirmarse que garantice eliminar absolutamente todos los residuos).
  • winget (Windows Package Manager): gestor de paquetes que permite buscar, instalar, actualizar y desinstalar aplicaciones desde la línea de comandos — herramienta que un técnico de CAU debe reconocer. Como ampliación existe Chocolatey, alternativa de la comunidad.

Desinstalación

  • Vías habituales: Configuración > Aplicaciones, el clásico Panel de control > Programas y características, y msiexec /x para paquetes MSI (útil en desinstalaciones desatendidas).
  • Alcance real: el proceso de desinstalación elimina los componentes gestionados por el instalador, pero pueden permanecer datos de usuario, configuraciones o determinados componentes compartidos.
🔍 Para ampliar — contexto útil, menor probabilidad de pregunta directa
El empaquetado y la distribución de software a escala en un parque de equipos se desarrolla en el Tema 16; aquí basta con conocer los formatos y los mecanismos de instalación y desinstalación en un equipo.

10. Posibles trampas de examen

  • «Windows Home puede actuar como host de Escritorio remoto» — falso: solo como cliente; el host requiere Pro o superior.
  • «Windows Home puede unirse a un dominio de Active Directory» — falso en el modelo tradicional de unión a dominio.
  • «TPM y Secure Boot son lo mismo» — falso: claves criptográficas vs. verificación del arranque.
  • «El Visor de eventos guarda la configuración del sistema» — falso: eso es el Registro; el Visor guarda sucesos.
  • «Sysprep sirve para inyectar controladores en una imagen» — falso: eso es DISM; Sysprep generaliza el equipo de referencia.
  • «KMS y MAK son dos nombres del mismo método» — falso: servicio de activación interno vs. clave con activaciones limitadas.
  • «WSUS está obsoleto y ya no funciona» — falso: está deprecated, pero sigue soportado y operativo.
  • «Restaurar sistema reinstala Windows» — falso: eso es Reiniciar este PC; Restaurar sistema revierte configuración y Registro.
  • «Restaurar sistema recupera los documentos borrados del usuario» — falso: no es una copia de seguridad de datos personales.
  • «A los SSD hay que desfragmentarlos periódicamente» — falso: se optimizan con TRIM, no con desfragmentación tradicional.
  • «Una desinstalación correcta elimina siempre todas las entradas del Registro» — demasiado categórico: elimina lo gestionado por el instalador; pueden quedar datos de usuario, configuraciones o componentes compartidos.
  • «MSI y MSIX son el mismo formato» — falso: tecnologías distintas (Windows Installer vs. empaquetado moderno).
  • «Todas las ediciones de Windows 10 quedaron fuera de soporte a la vez» — falso: las ediciones LTSC tienen ciclos de vida específicos.
  • Confundir la versión concreta de Windows 11 con un concepto estructural: las versiones cambian; los conceptos (ediciones, TPM, UAC, WinRE...) no.

12. Posibles preguntas cortas (con esquema de respuesta)

1. Explique las principales diferencias entre Windows Home y Pro

  • Home: orientada al uso general; sin unión tradicional a dominio AD ni host RDP.
  • Pro: unión a dominio, BitLocker, Client Hyper-V, host de Escritorio remoto.
  • Cierre: Enterprise/Education añaden seguridad y administración; LTSC es canal con ciclo de vida propio.

2. Explique TPM 2.0 y Secure Boot

  • TPM: módulo de seguridad para operaciones criptográficas y almacenamiento protegido de claves; usos (BitLocker, Hello).
  • Secure Boot: verificación de integridad/firma de la cadena de arranque desde UEFI.
  • Cierre: protegen cosas distintas (claves vs. arranque) y ambos figuran en los requisitos de Windows 11.

3. Diferencie el Registro de Windows y el Visor de eventos

  • Registro: base de datos jerárquica de configuración; hives principales; edición con regedit y precaución.
  • Visor de eventos: registros de sucesos del sistema, seguridad y aplicaciones.
  • Cierre: configuración vs. sucesos; ambos útiles en diagnóstico.

4. Explique Sysprep y DISM en el despliegue de equipos

  • Flujo: equipo de referencia → Sysprep (generaliza) → captura de imagen WIM → despliegue.
  • DISM: monta, modifica y mantiene imágenes o la instalación (inyectar controladores, actualizaciones).
  • Cierre: son complementarias, no intercambiables; PXE/WDS como vía de despliegue en red.

5. Diferencie KMS y MAK

  • KMS: activación contra un servicio de administración de claves de la organización.
  • MAK: clave de activación múltiple con un número determinado de activaciones.
  • Cierre: escenarios típicos de cada uno.

6. Explique los mecanismos básicos de recuperación de Windows

  • Puntos de restauración, Historial de archivos, imagen del sistema.
  • WinRE y medio USB de recuperación; modo seguro y sus usos.
  • Cierre: Reiniciar este PC como opción de reinstalación.

7. Diferencie Restaurar sistema y Reiniciar este PC

  • Restaurar sistema: revierte configuración/Registro a un punto anterior; no es copia de seguridad de datos.
  • Reiniciar este PC: reinstala Windows conservando o eliminando archivos personales.
  • Cierre: cuándo elegir cada uno (cambio reciente fallido vs. sistema gravemente dañado).

8. Explique la gestión del software base: MSI y winget

  • Formatos: .exe, MSI (Windows Installer), MSIX.
  • MSI: instalación silenciosa, mantenimiento, distribución, desinstalación (msiexec /x).
  • winget: gestor de paquetes por línea de comandos (buscar, instalar, actualizar, desinstalar).
  • Cierre: alcance real de la desinstalación (pueden quedar datos, configuraciones o componentes compartidos).

13. Supuestos prácticos CAU

Supuesto 1 — El equipo no arranca tras instalar un controlador

Escenario: tras actualizar el controlador de la tarjeta gráfica, un equipo municipal queda en pantalla negra y no completa el arranque.

  • a) ¿Por dónde empezar? Acceder a WinRE (o al medio USB de recuperación si no arranca solo) y probar el modo seguro, que carga un conjunto reducido de controladores y servicios.
  • b) ¿Qué hacer desde ahí? Desinstalar o revertir el controlador problemático; alternativamente, aplicar un punto de restauración anterior al cambio.
  • c) ¿Restaurar sistema recuperaría los documentos del usuario si faltaran? No: revierte configuración y Registro, no es copia de seguridad de datos personales.

Supuesto 2 — Equipos aún con Windows 10

Escenario: un servicio municipal conserva equipos con Windows 10 22H2 en ediciones generales.

  • a) ¿Qué implica su situación de soporte? Las ediciones generales de Windows 10 22H2 finalizaron soporte el 14/10/2025: sin parches de seguridad ordinarios, el riesgo aumenta. (Las ediciones LTSC tienen ciclos de vida específicos, así que hay que comprobar cada caso.)
  • b) ¿Qué opciones se valoran? Comprobar la compatibilidad con Windows 11 (requisitos de plataforma: TPM 2.0, Secure Boot, procesador soportado) y planificar la migración; donde no sea viable de inmediato, valorar el programa ESU, que permite prolongar las actualizaciones de seguridad en determinados escenarios.
  • c) ¿Cómo se migraría? In-place upgrade si el equipo es compatible y se quiere conservar el entorno; instalación limpia (o despliegue por imagen) en renovaciones.

Supuesto 3 — Treinta equipos con la misma imagen

Escenario: hay que desplegar 30 puestos idénticos para una nueva oficina de atención.

  • a) ¿Qué flujo se sigue? Preparar un equipo de referencia con sistema, aplicaciones y configuración → Sysprep para generalizar → capturar la imagen WIM → desplegarla.
  • b) ¿Cómo llega la imagen a los equipos? Por red mediante arranque PXE apoyado en WDS, o desde medio físico.
  • c) ¿Y si hay que añadir un controlador a la imagen? Con DISM, montando y sirviendo la imagen sin rehacerla desde cero.
  • d) ¿Cómo se activarán? Mediante activación por volumen: KMS si estarán en la red de la organización; MAK para equipos que no contacten habitualmente con ella.

Supuesto 4 — «Me pide permiso de administrador»

Escenario: una usuaria informa de que, al abrir una utilidad, aparece un aviso solicitando confirmación y credenciales.

  • a) ¿Qué mecanismo actúa? El UAC: la acción requiere privilegios elevados y el sistema solicita confirmación explícita.
  • b) ¿Cuál es su finalidad? Limitar el uso normal de privilegios administrativos y reducir el impacto de las acciones que los requieren.
  • c) ¿Debe desactivarse para «evitar molestias»? No: desactivarlo elimina una barrera de control; la vía correcta es gestionar los permisos y la aplicación, no suprimir el mecanismo.

Supuesto 5 — Atender un equipo sin desplazarse

Escenario: hay que revisar un puesto en una sede alejada; en otro caso, aplicar la misma comprobación a veinte equipos.

  • a) ¿Qué herramienta para el puesto concreto? RDP (Escritorio remoto), siempre que el equipo destino sea host válido: Pro o superior — Home no puede actuar como host.
  • b) ¿Y para los veinte equipos? PowerShell Remoting: comandos o scripts desatendidos sobre varios equipos.
  • c) ¿Y si hay que fijar una configuración común permanente? Mediante GPO en equipos de dominio (Tema 12) o gestión moderna de endpoints (Tema 30).

Supuesto 6 — Actualizaciones bajo control

Escenario: se quiere evitar que cada equipo descargue las actualizaciones por su cuenta y poder aprobarlas antes de distribuirlas.

  • a) ¿Qué solución clásica encaja? WSUS: descarga centralizada y distribución controlada a los equipos.
  • b) ¿Sigue siendo viable? Sí: está deprecated (sin nuevas funciones) pero soportado y funcional; «deprecated» no es «fuera de servicio».
  • c) ¿Hacia dónde apunta la gestión moderna? Hacia servicios cloud (Windows Update for Business, Autopatch, Intune), sin que ello implique que WSUS deje de funcionar.

Supuesto 7 — Desinstalar una aplicación en 40 equipos

Escenario: hay que retirar una aplicación distribuida como paquete MSI, sin que el usuario intervenga.

  • a) ¿Qué vía usar? msiexec /x sobre el paquete o su identificador, ejecutable de forma desatendida (por script o herramienta de distribución).
  • b) ¿Qué esperar del resultado? Se eliminan los componentes gestionados por el instalador; pueden permanecer datos de usuario, configuraciones o componentes compartidos.
  • c) ¿Alternativa moderna para software del catálogo? winget, que permite desinstalar (y actualizar) desde línea de comandos.

15. Resumen final: si mañana fuera el examen

  • Familia: Windows 10 (última versión de características 22H2) y Windows 11 (mismo núcleo NT, requisitos de seguridad de plataforma, evolución por versiones). Ediciones: Home (sin dominio ni host RDP) · Pro (dominio, BitLocker, Hyper-V cliente, host RDP) · Enterprise/Education · LTSC (canal con ciclo propio).
  • Seguridad de plataforma: TPM 2.0 protege claves · Secure Boot protege el arranque. Otras funciones: BitLocker, Defender, Windows Hello, UAC (elevación con confirmación); Hyper-V cliente y WSL como secundarias.
  • Servicios y recursos: services.msc (4 tipos de inicio) · Administrador de tareas · Registro = configuración (HKLM/HKCU/HKCR/HKU/HKCC) vs. Visor de eventos = sucesos · MMC y snap-ins · PowerShell.
  • Instalación: USB/DVD, red (PXE + WDS) o imágenes: Sysprep generaliza → WIM → DISM sirve la imagen. Limpia vs. in-place upgrade. Activación por volumen: KMS (servidor) vs. MAK (clave múltiple).
  • Administración: Windows Update (cliente) y WSUS (centralizado; deprecated pero soportado, con gestión moderna orientada a cloud). Remota: RDP (host desde Pro), PowerShell Remoting, GPO (T12), Intune (T30).
  • Mantenimiento: limpieza de disco · HDD → desfragmentación / SSD → TRIM · chkdsk (errores del sistema de archivos/disco) · Monitor de rendimiento y fiabilidad.
  • Recuperación: puntos de restauración · Historial de archivos · imagen del sistema · WinRE · USB de recuperación · modo seguro. Restaurar sistema (vuelve atrás) ≠ Reiniciar este PC (reinstala).
  • Software: .exe · MSI (silenciosa, distribuible, msiexec /x) · MSIX · winget (Chocolatey como ampliación). La desinstalación elimina lo gestionado por el instalador; pueden quedar datos, configuraciones o componentes compartidos.
