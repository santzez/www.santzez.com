1. Linux y distribuciones

📌 Imprescindible para el examen
Linux → el kernel (núcleo del sistema operativo).
Distribución → kernel + herramientas de sistema + gestor de paquetes + configuraciones y otros componentes. Lo que se instala en un servidor es siempre una distribución, no «Linux» a secas.
Familia Distribuciones Gestor Formato
Debian Debian, Ubuntu Server APT .deb
Red Hat RHEL, Rocky Linux, AlmaLinux DNF .rpm
SUSE SLES, openSUSE Zypper .rpm

Ubuntu pertenece a la familia Debian (deriva de ella y comparte APT y el formato .deb): no es una familia independiente. Sus versiones LTS (Long Term Support) tienen un ciclo de soporte prolongado, lo que las hace habituales en servidores; los años y fechas concretas son dato de actualidad, no materia nuclear.

🔍 Para ampliar — CentOS, Rocky y Alma
CentOS Linux tradicional llegó a su fin de vida; CentOS Stream cumple otra función dentro del ecosistema Red Hat (rama previa a RHEL, no equivalente en estabilidad a la antigua CentOS). Rocky Linux y AlmaLinux son alternativas compatibles con RHEL. Los datos de ciclo de vida figuran, fechados, en el apartado 16.

2. Instalación de un servidor Linux

Métodos

  • Instalación manual: desde una imagen ISO, respondiendo de forma interactiva al instalador — particionado, configuración de red, creación del usuario inicial.
  • Instalación automatizada/desatendida: las respuestas se aportan en un fichero de configuración, imprescindible para desplegar muchos servidores de forma idéntica. En la familia Red Hat, el mecanismo clásico es Kickstart; en Debian/Ubuntu se emplean herramientas de instalación automatizada como preseed o cloud-init, sin que todas las versiones actuales utilicen exactamente el mismo mecanismo.

Servidor sin entorno gráfico

Un servidor Linux suele instalarse sin entorno gráfico. Ventajas: menor consumo de recursos, menor superficie de ataque, menos componentes que mantener y actualizar, y administración por consola o SSH. Es una práctica habitual, no una imposibilidad técnica: un servidor Linux sí puede tener GUI si el caso lo justifica.

🧠 Para memorizar — paralelismo
La filosofía coincide con la de Windows Server Core (Tema 12): menos componentes, menos superficie de ataque, administración por línea de comandos o remota.

LVM (Logical Volume Manager)

  • Qué es: una capa de abstracción entre el almacenamiento físico y los volúmenes lógicos.
  • Ventajas: flexibilidad, agrupación de dispositivos y volúmenes, ampliación de volúmenes en determinados escenarios y una administración más flexible que el particionado clásico de tamaño fijo.
  • Matiz: no todas las operaciones son posibles sin condiciones — la reducción o el redimensionado en caliente dependen del sistema de archivos y del escenario.
🧠 Para memorizar
LVM → FLEXIBILIDAD. Y ojo: LVM no es un sistema de archivos, es la capa sobre la que se crean los volúmenes que luego se formatean.

Sistemas de archivos habituales

  • ext4: muy extendido, opción por defecto en muchas distribuciones.
  • XFS: habitual en entornos Red Hat; adecuado para determinados escenarios de grandes volúmenes y ficheros.
  • Btrfs: funciones avanzadas como snapshots y subvolúmenes.

3. Gestión de paquetes y del software

  • Repositorio: servidor con las versiones disponibles del software.
  • Paquete: unidad de software distribuible (.deb o .rpm).
  • Dependencia: otro paquete necesario para que el software funcione.
  • Gestor de paquetes: instala, actualiza y elimina software resolviendo automáticamente las dependencias desde los repositorios configurados. A bajo nivel existen dpkg (.deb) y rpm (.rpm), que instalan un paquete suelto sin resolver dependencias por sí mismos.
Acción APT (Debian/Ubuntu) DNF (Red Hat/Rocky/Alma)
Actualizar metadatos de repositorios apt update Equivalente funcional: actualizar la metadata de los repositorios
Consultar actualizaciones disponibles apt list --upgradable dnf check-update
Actualizar los paquetes instalados apt upgrade dnf upgrade
Instalar un paquete apt install dnf install
⚠️ No confundir — dos precisiones
1) apt update ≠ apt upgrade: el primero actualiza los metadatos/caché de los repositorios (no instala nada); el segundo instala las versiones más recientes de los paquetes ya presentes.
2) apt update ≠ dnf check-update: no son equivalentes exactos. apt update refresca los metadatos; dnf check-update comprueba qué actualizaciones están disponibles.

4. systemd y gestión de servicios

📌 Imprescindible para el examen
systemd → sistema de inicio y marco de gestión de servicios adoptado por la mayoría de distribuciones actuales.
PID 1 → es el primer proceso de espacio de usuario iniciado por el kernel.
systemd ≠ kernel: el kernel arranca a systemd, no al revés.

Unidades (units)

  • .service: un servicio o demonio — la unidad más habitual.
  • .socket: activación por socket.
  • .mount: puntos de montaje.
  • .timer: los timers de systemd proporcionan un mecanismo integrado de programación de tareas y pueden utilizarse en lugar de cron en muchos escenarios (no son, sin más, «el reemplazo de cron»).

systemctl

Comando Qué hace
systemctl start servicio Inicia el servicio ahora
systemctl stop servicio Lo detiene ahora
systemctl restart servicio Lo reinicia
systemctl status servicio Consulta su estado
systemctl enable servicio Configura su inicio automático con el sistema
systemctl disable servicio Desactiva el inicio automático
⚠️ No confundir — start ≠ enable
start arranca el servicio en ese momento. enable configura que arranque automáticamente con el sistema, pero no significa necesariamente que se inicie ahora. Y al revés: un servicio iniciado con start no quedará activo tras un reinicio si no está enabled.

journalctl

  • journalctl consulta el journal gestionado por systemd.
  • journalctl -u servicio muestra los eventos de un servicio concreto — herramienta de diagnóstico de primer orden.
  • Matiz: el journal no contiene automáticamente todos los logs generados por cualquier aplicación Linux; muchas aplicaciones escriben sus propios ficheros, tradicionalmente bajo /var/log.

5. Acceso remoto (SSH) y privilegios (root/sudo)

SSH

  • SSH (Secure Shell): protocolo seguro de administración remota, que cifra la comunicación entre cliente y servidor.
  • Puerto por defecto: 22/TCP.
  • Métodos de autenticación: por contraseña o mediante claves criptográficas — preferible la autenticación por claves en entornos de producción.
📌 Imprescindible para el examen — las claves SSH
Clave pública → se instala/autoriza en el servidor.
Clave privada → permanece en el cliente y debe protegerse (nunca se copia al servidor).
Invertir esto es una trampa clásica.

root y sudo

  • root: el superusuario, con privilegios totales sobre el sistema.
  • sudo: permite ejecutar comandos concretos con privilegios elevados desde una cuenta normal, de forma puntual y auditable.
  • Buena práctica: trabajar con un usuario normal + sudo, en lugar de iniciar sesión directamente como root.

6. Actualizaciones y ciclo de vida

  • Actualización manual: con el gestor de paquetes (apartado 3), planificada en una ventana de mantenimiento.
  • Actualización automática: unattended-upgrades en Debian/Ubuntu y dnf-automatic en la familia Red Hat. Lo que se instala automáticamente depende de la configuración: no debe darse por hecho que siempre instalan todos los parches críticos.
  • Ciclo de vida y soporte: cada distribución tiene su periodo de soporte y su fin de soporte; las versiones LTS ofrecen ciclos prolongados. Operar una versión sin soporte deja el servidor sin parches, por lo que la migración debe planificarse con antelación. Los plazos concretos son dato de actualidad (apartado 16).
🔍 Para ampliar — live patching
Actualizar el kernel normalmente exige reiniciar. Existen mecanismos de live patching (por ejemplo, kpatch u otros según la distribución) que permiten aplicar determinados parches al núcleo sin reiniciar, retrasando el reinicio a una ventana de mantenimiento. Contenido de ampliación.

7. Monitorización

Herramienta Función
top / htop Procesos + consumo de CPU/memoria, en vista interactiva y actualizada
ps Instantánea de los procesos en ejecución
free Memoria RAM + swap (usada y libre)
df Espacio de los sistemas de archivos (ocupado y libre)
du Espacio ocupado por archivos y directorios
uptime Tiempo activo + load average
ss Conexiones y puertos de red
journalctl Consulta del journal de systemd
/var/log Registros tradicionales en ficheros
⚠️ No confundir comandos — trampa principal del tema
df → espacio del sistema de archivos · du → espacio utilizado por directorios/archivos.
ps → instantánea de procesos · top/htop → visión interactiva y actualizada.
ss → conexiones y puertos · free → memoria · journalctl → journal de systemd.

Mini-procedimiento: un servicio no arranca

  • 1. systemctl status servicio — estado, últimos mensajes y si está enabled.
  • 2. journalctl -u servicio — eventos del servicio con más detalle.
  • 3. Comprobar configuración y dependencias (fichero de configuración, unidades de las que depende).
  • 4. Revisar recursos y permisos cuando proceda (espacio, memoria, propietario de ficheros, puertos en uso).

Mini-procedimiento: sistema de archivos lleno

  • 1. df — identificar qué sistema de archivos está lleno.
  • 2. du — localizar qué directorios o archivos ocupan el espacio dentro de ese sistema de archivos.
🔍 Para ampliar — monitorización centralizada
Para muchos servidores, estas herramientas puntuales se complementan con soluciones que recogen métricas de forma continua y alertan: Nagios, Zabbix o la combinación Prometheus + Grafana. Su configuración queda fuera del alcance del tema.

Equivalencias Linux / Windows (recurso didáctico)

Linux Windows Función (equivalente funcional aproximado)
systemctl services.msc Gestión de servicios
journalctl Visor de eventos Consulta de eventos
top / htop Administrador de tareas Procesos y recursos

Se trata de equivalentes funcionales aproximados: cumplen papeles análogos, no son técnicamente idénticos.

  • Linux = kernel · Distribución = kernel + herramientas + gestor + configuración.

  • start = ahora · enable = arranque automático.
  • SSH → 22; clave pública en el servidor, privada en el cliente.
  • root → TODO · sudo → ELEVACIÓN PUNTUAL.
  • LVM → FLEXIBILIDAD (capa entre almacenamiento físico y volúmenes lógicos; no es un sistema de archivos).
  • df → SISTEMA DE ARCHIVOS · du → DIRECTORIOS/ARCHIVOS · free → MEMORIA · ss → RED · ps → instantánea · top/htop → interactivo.
  • Instalación desatendida: Kickstart (Red Hat) · preseed/cloud-init (Debian/Ubuntu).
  • Actualización automática: unattended-upgrades (Debian/Ubuntu) · dnf-automatic (Red Hat) — según configuración.
  • Sistemas de archivos: ext4 (extendido) · XFS (Red Hat, grandes volúmenes) · Btrfs (snapshots, subvolúmenes).

10. Posibles trampas de examen

  • «Linux es un sistema operativo completo» — impreciso en este contexto: Linux es el kernel; lo completo es la distribución.
  • «Ubuntu es una familia independiente de Debian» — falso: pertenece a la familia Debian (APT, .deb).
  • «apt update instala las actualizaciones» — falso: actualiza metadatos; instalar es apt upgrade.
  • «apt update equivale a dnf check-update» — falso: refrescar metadatos ≠ comprobar actualizaciones disponibles.
  • «systemd es el núcleo de Linux» — falso: es el primer proceso de espacio de usuario (PID 1) que arranca el kernel.
  • «systemctl enable arranca el servicio inmediatamente» — falso: configura el arranque automático; iniciar ahora es start.
  • «journalctl muestra todos los logs de cualquier aplicación» — falso: muchas aplicaciones escriben en /var/log.
  • «df y du muestran lo mismo» — falso: sistema de archivos vs. directorios/archivos.
  • «ps y top son intercambiables» — impreciso: instantánea vs. vista interactiva actualizada.
  • «root y sudo son lo mismo» — falso: superusuario vs. mecanismo de elevación puntual.
  • «La clave privada SSH se copia al servidor» — falso: la que se autoriza en el servidor es la pública.
  • «LVM es un sistema de archivos» — falso: es una capa de gestión de volúmenes.
  • «Un servidor Linux nunca puede tener interfaz gráfica» — falso: es una práctica habitual instalarlo sin GUI, no una imposibilidad.
  • «La actualización automática instala siempre todos los parches críticos» — matiz: depende de la configuración de la herramienta.

12. Posibles preguntas cortas (con esquema de respuesta)

1. Explique qué es una distribución Linux

  • Linux = kernel; distribución = kernel + herramientas + gestor de paquetes + configuración.
  • Las tres familias con su gestor y formato; Ubuntu dentro de Debian.
  • Cierre: LTS y su relevancia en servidores.

2. Diferencie APT y DNF

  • APT (Debian/Ubuntu, .deb) y DNF (Red Hat y derivados, .rpm); ambos resuelven dependencias desde repositorios.
  • Acciones equivalentes (instalar, actualizar) y las dos precisiones: update ≠ upgrade; apt update ≠ dnf check-update.
  • Cierre: dpkg y rpm como herramientas de bajo nivel.

3. Explique systemd, systemctl y journalctl

  • systemd: sistema de inicio y gestión de servicios; PID 1; no es el kernel.
  • Unidades (.service, .socket, .mount, .timer).
  • systemctl: start/stop/restart/status y enable/disable (start ≠ enable).
  • journalctl: consulta del journal; -u servicio; matiz sobre /var/log.

4. Explique el acceso remoto mediante SSH

  • Protocolo seguro de administración remota; cifrado; puerto 22/TCP.
  • Autenticación por contraseña o por claves (preferible).
  • Reparto de claves: pública en el servidor, privada en el cliente y protegida.

5. Diferencie root y sudo

  • root: superusuario con privilegios totales.
  • sudo: ejecución puntual de comandos con privilegios elevados desde una cuenta normal.
  • Cierre: buena práctica (usuario normal + sudo) y su ventaja en trazabilidad.

6. Explique LVM

  • Definición: capa de abstracción entre almacenamiento físico y volúmenes lógicos.
  • Ventajas: flexibilidad, agrupación de dispositivos, ampliación en determinados escenarios.
  • Matices: no todas las operaciones son posibles sin condiciones; LVM no es un sistema de archivos.

7. Explique las principales herramientas de monitorización

  • Procesos y recursos: top/htop, ps, free, uptime.
  • Almacenamiento: df y du. Red: ss.
  • Registros: journalctl y /var/log; mención de la monitorización centralizada como ampliación.

8. Diferencie df y du

  • df: espacio ocupado y libre por sistema de archivos.
  • du: espacio ocupado por directorios y archivos concretos.
  • Cierre: el procedimiento habitual — df para localizar el FS lleno, du para encontrar qué lo llena.

13. Supuestos prácticos

Supuesto 1 — Un servicio no arranca

Escenario: tras un reinicio programado, un servicio de una aplicación municipal alojada en un servidor Linux no está disponible.

  • a) ¿Primer comando? systemctl status servicio: estado actual, últimos mensajes y si está configurado como enabled.
  • b) ¿Y si el estado no basta? journalctl -u servicio para ver los eventos con detalle.
  • c) ¿Qué más revisar? Configuración y dependencias del servicio; recursos y permisos (espacio en disco, memoria, puertos ocupados).
  • d) Si arrancó a mano pero vuelve a faltar tras reiniciar, ¿qué ocurre? Que se hizo start sin enable: no está configurado para arrancar con el sistema.

Supuesto 2 — Sistema de archivos lleno

Escenario: un servidor empieza a fallar y se sospecha falta de espacio.

  • a) ¿Cómo confirmarlo? Con df: identifica qué sistema de archivos está al límite.
  • b) ¿Cómo localizar la causa? Con du dentro de ese sistema de archivos: qué directorios o archivos ocupan el espacio.
  • c) Sospechosos habituales. Registros acumulados (por ejemplo, bajo /var/log), copias temporales o volcados; la política de rotación y limpieza es parte del mantenimiento.

Supuesto 3 — Administrar el servidor desde el CAU

Escenario: hay que revisar la configuración de un servidor situado en el CPD sin desplazarse.

  • a) ¿Qué herramienta? SSH, protocolo seguro de administración remota (puerto 22/TCP por defecto).
  • b) ¿Qué autenticación conviene? Mediante claves: la pública autorizada en el servidor y la privada protegida en el equipo cliente.
  • c) ¿Con qué cuenta trabajar? Con un usuario normal, elevando con sudo las acciones que lo requieran.

Supuesto 4 — Instalar y actualizar software

Escenario: hay que instalar un paquete nuevo y dejar el servidor actualizado en un servidor Ubuntu y en otro Rocky Linux.

  • a) ¿Qué gestor en cada uno? APT (.deb) en Ubuntu — familia Debian; DNF (.rpm) en Rocky — familia Red Hat.
  • b) ¿Qué pasos en APT? Actualizar metadatos (apt update), consultar lo actualizable (apt list --upgradable), actualizar (apt upgrade) e instalar (apt install).
  • c) ¿De dónde sale el software y qué resuelve el gestor? De los repositorios configurados; el gestor resuelve automáticamente las dependencias.

Supuesto 5 — Ampliar el almacenamiento con flexibilidad

Escenario: un volumen de datos se queda corto y se prevé que siga creciendo.

  • a) ¿Qué tecnología conviene haber previsto? LVM: capa entre el almacenamiento físico y los volúmenes lógicos, que permite agrupar dispositivos y ampliar volúmenes en determinados escenarios.
  • b) ¿Qué ventaja frente al particionado clásico? Flexibilidad: no queda todo fijado por el tamaño de partición inicial.
  • c) ¿Es una operación siempre trivial? No: las posibilidades de redimensionado dependen del sistema de archivos y del escenario; conviene planificar y respaldar.

Supuesto 6 — «El servidor va lento»

Escenario: los usuarios de una aplicación notan lentitud; hay que identificar qué está consumiendo el servidor.

  • a) ¿Qué herramientas usar? top/htop para ver en vivo qué procesos consumen CPU y memoria; ps para una instantánea concreta; free para el estado de memoria y swap; uptime para el load average.
  • b) ¿Y si se sospecha de la red? ss para conexiones y puertos en escucha.
  • c) ¿Dónde buscar rastro de errores? En journalctl y en los registros de /var/log.

Supuesto 7 — Mantener el servidor al día

Escenario: se plantea cómo gestionar las actualizaciones de varios servidores Linux.

  • a) ¿Opciones? Actualización manual planificada en ventana de mantenimiento, o automática con unattended-upgrades (Debian/Ubuntu) o dnf-automatic (Red Hat).
  • b) ¿Puede darse por hecho que lo instalarán todo? No: depende de la configuración de la herramienta.
  • c) ¿Qué más hay que vigilar? El ciclo de vida de la distribución: una versión sin soporte deja de recibir parches y obliga a planificar la migración.

15. Resumen final: si mañana fuera el examen

  • Linux = kernel · distribución = kernel + herramientas + gestor + configuración. Familias: Debian (APT/.deb — incluye Ubuntu) · Red Hat (DNF/.rpm) · SUSE (Zypper/.rpm). LTS = soporte prolongado.
  • Instalación: ISO manual o desatendida (Kickstart en Red Hat; preseed/cloud-init en Debian/Ubuntu). Servidor habitualmente sin GUI (menos recursos y superficie de ataque), en la línea de Windows Server Core — no es una imposibilidad.
  • LVM → flexibilidad: capa entre almacenamiento físico y volúmenes lógicos; permite agrupar y ampliar en determinados escenarios; no es un sistema de archivos. FS habituales: ext4, XFS, Btrfs.
  • Paquetes: repositorio, paquete, dependencia y gestor. apt update (metadatos) ≠ apt upgrade (instala); apt update ≠ dnf check-update (no son equivalentes exactos).
  • systemd: sistema de inicio y gestión de servicios, PID 1, no es el kernel. Unidades .service/.socket/.mount/.timer. systemctl: start (ahora) ≠ enable (arranque automático). journalctl consulta el journal (-u servicio); no recoge todos los logs de todas las aplicaciones (/var/log).
  • SSH: administración remota cifrada, puerto 22/TCP, mejor claves — pública en el servidor, privada en el cliente. root (todo) vs. sudo (elevación puntual); buena práctica: usuario normal + sudo.
  • Actualizaciones: manual o automática (unattended-upgrades / dnf-automatic, según configuración); vigilar el ciclo de vida y planificar migraciones; live patching como ampliación.
  • Monitorización: top/htop (procesos en vivo) · ps (instantánea) · free (memoria) · df (sistemas de archivos) · du (directorios) · uptime (load) · ss (red) · journalctl y /var/log (registros). Procedimientos: servicio caído → status + journalctl; disco lleno → df + du.

16. Actualidad Linux Server — datos fechados

📌 Información sujeta a cambio · Fecha de actualización de estos apuntes: agosto de 2026
Estos datos evolucionan; el núcleo del tema no depende de ellos.
  • Situación de CentOS: CentOS Linux tradicional está descontinuado (su última rama estable, CentOS Linux 7, alcanzó el fin de vida en 2024). CentOS Stream continúa como rama previa a RHEL dentro del ecosistema Red Hat. Las alternativas gratuitas compatibles con RHEL de referencia son Rocky Linux y AlmaLinux.
  • Ciclos de vida: las distribuciones publican periodos de soporte que cambian con cada versión; las LTS de Ubuntu ofrecen soporte estándar de varios años, ampliable con mantenimiento de seguridad extendido. Conviene consultar el ciclo vigente de la versión concreta antes de planificar una migración.
  • Herramientas de instalación automatizada: Kickstart sigue siendo el mecanismo de referencia en la familia Red Hat; en Debian/Ubuntu conviven preseed y cloud-init según la versión y el instalador utilizado.
  • Live patching: existen mecanismos para aplicar parches al kernel sin reiniciar (por ejemplo, kpatch en la familia Red Hat y soluciones equivalentes en otras distribuciones), con condiciones y coberturas que dependen del proveedor y la suscripción.
